## 设计主旨

MCAI 不是“QQ 机器人接几个运维命令”，而是一套**面向 Minecraft 服务端运维深度特化的 Agent Harness（智能体运行底座）**。QQ 群是人机交互入口，B 端主机、独立托管窗口、存档工具和只读探针是执行环境；核心价值在于用一套稳定、克制、讲证据的调度底座，让大模型在真实生产服上长时间、安全地完成排查与维护。

后续演进、提示词调整和功能评审统一遵循以下 5 条主旨：

1. **垂直场景特化的运行底座，不绑架原有服务端**：顺着 Windows 服主原本的 `start.bat`、人工控制台和自动重启习惯接入，不强推重型面板或外置数据库／向量库。每个服务端跑在独立托管窗口里，控制程序退出或重连不带崩游戏服；A 端单向 HTTPS 直连 B 端，A 端无需公网入口。
2. **长程上下文与缓存优先**：把跨轮次、长耗时排障当常态设计。保持系统提示与高频核心工具前缀稳定，不半路随意改写前缀或原地裁剪历史，尽量吃满长上下文缓存；大体积工具输出保留首尾概览、原文外置按需回读，接近窗口上限才整组压缩交接；底层做实推理链保留、流式容错、断线续接与持续自动重试。
3. **提示词立通用原则，把应变权还给 Agent**：系统提示和运行规则只守泛用底线（拿实测证据说话、没查到不等于不存在、坦诚交代未验证边界），不把单个实战踩坑写成僵硬的 `if-else` 攻略补丁堆进提示词，避免上下文膨胀和模型机械套路化，保留面对未知故障的自主推理能力。
4. **人机双层信息视图**：把“给人看的信息”和“给机器审核与留痕的信息”彻底分开。发到群里的回答、提问和待批卡片只讲通俗简明的人话，不堆原始代码、NBT 内部路径、翻页轮询和专业术语；原始工具证据、脚本正文、字段变动和过程日志完整留在本地并直接交由独立审核模型把关，管理员只需看清范围与风险后拍一次板。
5. **放手只读查证，严控生产落盘与真实验收**：只读排查尽量顺手且无副作用（探针不主动加载区块、不扰动世界）；一切生产写入、启停、安装与维护命令必过“运行规则 + 独立审核 AI + 管理员批准”，改文件先停服备份，高风险改动先上隔离试服。验收只认真实反馈（真日志、主线程响应、落盘数据），不信表面命令回显；操作编号先落盘防重复重放，失败保留现场不默认回滚或盲目重跑，验收后沉淀为可读可改的本地 Markdown 经验文档。

### 已确定的系统约束

- **运行平台与入口**：A、B 均为 Windows，AstrBot 最低 v4.29.4、不设版本上限；保留原生 runner，不修改上游源码。中间层、终端、诊断与修复脚本统一使用 PowerShell 7.3+（`pwsh`），不回退 Windows PowerShell；统一使用 `mcai` 包名、命令和插件标识，不维护旧版本迁移和旧接口。
- **通信与托管**：A 主动 HTTPS 直连 B，不引入 SSH 隧道、Codex CLI 运行依赖、MCSManager 或桌面键盘自动化；以 `mcai tm` 独立托管各窗口（B 退出不结束服务端），实例固定目录与 `start.bat` 并保留 BAT 自动重启（详见[配置与终端设计](configuration.md)）。
- **任务绑定与试服**：一任务绑定一个正式实例或独立测试实例，由 AI 按自然语言选择，目录不明先追问。授权按绑定快照和 B 实时配置核对。正式实例的任务可创建隔离副本，每台 B 同时只允许一个任务试服窗口或运行中的任务试服；独立测试实例不能再建副本。见 [Agent 与审核](agent.md)。
- **权限、失败与幂等**：生产操作按现有规则、独立 AI 审核和一次管理员批准执行，未经要求不增加审批层级或权限隔离；通用脚本不是操作系统沙箱。文件修复先停服备份，失败保留现场继续排查，禁止默认重跑；先持久化操作编号再执行，断线恢复沿用原编号和原参数。
- **交流、知识与资源**：群内答复完整分段不截断；工具原文、推理摘要与审核内容留本地，审核申报不进入主模型后续上下文（见[Agent 与审核](agent.md)）。搜索、下载暂存与验收后 Markdown 经验归档均不另建外置搜索或向量库服务（见[存档与联网](integrations.md)、[经验文档](storage-and-recovery.md#经验文档)）。控制台每窗口有界内存不持续落盘，辅助操作共享内存额度且 MC 进程不计入（见[终端与资源设计](terminal-and-resources.md)）。
- **服内诊断 Probe**：只做服内诊断，不主动加载区块，只在服务端线程读取世界对象；测试负载只进隔离测试服，禁止打入发行 JAR（见[服内诊断设计](probe.md)）。

## 目标与系统结构

QQ 群是MC服务端运维与排障入口：管理员可提出日常运维、明确操作需求，也可直接描述或引用问题创建任务；玩家用带任务名的指令补充线索。AI识别服务端、按目标核实必要信息并查询或提案，管理员批准后修改，验收后形成可复用经验。普通闲聊不进入上下文，完整执行信息写本地记录。

```text
QQ 群
  ↕ 群命令、关键交流、可选 执行进度汇报
A：AstrBot 插件
  原生 Agent runner／独立审核／任务状态／MOD联网／A任务工作区／经验文档
  │ 主动发起 HTTPS，令牌 + 证书指纹
  ▼
B：MC 控制程序
  操作记录／后台任务／文件接收／任务测试副本／存档工具
  ├─ 本机WebSocket → 独立托管窗口1 → ConPTY/PWSH/BAT → 服务端1
  ├─ 本机WebSocket → 独立托管窗口2 → ConPTY/PWSH/BAT → 服务端2
  ├─ 独立 Java 21+ → MCA Selector 辅助程序
  └─ 可选 MCAI Probe → 控制台与本地结果文件
```

A 无公网入口，只需出站访问 B；B 开放一个 TCP 端口。网络连接与后台进程生命周期分离，A 重载或连接中断后按原编号查询。B退出或重启后，用户独立启动的托管窗口继续运行并自动重连。

用户通过 `mcai tm` 创建独立交互终端，B只持有连接引用；`attach`提供额外查看。不依赖桌面自动化。

## 设计决策

以下是当前实现采用的方案和约束：

| 主题 | 当前采用 | 原因与约束 |
|---|---|---|
| AI 运行位置 | A 的 AstrBot 原生 runner | 复用现有模型配置；不要求 B 安装 Codex CLI 或 DeepSeek Harness |
| 远程控制 | 内置 HTTPS 直连 | A 主动访问 B 的实际地址与端口；跨公网时使用映射端口 |
| 服务端管理 | B 的常驻程序和多实例 ConPTY | 支持多个 BAT 与人工控制台；不引入 MCSManager |
| 生产操作保护 | 运行时规则＋独立 AI 审核＋一次管理员批准 | 保留通用脚本，不增加风险分级、额外人工审批或命令审查系统 |
| 修复失败 | 保留现场并继续检查 | 不自动回滚或重跑；新的修复方案重新审核和批准 |
| 服务端选择 | AI根据自然语言绑定单一目标 | 用户不必填写目录；规范目录用于身份与经验，配置名用于接口路由 |
| 搜索与网页 | API托管搜索＋独立alpha/search＋A正文读取 | 复用提供商，不另配本地搜索服务 |
| MOD联网与安装 | A访问Modrinth／CurseForge并保存任务下载，批准前传入B暂存校验 | B不访问MCAI外网；下载不自动安装或执行 |
| 经验存储 | A的Markdown索引＋每实例文档 | 便于人工维护；不使用向量数据库或独立知识库服务 |
| 群内输出 | 关键交流与可选执行进度汇报 | 不播报分页、轮询和工具进度；详细过程留本地 |

DeepSeek Harness 仅作为审核、重试和持久步骤组织的设计参考；MCP 也不是当前两端通信的必需层。当前实现将控制台、后台诊断、存档和下载作为 B 内部能力，通过同一操作接口供 Agent 调用。

## 当前能力边界

- 目标环境是 Windows 上的 Minecraft Java 服务端，适配原版、插件端、整合包和新旧存档的基础结构，不保证理解每个模组字段的含义。
- 可选MCAI Probe提供服内现场；已有MC命令、Java诊断工具、spark和磁盘查询继续提供补充证据。探针由管理员安装，支持范围见[使用文档](../usage/probe.md)。
- 活动区块的实时状态不能从磁盘存档直接推断；不自动强制保存，`save-all flush` 走修复批准。
- 单独 NBT 和 Java 区域存档受支持，基岩版 LevelDB 不在支持范围；动态、需登录网页也不提供完整浏览器能力。
- A工作区脚本以AstrBot账号权限运行，B脚本以主机账号权限运行；两者均不是操作系统沙箱。
- 试服是生产任务在 B 工作区内的子环境。每台 B 共用一组试玩地址与专用端口，只允许一个试服窗口打开或运行；[停服后关窗](integrations.md#a工作区与测试副本)可释放名额并保留副本。
- 当前经验索引按一台 B 设计。支持多个 MC 实例，不等同于一个任务跨多台主机、多实例联合修复。

当前实现与验证状态应分别查看[工具设计](agent.md)和[测试说明](../development/testing.md)。未做过的真实模型服务、QQ 或整合包联调，不能用模拟测试替代描述。
