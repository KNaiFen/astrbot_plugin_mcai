## 目标与系统结构

QQ 群是MC服务端运维与排障入口：管理员可提出日常运维、明确操作需求，也可直接描述或引用问题创建任务；玩家用带任务名的指令补充线索。AI识别服务端、按目标核实必要信息并查询或提案，管理员批准后修改，验收后形成可复用经验。普通闲聊不进入上下文，完整执行信息写本地记录。

```text
QQ 群
  ↕ 群命令、关键交流、可选 执行进度汇报
A：AstrBot 插件
  原生 Agent runner／独立审核／任务状态／网页读取／经验文档
  │ 主动发起 HTTPS，令牌 + 证书指纹
  ▼
B：MC 控制程序
  操作记录／后台任务／下载／存档工具
  ├─ 本机WebSocket → 独立托管窗口1 → ConPTY/PWSH/BAT → 服务端1
  ├─ 本机WebSocket → 独立托管窗口2 → ConPTY/PWSH/BAT → 服务端2
  ├─ 独立 Java 21+ → MCA Selector 辅助程序
  └─ 可选 MCAI Probe → 控制台与本地结果文件
```

A 无公网入口，只需出站访问 B；B 开放一个 TCP 端口。网络连接与后台进程生命周期分离，A 重载或连接中断后按原编号查询。B退出或重启后，用户独立启动的托管窗口继续运行并自动重连。

用户通过 `mcai tm` 创建独立交互终端，B只持有连接引用；`attach`提供额外查看。不依赖桌面自动化。

## 设计决策

这些决策对应本线程后续确认的方向，取代早期方案：

| 主题 | 当前采用 | 原因与约束 |
|---|---|---|
| AI 运行位置 | A 的 AstrBot 原生 runner | 复用现有模型配置；不要求 B 安装 Codex CLI 或 DeepSeek Harness |
| 远程控制 | 内置 HTTPS 直连 | A 主动访问 B 的公网 IP＋映射端口，不部署 SSH 隧道或重连脚本 |
| 服务端管理 | B 的常驻程序和多实例 ConPTY | 支持多个 BAT 与人工控制台；不引入 MCSManager |
| 生产操作保护 | 运行时规则＋独立 AI 审核＋一次管理员批准 | 保留通用脚本，不增加风险分级、额外人工审批或命令审查系统 |
| 修复失败 | 留现场，AI继续检查并重新提案 | 新方案重新审核、批准；无方向或模型故障才暂停，不自动回滚失败修复 |
| 服务端选择 | AI根据自然语言绑定单一目标 | 用户不必填写目录；规范目录用于身份与经验，配置名用于接口路由 |
| 搜索与网页 | API托管搜索＋独立alpha/search＋A正文读取 | 复用提供商，不另配本地搜索服务 |
| 下载与安装 | B暂存、校验，再批准安装 | 下载不自动改变生产实例，不自动执行下载文件 |
| 经验存储 | A的Markdown索引＋每实例文档 | 便于人工维护；不使用向量数据库或独立知识库服务 |
| 群内输出 | 关键交流与可选执行进度汇报 | 不播报分页、轮询和工具进度；详细过程留本地 |

DeepSeek Harness 仅作为审核、重试和持久步骤组织的设计参考；MCP 也不是当前两端通信的必需层。当前实现将控制台、后台诊断、存档和下载作为 B 内部能力，通过同一操作接口供 Agent 调用。

## 当前能力边界

- 目标环境是 Windows 上的 Minecraft Java 服务端，适配原版、插件端、整合包和新旧存档的基础结构，不保证理解每个模组字段的含义。
- 可选MCAI Probe提供服内现场；已有MC命令、Java诊断工具、spark和磁盘查询继续提供补充证据。探针由管理员安装，支持范围见[使用文档](../usage/probe.md)。
- 活动区块的实时状态不能从磁盘存档直接推断；不自动强制保存，`save-all flush` 走修复批准。
- 单独 NBT 和 Java 区域存档受支持，基岩版 LevelDB 不在支持范围；动态、需登录网页也不提供完整浏览器能力。
- 文件工具解析实例内路径，通用脚本仍以主机账号权限运行。规则与AI审核降低误操作概率，不提供操作系统目录隔离。
- 当前经验索引按一台 B 设计。支持多个 MC 实例，不等同于一个任务跨多台主机、多实例联合修复。

当前实现与验证状态应分别查看[工具设计](agent.md)和[测试说明](../development/testing.md)。未做过的真实模型服务、QQ 或整合包联调，不能用模拟测试替代描述。
