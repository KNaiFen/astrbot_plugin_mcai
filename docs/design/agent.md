# Agent、工具与审核

[设计索引](README.md) · [状态与恢复](storage-and-recovery.md)

## 工具分工

工具 schema 由 `mcai/tool_schemas.py` 定义，AstrBot 原生 runner 驱动调用。传输接口与模型工具分开：模型看到按对象组织的具名工具，B 复用操作编号与后台任务机制。

| 工具 | 主要输入与行为 |
|---|---|
| `mc_instances` | B的目录、名称、说明、运行与占用状态 |
| `mc_select_instance` | `instance`、`reason`；把任务绑定一个已配置服务端 |
| `mc_history` | `index/read/search`；按目录读索引、关键词片段和正文分页 |
| `mc_web` | `open/read/find`；URL或持久引用、偏移与查找词 |
| `mc_search` | `search/open/find`；提供商alpha/search、查询或来源引用、任务级搜索会话 |
| `mc_mods` | 站点及 `search/project/versions/file/download`；项目、版本、加载器和文件 |
| `mc_download` | URL、可选文件名及SHA-256；下载到B暂存目录 |
| `mc_status` | 实例状态、主机指标、进程树、实际Java与世界发现 |
| `mc_players`、`mc_metrics` | 探针玩家与近期现场、全服及维度耗时 |
| `mc_objects`、`mc_profile`、`mc_inspect` | 已加载对象普查、短时热点、按UUID／位置检查目标 |
| `mc_files` | `find/read`；glob或相对路径与行范围 |
| `mc_logs` | 文件/glob、字面量/正则、时间、编码和上下文 |
| `mc_console` | `read/command`；按序号读取或发送在线诊断命令 |
| `mc_exec` | PowerShell诊断脚本、实例内工作子目录与超时 |
| `mc_nbt` | 文件、NBT路径、摘要/值、子项分页；修改值使用带类型SNBT |
| `mc_region` | 区块读取或批量查询；世界、实体类型、UUID、坐标、NBT条件和统计 |
| `mc_job` | 后台查询、分页、长字段引用、取消与修复记录 |
| `mc_propose` | 简短方案、明确步骤及审核材料；等待管理员批准 |
| `mc_say` | 关键提问或结论 |
| `mc_pause` | 保存进度并暂停 |

不同动作有明确参数结构，不暴露自由填写的泛化 `arguments`。工具调用通过当前 `tool_call` 和 `open_step` 记录持久化，断线后按原编号恢复结果。

未绑定目标时允许实例列表、选择、历史、网页和交流；实例状态、诊断、存档及下载工具要求已绑定目标。

## 三种操作

| 类型 | 流程 |
|---|---|
| 在线诊断 | 查询自主执行；`mc_exec`和控制台发送先独立AI审核，不自动停服 |
| 在线修复 | `mc_propose`整组审核 → `/mcaiapply` → 原命令；可无恢复备份，群内确认说明 |
| 文件修复 | `mc_propose`整组审核 → `/mcaiapply` → 停服、备份、修改、验证；失败保留现场 |

修复步骤包括显式启停、`command`、`write_text`、NBT／区域修改、`script`、`restore`、`install_download`。脚本必须声明全部 `backup_paths`；下载安装明确目标文件及待移除旧文件。启动、重启、恢复和强制保存也属于待批准方案。

备份覆盖实际目标：已有文件记录原始内容，新增目标记录原先不存在；同一方案多次修改只备份初始状态。区域编辑关联外部 `.mcc` 文件也进入清单。脚本对清单外文件的效果依靠规则和审核约束，程序不能从任意脚本自动推断全部写入。

## 独立AI审核

| 入口 | 通过 | 拒绝或失败 |
|---|---|---|
| `mc_exec` | 提交原诊断脚本 | 不执行 |
| `mc_console command` | 发送原诊断命令 | 不发送 |
| `mc_propose` | 保存原步骤，向管理员请求一次批准 | 不形成可批准方案 |

查询、分页、取消、交流和暂停不审核。管理员批准不能绕过被拒绝的提案；后续新方案需重新审核。

每个受审调用声明 `review.purpose` 和 `review.script_files`，可指定外部脚本编码。A从B读取实际正文，审核输入包含原命令、内联脚本、外部脚本、工作与实例目录、步骤、备份范围；安装下载时还包含来源、文件哈希、版本与依赖。

实现检查常见字面量 BAT／PS1／Python 引用是否申报，不实现通用Shell解析器。材料缺失或超限不能静默截断后放行。审核决定绑定本次调用和参数，脚本内容哈希在B执行前复核；变化则重新审核和提案。待执行方案的参数或规则变化也不能沿用旧审核。

审核使用单独提供商配置和思考程度，在无执行工具的独立对话中返回严格 JSON 的 `allow` 或 `deny`。理由、响应和API提供的推理信息只写本地记录。主对话清除 `review` 申报和审核对话，通过后保留原工具结果，拒绝仅返回未执行及简短原因。

默认模板 `mcai/agent_rules.md` 安装成A数据目录的 `AGENTS.md`，与内置工具提示一同提供给排障模型和独立审核模型。预设说明QQ群任务、Windows A/B、独立托管、消息可见范围、证据判断、诊断与修复、原编号恢复、历史摘要及验收；核实删除、覆盖、递归、批量操作的目标与范围，留意空变量和过宽选择条件。每轮与续接重新读取，模板升级不覆盖用户编辑；已有安装按[运行时规则说明](../usage/configuration.md#运行时规则)人工合并。

## 群内交流与API摘要

输入按任务收集：`/mcainew 任务名 [补充说明]`读取第一条引用消息的文本，将可选补充标注为创建者补充，一起保存至report和初始pending，首次模型调用即可读取；后续只接收`/mcaisay 任务名 内容`。不拉取群历史，普通群聊不进入任务；图片与语音没有独立解析路径。插件没有反馈条数或速率上限，待处理反馈会合并输入并持久化；模型历史由token预算控制，详见[上下文与群消息范围](../usage/configuration.md#上下文与群消息范围)。

普通消息用于必要提问、关键结论、批准与验收，完整文本保留本地，群消息做长度控制。工具分页、后台轮询和审核过程不单独播报。

Responses 主模型显式请求 `reasoning.summary=auto`，流式读取原始 `response.reasoning_summary_text.delta/done`。段落完成才进入持久发件箱发送，保留原文，不用其他模型改写。不能把AstrBot合并后的通用 `reasoning_content` 当成摘要。

摘要按响应、条目与摘要索引去重，长段按平台长度拆分，不添加定时或每分钟限额；停止任务后丢弃未发送摘要。审核模型内容不转发，摘要通知也不作为新群反馈。摘要是当前排查方向，解决结论仍需工具证据及管理员验收。
