# Agent、工具与审核

[设计索引](README.md) · [状态与恢复](storage-and-recovery.md)

## 工具分工

工具 schema 由 `mcai/tool_schemas.py` 定义，AstrBot 原生 runner 驱动调用。传输接口与模型工具分开：模型看到按对象组织的具名工具，B 复用操作编号与后台任务机制。

| 工具 | 主要输入与行为 |
|---|---|
| `mc_instances` | B的目录、名称、说明、运行与占用状态 |
| `mc_select_instance` | `instance`、`reason`；把任务绑定一个已配置服务端 |
| `mc_history` | `index/read/search`；按目录读索引、关键词片段和正文分页 |
| `mc_web` | `open/read/find`；URL或持久引用、偏移与查找词 |
| `mc_search` | `search/open/find`；提供商alpha/search、查询或来源引用、任务级搜索会话 |
| `mc_mods` | A端访问Modrinth／CurseForge，查询 `search/project/versions/file/download`；项目、版本、加载器和文件 |
| `mc_inventory` | 本地MOD／插件／数据包元数据、嵌套JAR、哈希、依赖与历史清单差异 |
| `mc_download` | A端按URL、可选文件名及SHA-256下载到当前任务暂存 |
| `mc_workspace` | A端任务目录的文件读写、B端JAR拉取、下载暂存和经审核的PowerShell构建 |
| `mc_test_server` | 查询或打开当前任务的 B 端测试副本，或关闭已停服窗口释放全局名额；测试服操作沿用原任务和批准方案 |
| `mc_status` | 实例状态、主机指标、进程树、实际Java与世界发现 |
| `mc_query` | 参数数组形式的查询CLI；文件、日志、NBT／区域、方块、扫描、导出与进程／JVM诊断 |
| `mc_tools` | 按名称加载工具并读示例，按 `workflow` 读取专项 Playbook；加载集合随任务持久化 |
| `mc_verify` | 固定只读的配置解析、文本／NBT断言、就绪观察与本机端口检查 |
| `mc_players`、`mc_metrics` | 探针玩家与近期现场、全服及维度耗时 |
| `mc_objects`、`mc_profile`、`mc_inspect` | 已加载对象普查、短时热点、按UUID／位置检查目标 |
| `mc_chunks`、`mc_runtime` | 已加载区块与ticket、实际运行组件与生效状态 |
| `mc_console_read`、`mc_console_line`、`mc_console_send` | 分别读取新输出、续读长行、批量发送受审诊断命令 |
| `mc_exec` | PowerShell诊断脚本、实例内工作子目录与超时 |
| `mc_job_read`、`mc_job_wait`、`mc_job_cancel` | 后台输出分页、有界等待、取消 |
| `mc_artifact_read`、`mc_artifact_find` | 同一job_id内长字段字符续读与定位 |
| `mc_operation_read`、`mc_context_history` | 原操作与脚本日志；当前任务压缩前原文，不是已验收经验 |
| `mc_propose` | 首次方案与具体步骤；可声明continuation，批准后以plan_id续批 |
| `mc_plan_finish` | 本批已结算后结束多轮方案执行资格，记录结果待验收 |
| `mc_say` | 缺少用户信息时的必要提问；结论使用final |
| `mc_pause` | 保存进度并暂停 |

任务从首个请求就开放实例、状态、经验、交流、后台和历史续读，以及 `mc_query`、Probe 常用诊断、运行时与清单检查、在线诊断脚本和控制台的发送／读取／长行续读。独立验证、生产提案、多轮收尾、工作区、试服、联网搜索与下载通过 `mc_tools` 按需加入，任务中不自动卸载，暂停后可以继续使用。工具定义使用完整 schema；Chat 和 Responses 显式设置 `strict:false`，程序仍校验组合分支、必填项与额外字段。基础工具提前开放不改变审核入口。

九类查询的完整契约留在程序内校验，由共享CLI参数解析器转成原查询名称和参数；argv不经过shell解释。AI入口复用原HTTPS操作通道，安装CLI使用同一解析器；无需额外进程转发或系统PATH。原argv和解析结果一起持久化，恢复使用原参数及操作编号，审核证据使用程序保存的真实查询语义。帮助在本地返回，不创建远程操作。查询自身的分页建议转换为mc_query参数，后台与产物仍沿原工具续读。详见[查询命令](../usage/queries.md)。

模型入口参数与续读建议共用`tool_arguments.py`的命名表；转换只处理声明字段，NBT键、用户正文、B传输与已持久化操作参数保持各自含义。模型不提供旧参数别名。

执行、审核和压缩交接共用任务目标策略：明确本阶段目标、关键事实缺口及足以结束的证据；区分用户硬条件与辅助观测，按影响选择验证强度。同会话、同源版本及目标范围内复用已通过结果，冲突或变化时只补受影响部分；独立查询使用一轮工具或既有批量参数。参数错误返回原证据引用供局部纠错，不重新收集已有效材料。该策略不设某个TPS数值或某项工具complete的通用验收阈值。

创建入口已核验管理员身份，初始任务与say使用同一外层is_admin来源字段；任务要求仍须经具体方案审核批准。压缩请求提供程序任务来源及批次边界，只总结所选旧历史，不依据局部未出现否定全局任务或授权；最新用户原文保留在主对话。

摘要正文按可用窗口和选中材料提供字符目标。完整摘要第一次未减少上下文时，自动按更紧目标重整一次；仍不收敛明确保留现场。只有完整响应且实际缩减才替换活动历史，不对摘要正文截尾。

| 含义 | 模型参数标准 |
|---|---|
| 查询分支／修改步骤／验证类型 | `mode`／`action`／`kind` |
| 文本检索、文件匹配、上下文行数 | `query`＋可选`regex`、`glob`、`before_lines/after_lines` |
| 事件分页、列表或字符分页 | `cursor/limit`、`offset/limit`；事件limit为1—100 |
| 超时、采集时长、采样间隔 | `timeout_seconds`、`duration_seconds`、`interval_seconds` |
| 等待、统计、稳定观察窗口 | `wait_seconds`、`window_seconds`、`stable_seconds` |
| 世界目录、清单比较基线 | `world_path`、`baseline_job_id` |
| Probe对象类型、实体存档类型 | `object_type`、`entity_type` |
| 就绪命中、禁止出现的文本 | `query`、`forbid_query`，默认字面量；`regex=true`启用正则 |

单点方块读取与NBT／文件读取统一为`mode=read`；控制台命令始终提交`commands`数组。查询仍按对象分工，不新增通用动作工具。缺参和错参同时返回字段路径、当前分支必填字段及允许字段，供模型直接纠正。

生产排障提供商限定为AstrBot的`openai_chat_completion`与`openai_responses`。其他原生适配器在设置与运行入口明确拒绝，避免上游结构转换损坏引用、组合分支和类型；能力测试中的平面echo不能证明生产工具结构受支持。

模型结果统一为`{ok, data, evidence_id?, error?, next_call?}`。新工具结果的evidence_id可由三个受审入口通过evidence_ids引用，A从当前任务已结算记录读取原始工具名、参数、采集目标与结果；历史压缩不删除原记录。ok只表示本次调用处理成功；后台是否完成看data.status，输出读完看data.complete。后台原id在模型侧为job_id；原始返回仍用于内部跟踪并保存在result，实际模型格式保存在model_result，诊断导出包含两者。next_call为可直接采用的name/arguments，仅提供续读或原操作核对建议，不自动执行。

有界概览优先正文，省略部分保留路径和数量；result_path按键／下标读取时可直接穿过content／text中的JSON对象。字段不存在时返回缺失路径与该层可用键，帮助局部纠错。准备后的实际步骤可能包含程序插入的snapshot，模型不能把它作为mc_propose公开action提交。

单次工具结果同时受剩余窗口与字符数限制。常规探索最多 9000 字符；产物续读、历史续读、控制台定位／长行及网页等定向读取最多 14000 字符。小窗口仍按剩余可用额度的 65% 收紧。超出入口预算时，本地保存完整原件并返回证据引用和有界预览。后台输出进入模型前去掉 ANSI 控制序列；同一任务内再次轮询同一后台编号，静态字段相同时仅回传动态状态和续读数据。B 的 HTTP 返回及本地原始记录不变。

选择实例只附相关经验的标题、标签、编号和短摘要；按编号用 `mc_knowledge` 查看原步骤。Probe 性能及玩家历史首屏保留关键统计，长列表用小样本概览或续页。

B 端 NBT、区块和世界扫描分页按 JSON 的 UTF-8 字节计，单页上限为 120000 字节。节点的 SNBT 原文或转义后超过 12000 字节时，返回结构摘要和原路径，并按实际返回条数计算下一页偏移。日志归组仅在比较时替换时间、tick、耗时、UUID、坐标等动态值，首条样本保留原文；日志文件数、原始与解压读取量、物理行数、分组数及结果产物均有明确上限。达到上限时返回 `partial`、截断原因及已扫描统计。

控制台`events_complete`只说明事件页是否结束；`pending_reads`保留本页所有长行尾部及下一事件页的调用，存在待办时`complete=false`。需要完整页时逐项读完；当前决定证据已足够可保留未读状态，不把读取complete当成任务验收门槛。单条长行的complete只结束该行。CLI attach仍按原偏移完整显示输出。

错误code为invalid_arguments、review_denied、context_capacity、precondition_failed、operation_failed、remote_error、unknown_tool；另含message、可选path及execution_state。缺参path定位缺失字段，额外参数定位多余字段。context_capacity明确not_executed，details给出recoverable和largest_sources，执行模型自动定向补证、收窄引用或拆分等价步骤后再审核。参数、审核和前置条件明确拒绝为not_executed，B确认失败为failed，提交后无法核实为unknown。failed可能已有部分效果，unknown不能换编号重放。mc_say只确认queued，提案为awaiting_approval，暂停为paused；平台实际发送另由发件箱记录。任务恢复与正常调用共用同一模型结果构造，不重写历史调用或审核材料。

未绑定目标时允许实例列表、选择、历史、网页和交流；实例状态、诊断、存档及MOD下载工具要求已绑定目标。A工作区按任务目录隔离。

## 状态查询与只读问答

`/mcaiserver` 直接读取 B 的实例列表和只读操作。现有 `metrics` 操作提供摘要视图，只读 Probe 能力和 B 数据盘余量，不扫世界目录或枚举宿主进程。群回复仅对管理员显示磁盘及窗口会话。已运行且有 Probe 的实例通过现有后台查询并行读取玩家和近 10 秒性能；B 请求单次发送并受超时约束，操作状态可在时限内轮询。

`/mcaiask` 每次使用独立 `ask-…` 编号，由 AstrBot 原生 runner 执行。指令只接收问题文本，不再单独解析实例 ID；问答上下文只包含单次问题，模型须结合问题与实例说明选择并绑定唯一实例，不读写任务占用，选定后不切换；若问题中没有足够信息判断要绑定哪个服务端，直接回复不知道是哪个服务端并结束，不回答该问题。模型只拿到只读白名单，实际分派和 `mc_tools` 查询也只接受白名单。后台等待、读取及产物续读仅接受本次问答拿到的 job ID；`mc_query` 不启动 JFR 录制。问答版状态不返回磁盘和窗口会话，也不枚举宿主进程。

模型请求次数上限（`ask_max_steps`，默认 10 次）与总超时（`ask_timeout_seconds`，默认 180 秒）均可在插件设置中配置，最后一步只总结已有结果。结束时通过已有操作取消接口取消自己启动且未结算的 B 后台工作；取消受单独的 8 秒时限约束，B 失联时记录未能确认，最终答复也会提示。答复经持久化发件箱发送，原始模型调用及工具结果按问答编号留痕，可在诊断导出单选；用量计入每日总量和其中的非任务分类。

## 三种操作

组合分支校验先报告未知动作及schema中的允许值，再从匹配动作中定位必填或额外字段。备份由B按有效步骤自动加入，`snapshot`不属于模型可提交的步骤；恢复提交`restore`与`backup`即可。

| 类型 | 流程 |
|---|---|
| 在线诊断 | 查询自主执行；`mc_exec`和控制台发送先独立AI审核，不自动停服 |
| 在线修复 | `mc_propose`整组审核 → `/mcaiapply 任务名 短码` → 原命令；可无恢复备份，群内确认说明 |
| 文件修复 | `mc_propose`整组审核 → `/mcaiapply 任务名 短码` → 停服、备份、修改、验证；失败保留现场 |

定时维护沿用 `mc_propose` 的生产操作路径。每份计划只含一个 `schedule` 步骤，不参加试服或多轮授权；批准正文列明 B 的本地时间、规范实例、目标路径、保留数或公告、通知选项。B 比对保存的审核快照，收到对应管理员批准后才登记；替换计划需要新的审核和短码批准。调度和中断恢复见[状态与恢复](storage-and-recovery.md#定时维护)。

修复步骤包括显式启停、`command`、`write_text`、NBT／区域修改、`script`、`restore`、`install_download`、`prepare_test`和`copy_test_world`。脚本必须声明全部 `backup_paths`；下载安装明确目标文件及待移除旧文件。启动、重启、恢复和强制保存也属于待批准方案。测试副本通过同一任务的`environment=test`选择，不改变生产目标绑定；下载的工作区制品须先在测试副本安装并收到后续SAY反馈，才能纳入原多轮批准方案的生产替换。

B在审核材料采集时将原步骤展开为实际执行顺序，包含必要停服、一次初始备份和恢复启动；审核、批准正文及执行使用同一份已保存步骤。原先运行且无显式启停时，成功后恢复运行；原先停止保持停止。显式启停优先，失败不恢复启动。公告等前置在线命令先执行，首次离线处理时才停服备份；在线命令声明备份会明确展示停服／备份／启动。无法成立的在线顺序在产生效果前拒绝。

批准正文从实际步骤生成关键动作、路径、启停、备份及验证，再附模型摘要，审核员同时核对该正文。首批提案返回 `awaiting_approval` 时附带含短码的 `approval_command`；只有管理员发送与当前提案匹配的短码才执行。批准一次后，原范围内的续批仍只做独立审核。只有实际启动的批次读取并绑定 `start.bat`；完整配置供核对，运行配置比较仅检查审核快照中适用的 Java 路径与停服命令。已提交操作仍按原编号结算。

`mc_tools` 的 `workflow` 可读 MOD 源码修复（`mod_repair`）、文本补丁和文件写入（`file_patch`）、NBT 和坏区块（`world_nbt_repair`）、MOD 安装（`mod_install`）及定时维护（`schedule`）。指引放在工具结果，已加载状态随任务保存；活动历史丢失指引时由程序补回。试玩邀请引用已结算的试服安装及当前就绪证据。管理员通过普通 `/mcaisay` 反馈，A 核对实际消息身份、邀请及制品，独立审核根据原话和后续反馈判断语义。正式发布前 B 复核安装件和暂存哈希，正常停掉试服，再按原批准备份、安装和启动验证。已结算发布才可验收归档，任务临时内容由程序收尾。

局部文本修改使用 `patch_text`：提供 `path`、原文件 `sha256`、`edits: [{old, new}]`，非UTF-8无BOM文本同时指定 `encoding`。先用 `mc_query files stat` 获取哈希，再用 `preview_patch` 查看差异；预览不写入。原文必须唯一匹配，执行时文件哈希变化则失败。保留原BOM、编码、未修改部分及换行形式；仍走文件修复的停服和备份。`write_text`继续用于明确提交整份新内容。

`mc_query files search`限定文本glob，支持字面量／正则和`lines/files/count`；编码错误逐文件明确报告。`tail`读取末尾，`stat`返回大小、修改时间、BOM和SHA-256。`mc_job_wait`默认等10秒、最多25秒，出现输出或任务结束立即返回；等待和检索不创建新诊断进程。

`mc_query logs search`默认`view=events`，按完整多行事件归组，只归一化事件头的出现时间，保留对象差异、代表栈、次数和起止位置。常见及罕见组进入有界结果，全部组和出现区间保存为既有job的`log-events.json`产物。`view=value`沿原精确行查询，前后文行数仅用于该模式；`mc_query files search`语义保持不变。

`mc_artifact_read`和带entry的`mc_context_history`默认`view=summary`，使用执行和审核共用的确定性有界结构投影，保留原文体积、校验和与JSON路径索引；缺省项不表示不存在。`result_path`是JSON键／下标数组，可收窄到必要字段；`view=value`或明确offset才按字符读原文，`mc_artifact_find`返回原文偏移。结构视图不用于重写NBT。执行侧只对活动上下文中相同来源、交叠正文完全一致的范围去重，以covered_by和segments保留原范围及证据引用；历史压缩后可再次读取原文。原始result与已经入史的model_result不改写。

`mc_operation_read`同样支持`result_path`，从原记录中只取状态、失败步骤、错误或某项结果，返回operation_id、result_path及原始value；大字段继续经既有结果外置处理。审核指出缺口后先取对应原值再提案，避免反复提交同一份缩略记录。单次方案完成后直接报告，多轮方案才调用`mc_plan_finish`。

审核从相同持久原始记录独立投影，不使用主模型自由摘要代替证据，去除相同结果及重叠文本，续批只保留一份上一批观测。实际步骤、脚本和授权约束仍完整送审。本地预算不足回主模型自动调整；API明确报上下文超限时逐次缩小证据视图，缩减无进展则返回context_capacity，避免相同载荷空转。原编号与已提交操作沿原恢复机制核实，不重放。容量预检以既有字符基础裕量加最近16次实测输入超额上界校准，避免把小请求的固定差额按高比例外推到大请求；分批尺寸仍保留最近16次比例裕量。校准随实际usage更新，不引入本地分词器。

`mc_query diagnostics`是固定只读查询：`process`记录实例托管树内目标的CPU／I/O增量、内存和线程数，`jvm`使用实际JVM同目录的`jcmd.exe`读取参数、堆概要并连续采集线程快照。默认3个样本、间隔1秒，最多5个、间隔最多10秒；采集进程受原辅助内存额度与取消机制约束，MC不在该Job内。Oracle javapath包装进程按父子关系识别，以叶子JVM作为目标；多个独立JVM不能自动选择。缺JDK工具或采集失败明确返回错误，原始输出保留。

排障任务另可录制 JFR。区块录制默认静默，只有明确指定 `notify_user=true` 且 A 在结束前观察到进入录制阶段，才按后台编号向任务群提醒一次。内存 JFR 与区块录制以 `recording_kind` 区分，不发复现提醒；两者共用实例互斥、JVM 身份核对和原编号结算。用法见[查询说明](../usage/queries.md#常见查询)。

`memory-jfr`、`class-histogram` 和 `hprof-summary` 均不进入只读问答白名单。内存 JFR 默认 25 秒；JDK 16+ 使用 ObjectAllocationSample，按 Java 线程丢弃时间最早的样本并单列权重（JDK-8307488），JDK 11–15 分列 TLAB 与 TLAB 外事件。老对象只输出样本，不查 GC Root。类直方图用 `jcmd GC.class_histogram -all`，可能暂停 JVM，包含未回收对象，仅显式调用。离线 HPROF 只读实例或当前任务内已有文件，不创建堆转储；完整类直方图流式写入产物。HPROF 能给精确的记录计数和序列化载荷大小，JVM 布局不在文件内，浅占用与保留字节明确标成估算。对象/引用数及辅助堆额度允许时，计算可达记录图的支配关系并返回代表路径；过预算只返回直方图和大数组。

卡死恢复使用方案第一步`force_stop`，必须提交`mc_status.java_processes`中的`pid/created`和窗口`session_id`（步骤字段为`process_created`）。同样整组审核、一次批准；执行前保存控制台和状态证据，窗口重新核对身份，先结束BAT重启链及Java包装进程，再结束所选JVM及其子进程，保留托管PowerShell。可以接同一方案的文件备份／修复。普通`stop`超时不自动强制结束；同编号仍只查询持久控制结果，新会话不重放。

方案可插入`verify`步骤，`checks`支持`file`（json/toml/yaml/nbt解析）、`text`（文本存在／不存在）、`nbt/region`（带类型旧值断言）、`ready`和`tcp`。`patch_text`的可选`format`在替换前解析候选内容，失败不替换原文件。验证检查及已通过结果持久化到原操作；失败保留已发生修改、备份和当前服务端，不自动回滚或重新执行。查询工具`mc_verify`执行相同检查，不写生产文件。

失败回包的`failed_check`给出零基index、原始check、error和passed_indices；修复操作另带零基step，`mc_operation_read`直接读取此结构及已通过的verification。文本正则按整份文件匹配，逐行锚点须显式使用`(?m)`，例如`(?m)^motd=目标值\r?$`；不自动更改正则语义。验收MC会重写的配置应核对实际键值或运行效果。

就绪检查必须在同方案有效步骤的`start/restart`之后执行，或提供先前读取的控制台`cursor/session_id`；启动前保存游标，旧的Done／READY不能作为新证据。`query/forbid_query`默认按单行字面量匹配，只有`regex=true`才解释为正则；全部正则在方案展开时预编译，任何步骤产生效果前拒绝错误表达式。可设`stable_seconds`观察后续错误；就绪超时最多300秒，观察最多60秒。会话变化、Java退出／更换或缓冲淘汰导致失败。`tcp`只证明127.0.0.1指定端口接受连接，不证明玩家登录或业务正常。推荐步骤顺序为修改→离线格式／数据断言→显式启动→就绪与错误观察。已发生修改但仅缺验证时，先查原操作，再用只读`mc_verify`补验。

备份覆盖实际目标：已有文件记录原始内容，新增目标记录原先不存在；同一方案多次修改只备份初始状态。区域编辑关联外部 `.mcc` 文件也进入清单。脚本对清单外文件的效果依靠规则和审核约束，程序不能从任意脚本自动推断全部写入。

修复备份在停正式服或试服前预检。辅助进程按实际复制语义统计文件，跟随链接和目录联接；回到当前目录链上的同一目录时报循环错误。B 主进程以备份所在卷的剩余空间减去同卷尚未完成的其他修复备份估算，核对是否足够容纳本批备份及 `max(1 GiB, 备份大小的 5%)` 余量。估算量在通过检查时登记，复制完成、操作失败或取消时释放。预检过后文件或实际剩余空间仍可能变化。

普通备份使用标准复制，只记录覆盖范围和原先是否存在，不默认建立逐文件指纹表。选中恢复时才采集该备份的必要校验，完整表保存在B现有本地review记录中；材料请求复用工具调用编号，恢复步骤仅以review_id引用该记录，表不进入送审步骤、批准快照或请求摘要。审核获得恢复范围、相关旧正文与差异，以及文件数和二进制目录结构，不提供无语义的指纹字符串。B复制全部恢复候选并核对范围、类型与内容后，再替换当前目标；失败保留现场。CLI直接恢复复用相同的展开与候选检查，文本修改／恢复仍按步骤选择正确版本。

网页入口使用已登录的 Dashboard 用户身份 `web:<username>`。任务看板从现有状态机读取待批方案并用 `Tasks.approve` 批准，同时核对原独立审核记录、提案参数摘要和当前短码。暂停、续接、中止、验收与归档重试复用原 Task 方法。

明确的 Dashboard 常规操作包含定时计划登记和 `start`、`stop`、`restart`。网页计划通过同一 `prepare_schedule` 和调度锁登记；QQ 提案仍必须审核并批准。常规控制只允许一个指定的启停步骤、正式实例和对应目录，经 `/operations/{id}` 持久化并走实例锁与托管窗口；活动任务及维护冲突拒绝提交。任意脚本、文件修改和 `force_stop` 保留原审核流程。

## 独立AI审核

| 入口 | 通过 | 拒绝或失败 |
|---|---|---|
| `mc_exec` | 提交原诊断脚本 | 不执行 |
| `mc_console_send` | 发送原诊断命令 | 不发送 |
| `mc_propose` | 首次保存方案待一次批准；续批核对原范围后排队执行 | 不形成可批准方案或不执行本批 |

查询、分页、取消、交流和暂停不审核。管理员批准不能绕过被拒绝的提案；后续新方案需重新审核。

首次提案可附`continuation: {scope, completion}`，同首批steps一起审核。`plan_id`使用该次持久工具调用ID，管理员批准后保存方案原文、目标、规则及审核身份的快照。续批通过`mc_propose`引用`plan_id`，只提交本批summary、steps及材料，不能同时提供continuation。审核上下文由程序提供已批准快照、evidence_ids引用的带来源原始记录和上一批执行记录；审核员判断操作语义及范围，程序核对版本、规则、目标和本批参数一致性。每批可在范围内改变命令或工具，审核通过返回queued及操作编号，不再请求人工批准；B仍只接收有限步骤。

`mc_plan_finish`在当前批次和后台结果已结算后结束执行资格，持久记录结果并交回模型报告待验收。普通final不会结束活动多轮方案；达到单轮步数上限自动保存并继续。必要提问用mc_say进入等待，补充后沿原方案继续；硬暂停保存方案直到管理员续接。原来的未声明continuation的提案维持单批行为。

审核上下文由A从任务原文、带来源的补充、实际参数和evidence_ids引用的本任务已结算记录组装，模型无需填写`review`或逐次用途申报。证据保留工具名、原参数、采集目标与原始结果，不能用模型摘要替代，历史压缩后仍可引用。仅引用外部脚本时填写顶层`script_files`（始终按实例根目录解析，不随`cwd`变化）和可选`script_encoding`，A从B读取实际正文。审核输入包含原命令、内联／外部脚本、工作与实例目录、步骤及备份范围；安装下载时还包含来源、文件哈希、版本与依赖。申报字段从后续主模型历史移除，正文和审核回复只留本地。

PowerShell引用由原生AST区分执行与数据参数，BAT／Python识别明确字面量启动，不实现通用Shell解释器。顶层外部脚本需申报；明确二级依赖自动读取、去重，动态引用和未读取依赖明确标记给审核判断。按有效步骤选择实际会执行的脚本版本，不解析不会执行的旧坏版本。仅修改而不执行的脚本不进入执行校验；已有外部依赖在产生效果前核对，并在真正执行该版本的步骤前复核，普通步骤不反复检查所有脚本。已明确写入／恢复的版本不限制初始文件状态，执行时直接核对该步骤应使用的正文。同次材料采集复用正文摘要，普通覆盖文件只提供正文与差异；材料缺失或超限明确报错。

`Get-ChildItem -Filter '*.ps1'`、读取脚本正文、输出带脚本后缀的字符串及搜索过滤参数属于数据使用，不再按扩展名误判为执行。解析进程在一次材料采集中复用，物理内容按路径缓存，语法按版本缓存；完整原命令仍提交审核。内联脚本的PSScriptRoot不假定为实例目录，无法确定的实际路径明确标记。

审核使用单独提供商配置和思考程度，在无执行工具的独立对话中返回严格 JSON 的 `allow` 或 `deny`。理由、响应和API提供的推理信息只写本地记录。主对话清除脚本申报字段和审核对话，通过后保留原工具结果，拒绝仅返回未执行及简短原因。

审核配置快照中的运行参数用于留证；执行时只比较其中适用的 Java 路径和停服命令。停服超时、重启提示、BAT 编码和 PowerShell 路径不参与这项比较。实例目录身份独立验证，运行中的窗口继续使用自己的配置快照。

审核输入按所配窗口的 85% 扣除预留输出判断，未配窗口时以 272000 tokens 计算。审核系统提示固定，试玩发布说明随请求材料发送。审核及反馈整理分别发送任务范围内的缓存键，Chat 或 Responses 明确以 400／422 拒绝该字段时去掉它重试。

反馈超过审核预算时，由独立审核提供商分批整理，主模型摘要不作为审核来源。装得下的最新反馈保留原文；单条反馈过大时按原顺序切分，每段保留身份、原反馈编号和位置。逐字引文仍和原始反馈校验并附上来源。各批次保存 `review_context`，按任务／模型／规则／源反馈缓存，每次整理请求限时 300 秒；整理期间收到新反馈仍使原审核失效。

B 端审核材料按 5 MiB JSON 上限组装，为 8 MiB IPC 帧预留空间。优先省略大型非脚本文件全文，保留前后预览、校验哈希、字节数和精确 `diff`；只有单条差异本身足以挤爆帧时才标明并缩成前后预览。A 端在反馈整理后若仍超限，对送审副本省略大文件全文，再收紧预览和证据正文，保留证据编号、参数和校验值。脚本及其执行依赖、有效步骤、批准文字和计划结构保持完整；这些核心内容仍装不下时明确报容量错误，现场和执行材料不变。

审核只判断当前调用的实际目标、范围和效果，不要求一次调用完成整个任务，不额外发明数量上限、在线备份或重复批准。诊断命令使用`commands`数组，整批审核、按序发送；每条发送前保存稳定子编号及批次进度，发送失败保留已发送部分并停止余项。同一操作重连只查询原编号，不重放整批。返回会话、起始游标、逐条发送状态及已有新输出，实际效果由后续输出核实。参数校验错误包含字段路径，模型可依具体原因修正，沿用原步骤预算。

运行时规则分为三份：`mcai/agent_rules.md` 安装成A数据目录的 `AGENTS.md`，供执行模型读取；`mcai/review_rules.md` 安装成 `REVIEW_AGENTS.md`，供独立审核模型读取；`mcai/summary_rules.md` 安装成 `SUMMARY_AGENTS.md`，供历史压缩和验收整理模型读取。三份文件各自描述角色边界、输入重点和输出要求，不把执行模型的沟通规则注入审核模型。每轮与续接重新读取，模板升级不覆盖用户编辑；已有安装按[运行时规则说明](../usage/configuration.md#运行时规则)分别人工合并。

执行模型按运维或排障目标核实必要信息，只追问影响目标和操作范围的关键缺口、吸收后续补充并保持任务持续推进。明确操作按目标、当前状态、范围和预期结果执行；验收总结按实际目标、操作和结果归档。面向用户的消息先说明动作或结论，再给必要依据和下一步；报告聚焦行为结果与待验收事项，工具字段、证据编号、脚本正文、代码和内部日志保留在本地记录。审核模型由 `REVIEW_AGENTS.md` 约束，专注当前调用的目标、范围、实际步骤、证据、备份和验证，返回入口要求的JSON；整理模型由 `SUMMARY_AGENTS.md` 约束，专注历史事实和已验收经验。自然语言任务目标不代替管理员用 `/mcaiapply 任务名 短码` 批准具体方案。规则采用适合MC运维与排障的通用工作方法，不引入Codex身份、专属工具、沙箱权限、Git工作流、技能或子代理。

## 群内交流与执行进度汇报

任务消息、进度与命令回复统一使用`「任务名」：`前缀。

say 入口按 AstrBot 管理员或配置的 `admin_ids` 计算 `is_admin`，作为必填关键字参数传入 `Tasks.feedback`。反馈记录和pending均保存插件判定的身份；普通成员正文前加不完全可信提示，管理员前加身份提示，正文自称身份不能改变外层字段。任务来源和宿主机范围由程序提供给各角色；执行模型读取 `AGENTS.md`，审核模型读取 `REVIEW_AGENTS.md`，历史与验收整理模型读取 `SUMMARY_AGENTS.md`，三者各自保留角色规则。普通成员的停服、删改MOD／数据及改变目标要求须管理员提出或确认；管理员指令也不能越出当前MC任务实施宿主机重启、格式化、无关文件删除等破坏性操作。模型规则与独立AI审核负责这些语义判断，通用脚本的系统权限保持原样。

管理员用 `/mcaisaymode 任务名 false` 暂停普通成员反馈，`true` 开启；管理员say始终可接收。接收检查先于pending、反馈、参与者、方案失效和模型唤醒等变更，被拒消息直接返回原因。切换只保存任务开关并记录操作者，不改变模型、任务和已提交操作状态；先前已接收内容保留。

输入按任务收集：`/mcainew 任务名 问题描述`可直接创建；有引用时读取第一条引用文本，将可选补充标注为创建者补充，一起保存至report和初始pending，首次模型调用即可读取。后续只接收`/mcaisay 任务名 内容`。不拉取群历史，普通群聊不进入任务；语音不解析。插件没有反馈条数或速率上限，待处理反馈会合并输入并持久化；模型历史由token预算控制，详见[上下文与群消息范围](../usage/configuration.md#上下文与群消息范围)。

主模型的系统提示保留初始任务描述、规则和能力开关。实例、待批及已批准方案和已加载工作流使用程序生成的 `runtime_state`，仅在状态变化或历史压缩移除快照时追加。已有历史的任务收到新补充时，真实反馈留在 `user`，紧随其后的 `supplement_context` 提醒模型按管理员追问边界作答或按需核实普通成员线索。两类程序事件在 Responses 使用 `developer`，Chat 仅在发送时投影为 `user`。独立审核仍从持久化反馈和原始证据取材。

创建和补充收集本条消息和 `Reply.chain` 中的 `File`、`Image`。补充权限先检查命令发送者，引用附件的反馈身份则由 `Reply.sender_id` 按 AstrBot 管理员和插件 `admin_ids` 判定。文件下载使用组件解析的平台地址，读取时限制字节总数；图片用框架组件落地后立即核对大小。每个附件独立存入任务工作区 `attachments/` 下的目录；压缩包验证路径并限制实际解出大小和数量，失败只移除该附件。反馈标明附件不可信、不构成授权；未绑定实例时也可加载 `mc_workspace` 读取附件。

图片识别以排障模型发起一次独立、无工具的 Chat／Responses 请求，trace 和用量按任务记录；主 runner 只收到识别文字及来源，原图不加入后续输入。设置页的明确不支持结果与提供商身份匹配时跳过识别；没有结果或未观察到时尝试请求一次。拒绝图片输入或识别失败都保留现场原图，并提示用文字补充。

普通消息用于必要提问、关键结论、批准与验收。mc_say仅用于必要提问，结论和验收请求使用final；提问工具结算并保存完整工具组后结束本轮，不再请求模型生成同义追问。同一响应已有的其他final仍正常处理，完全相同文本去重；检查点恢复不会重发已入箱的追问，新反馈后正常续接。面向群的命令提示在入箱前统一规范 `“/mcai...”` 两边空格，若 `final` 文本提及 `/mcaidone` 而未给出 `/mcaisay` 时由程序补充 `/mcaisay` 续查提示；普通消息入箱前移除含`/mcai…`命令提示行前的空白行，其他正文、方案说明、暂停原因及来源链接完整保留。发件箱以单条完整正文为单位；QQ OneBot v11 超过 `group_forward_threshold`（默认400字符）时由消息层用一张合并转发卡片承载各段，段长最多1800字符并优先按换行分段，卡片之后再单独发送原有的 @。发送进度和重试状态均落盘，重载接着发送未确认的部分。同一发送目标按入箱顺序处理，确认是单条故障的消息独立重试，规则见[状态、持久化与恢复](storage-and-recovery.md#两类重启)。工具分页、后台轮询和审核过程不单独播报。

`forward_progress`默认关闭，仅控制commentary是否发群。运行时AGENTS.md保留两个交流通道、中途进度说明和最终答复规则：工具调用前先说明，工作中分享假设、发现、决策和方向变化，重点说明已知、未知与下一步；消息采用直接、简洁、正向表达，连续约束合并为可执行条件。中途消息保持进度性质，final独立完整。本插件不会在最终答复出现后折叠此前进度，模板保留无需回看进度的要求。程序只转发主模型 Responses 中`type: message`且`phase: commentary`的`output_text`，不转发`reasoning.summary`、通用`reasoning_content`或审核内容，也不主动请求推理摘要。

流式在`response.output_item.done`时收集完整进度消息，非流式从响应输出读取；同一响应与消息条目去重，清除Markdown和空行后复用持久化发件箱及相同发送格式，停止任务后丢弃未发送进度。进度通知不作为新群反馈，最终结果不重复包含commentary。保留原生runner；任务私有适配器在历史中保存原始助手消息及phase，后续请求与工具检查点恢复按原消息边界回放。纯commentary响应继续下一步，不把进度误判成任务结束；分页、轮询和工具流水不另行播报。结论仍需工具证据及管理员验收。

插件私有客户端在实际Chat/Responses SDK调用边界保存请求、返回和流式片段，按任务写入`traces/`；其他提供商记录其规范化调用边界。审核、压缩、验收和能力测试同样留痕，不修改共享客户端。插件命令在权限和参数判断前记录，处理结果与回复沿事件编号关联；任务发件箱记录实际发送成功或失败。设置页可按时间和任务导出本地记录、三份运行时规则和状态快照，不依赖B在线。记录失败会明确写入AstrBot错误日志，不因此重发已完成的API请求。
