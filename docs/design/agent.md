# Agent、工具与审核

[设计索引](README.md) · [状态与恢复](storage-and-recovery.md)

## 工具分工

工具 schema 由 `mcai/tool_schemas.py` 定义，AstrBot 原生 runner 驱动调用。传输接口与模型工具分开：模型看到按对象组织的具名工具，B 复用操作编号与后台任务机制。

| 工具 | 主要输入与行为 |
|---|---|
| `mc_instances` | B的目录、名称、说明、运行与占用状态 |
| `mc_select_instance` | `instance`、`reason`；把任务绑定一个已配置服务端 |
| `mc_history` | `index/read/search`；按目录读索引、关键词片段和正文分页 |
| `mc_web` | `open/read/find`；URL或持久引用、偏移与查找词 |
| `mc_search` | `search/open/find`；提供商alpha/search、查询或来源引用、任务级搜索会话 |
| `mc_mods` | 站点及 `search/project/versions/file/download`；项目、版本、加载器和文件 |
| `mc_inventory` | 本地MOD／插件／数据包元数据、嵌套JAR、哈希、依赖与历史清单差异 |
| `mc_download` | URL、可选文件名及SHA-256；下载到B暂存目录 |
| `mc_status` | 实例状态、主机指标、进程树、实际Java与世界发现 |
| `mc_diagnostics` | 实例内进程CPU／I/O增量与JVM参数、堆概要、连续线程快照 |
| `mc_verify` | 固定只读的配置解析、文本／NBT断言、就绪观察与本机端口检查 |
| `mc_players`、`mc_metrics` | 探针玩家与近期现场、全服及维度耗时 |
| `mc_objects`、`mc_profile`、`mc_inspect` | 已加载对象普查、短时热点、按UUID／位置检查目标 |
| `mc_files` | `find/read/tail/stat/search/preview_patch`；文件属性、SHA-256、检索与保留编码的补丁预览 |
| `mc_logs` | 文件/glob、字面量/正则、时间、编码和上下文 |
| `mc_console_read`、`mc_console_line`、`mc_console_send` | 分别读取新输出、续读长行、批量发送受审诊断命令 |
| `mc_exec` | PowerShell诊断脚本、实例内工作子目录与超时 |
| `mc_nbt` | 文件、NBT路径、摘要/值、子项分页；修改值使用带类型SNBT |
| `mc_region_nbt`、`mc_region_blocks` | 前者read/select/preview_batch查询区块NBT；后者get/search读取或统计已保存方块 |
| `mc_region_check`、`mc_region_export`、`mc_region_scan` | 区域／点检查、原始区块导出、世界数据扫描 |
| `mc_job_read`、`mc_job_wait`、`mc_job_cancel` | 后台输出分页、有界等待、取消 |
| `mc_artifact_read`、`mc_artifact_find` | 同一job_id内长字段字符续读与定位 |
| `mc_operation_read`、`mc_context_history` | 原操作与脚本日志；当前任务压缩前原文，不是已验收经验 |
| `mc_propose` | 首次方案与具体步骤；可声明continuation，批准后以plan_id续批 |
| `mc_plan_finish` | 本批已结算后结束多轮方案执行资格，记录结果待验收 |
| `mc_say` | 缺少用户信息时的必要提问；结论使用final |
| `mc_pause` | 保存进度并暂停 |

共39个工具。模型注册和执行端使用同一份完整schema，保留oneOf、分支必填及额外参数限制；重复复杂结构使用工具内部$defs/$ref，分支共享类型声明，保留每个分支允许的键。Chat／Responses工具显式strict:false，避免默认严格化改变可选参数；程序仍执行完整校验。工具调用通过`tool_call/open_step`持久化，断线沿原编号恢复。

生产排障提供商限定为AstrBot的`openai_chat_completion`与`openai_responses`。其他原生适配器在设置与运行入口明确拒绝，避免上游结构转换损坏引用、组合分支和类型；能力测试中的平面echo不能证明生产工具结构受支持。

模型结果统一为`{ok, data, evidence_id?, error?, next_call?}`。新工具结果的evidence_id可由三个受审入口通过evidence_ids引用，A从当前任务已结算记录读取原始工具名、参数、采集目标与结果；历史压缩不删除原记录。ok只表示本次调用处理成功；后台是否完成看data.status，输出读完看data.complete。后台原id在模型侧为job_id；原始返回仍用于内部跟踪并保存在result，实际模型格式保存在model_result，诊断导出包含两者。next_call为可直接采用的name/arguments，仅提供续读或原操作核对建议，不自动执行。

控制台`events_complete`只说明事件页是否结束；`pending_reads`逐项保留本页所有长行尾部及下一事件页的调用，存在待办时`complete=false`，`next_call`优先长行。调用者须逐项保留并读完待办，单条长行返回`complete=true`只结束该行，不清空其他待办。CLI attach分别维护完成行游标、已显示半行偏移和会话，长行通过原偏移接口读完。

错误code固定为invalid_arguments、review_denied、precondition_failed、operation_failed、remote_error、unknown_tool；另含message、可选path及execution_state。缺参path定位缺失字段，额外参数定位多余字段。参数、审核和前置条件明确拒绝为not_executed，B确认失败为failed，提交后无法核实为unknown。failed可能已有部分效果，unknown不能换编号重放。mc_say只确认queued，提案为awaiting_approval，暂停为paused；平台实际发送另由发件箱记录。任务恢复与正常调用共用同一模型结果构造，不重写历史调用或审核材料。

未绑定目标时允许实例列表、选择、历史、网页和交流；实例状态、诊断、存档及下载工具要求已绑定目标。

## 三种操作

| 类型 | 流程 |
|---|---|
| 在线诊断 | 查询自主执行；`mc_exec`和控制台发送先独立AI审核，不自动停服 |
| 在线修复 | `mc_propose`整组审核 → `/mcaiapply` → 原命令；可无恢复备份，群内确认说明 |
| 文件修复 | `mc_propose`整组审核 → `/mcaiapply` → 停服、备份、修改、验证；失败保留现场 |

修复步骤包括显式启停、`command`、`write_text`、NBT／区域修改、`script`、`restore`、`install_download`。脚本必须声明全部 `backup_paths`；下载安装明确目标文件及待移除旧文件。启动、重启、恢复和强制保存也属于待批准方案。

B在审核材料采集时将原步骤展开为实际执行顺序，包含必要停服、一次初始备份和恢复启动；审核、批准正文及执行使用同一份已保存步骤。原先运行且无显式启停时，成功后恢复运行；原先停止保持停止。显式启停优先，失败不恢复启动。公告等前置在线命令先执行，首次离线处理时才停服备份；在线命令声明备份会明确展示停服／备份／启动。无法成立的在线顺序在产生效果前拒绝。

批准正文从实际步骤生成关键动作、路径、启停、备份及验证，再附模型摘要，审核员同时核对该正文。只有实际启动的批次读取并绑定start.bat；配置完整展示，仅Java选择和停服命令这类实际执行内容的变化使审核失效，超时和控制台编码等运行参数不另设审核门槛。协议为mcai-5，A、B和托管窗口须配套；已提交操作仍按原编号结算。

局部文本修改使用 `patch_text`：提供 `path`、原文件 `sha256`、`edits: [{old, new}]`，非UTF-8无BOM文本同时指定 `encoding`。先用 `mc_files stat` 获取哈希，再用 `preview_patch` 查看差异；预览不写入。原文必须唯一匹配，执行时文件哈希变化则失败。保留原BOM、编码、未修改部分及换行形式；仍走文件修复的停服和备份。`write_text`继续用于明确提交整份新内容。

`mc_files search`限定文本glob，支持字面量／正则和`lines/files/count`；编码错误逐文件明确报告。`tail`读取末尾，`stat`返回大小、修改时间、BOM和SHA-256。`mc_job_wait`默认等10秒、最多25秒，出现输出或任务结束立即返回；`mc_artifact_find`返回字符偏移，`mc_artifact_read`读取原文。优先使用返回的next_call；等待和检索不创建新诊断进程。

`mc_diagnostics`是固定只读查询：`process`记录实例托管树内目标的CPU／I/O增量、内存和线程数，`jvm`使用实际JVM同目录的`jcmd.exe`读取参数、堆概要并连续采集线程快照。默认3个样本、间隔1秒，最多5个、间隔最多10秒；采集进程受原辅助内存额度与取消机制约束，MC不在该Job内。Oracle javapath包装进程按父子关系识别，以叶子JVM作为目标；多个独立JVM不能自动选择。缺JDK工具或采集失败明确返回错误，原始输出保留。

卡死恢复使用方案第一步`force_stop`，必须提交`mc_status.java_processes`中的`pid/created`和窗口`session_id`（步骤字段为`process_created`）。同样整组审核、一次批准；执行前保存控制台和状态证据，窗口重新核对身份，先结束BAT重启链及Java包装进程，再结束所选JVM及其子进程，保留托管PowerShell。可以接同一方案的文件备份／修复。普通`stop`超时不自动强制结束；同编号仍只查询持久控制结果，新会话不重放。

方案可插入`verify`步骤，`checks`支持`file`（json/toml/yaml/nbt解析）、`text`（文本存在／不存在）、`nbt/region`（带类型旧值断言）、`ready`和`tcp`。`patch_text`的可选`format`在替换前解析候选内容，失败不替换原文件。验证检查及已通过结果持久化到原操作；失败保留已发生修改、备份和当前服务端，不自动回滚或重新执行。查询工具`mc_verify`执行相同检查，不写生产文件。

就绪检查必须在同方案有效步骤的`start/restart`之后执行，或提供先前读取的控制台`after/session_id`；启动前保存游标，旧的Done／READY不能作为新证据。`pattern/forbid`按单行正则匹配，可设`stable_seconds`观察后续错误；就绪超时最多300秒，观察最多60秒。会话变化、Java退出／更换或缓冲淘汰导致失败。`tcp`只证明127.0.0.1指定端口接受连接，不证明玩家登录或业务正常。推荐步骤顺序为修改→离线格式／数据断言→显式启动→就绪与错误观察。

备份覆盖实际目标：已有文件记录原始内容，新增目标记录原先不存在；同一方案多次修改只备份初始状态。区域编辑关联外部 `.mcc` 文件也进入清单。脚本对清单外文件的效果依靠规则和审核约束，程序不能从任意脚本自动推断全部写入。

普通备份使用标准复制，只记录覆盖范围和原先是否存在，不默认建立逐文件指纹表。选中恢复时才采集该备份的必要校验，完整表保存在B现有本地review记录中；材料请求复用工具调用编号，恢复步骤仅以review_id引用该记录，表不进入送审步骤、批准快照或请求摘要。审核获得恢复范围、相关旧正文与差异，以及文件数和二进制目录结构，不提供无语义的指纹字符串。B复制全部恢复候选并核对范围、类型与内容后，再替换当前目标；失败保留现场。CLI直接恢复复用相同的展开与候选检查，文本修改／恢复仍按步骤选择正确版本。

## 独立AI审核

| 入口 | 通过 | 拒绝或失败 |
|---|---|---|
| `mc_exec` | 提交原诊断脚本 | 不执行 |
| `mc_console_send` | 发送原诊断命令 | 不发送 |
| `mc_propose` | 首次保存方案待一次批准；续批核对原范围后排队执行 | 不形成可批准方案或不执行本批 |

查询、分页、取消、交流和暂停不审核。管理员批准不能绕过被拒绝的提案；后续新方案需重新审核。

首次提案可附`continuation: {scope, completion}`，同首批steps一起审核。`plan_id`使用该次持久工具调用ID，管理员批准后保存方案原文、目标、规则及审核身份的快照。续批通过`mc_propose`引用`plan_id`，只提交本批summary、steps及材料，不能同时提供continuation。审核上下文由程序提供已批准快照、evidence_ids引用的带来源原始记录和上一批执行记录；审核员判断操作语义及范围，程序核对版本、规则、目标和本批参数一致性。每批可在范围内改变命令或工具，审核通过返回queued及操作编号，不再请求人工批准；B仍只接收有限步骤。

`mc_plan_finish`在当前批次和后台结果已结算后结束执行资格，持久记录结果并交回模型报告待验收。普通final不会结束活动多轮方案；达到单轮步数上限自动保存并继续。必要提问用mc_say进入等待，补充后沿原方案继续；硬暂停保存方案直到管理员续接。原来的未声明continuation的提案维持单批行为。

审核上下文由A从任务原文、带来源的补充、实际参数和evidence_ids引用的本任务已结算记录组装，模型无需填写`review`或逐次用途申报。证据保留工具名、原参数、采集目标与原始结果，不能用模型摘要替代，历史压缩后仍可引用。仅引用外部脚本时填写顶层`script_files`和可选`script_encoding`，A从B读取实际正文。审核输入包含原命令、内联／外部脚本、工作与实例目录、步骤及备份范围；安装下载时还包含来源、文件哈希、版本与依赖。申报字段从后续主模型历史移除，正文和审核回复只留本地。

PowerShell引用由原生AST区分执行与数据参数，BAT／Python识别明确字面量启动，不实现通用Shell解释器。顶层外部脚本需申报；明确二级依赖自动读取、去重，动态引用和未读取依赖明确标记给审核判断。按有效步骤选择实际会执行的脚本版本，不解析不会执行的旧坏版本。仅修改而不执行的脚本不进入执行校验；已有外部依赖在产生效果前核对，并在真正执行该版本的步骤前复核，普通步骤不反复检查所有脚本。已明确写入／恢复的版本不限制初始文件状态，执行时直接核对该步骤应使用的正文。同次材料采集复用正文摘要，普通覆盖文件只提供正文与差异；材料缺失或超限明确报错。

`Get-ChildItem -Filter '*.ps1'`、读取脚本正文、输出带脚本后缀的字符串及搜索过滤参数属于数据使用，不再按扩展名误判为执行。解析进程在一次材料采集中复用，物理内容按路径缓存，语法按版本缓存；完整原命令仍提交审核。内联脚本的PSScriptRoot不假定为实例目录，无法确定的实际路径明确标记。

审核使用单独提供商配置和思考程度，在无执行工具的独立对话中返回严格 JSON 的 `allow` 或 `deny`。理由、响应和API提供的推理信息只写本地记录。主对话清除脚本申报字段和审核对话，通过后保留原工具结果，拒绝仅返回未执行及简短原因。

审核只判断当前调用的实际目标、范围和效果，不要求一次调用完成整个任务，不额外发明数量上限、在线备份或重复批准。诊断命令使用`commands`数组，整批审核、按序发送；每条发送前保存稳定子编号及批次进度，发送失败保留已发送部分并停止余项。同一操作重连只查询原编号，不重放整批。返回会话、起始游标、逐条发送状态及已有新输出，实际效果由后续输出核实。参数校验错误包含字段路径，模型可依具体原因修正，沿用原步骤预算。

默认模板 `mcai/agent_rules.md` 安装成A数据目录的 `AGENTS.md`，与内置工具提示一同提供给主模型（配置中的“排障模型”）和独立审核模型。预设说明QQ群远程运维与排障任务、Windows A/B、独立托管、消息可见范围、证据判断、操作与修复、原编号恢复、历史摘要及验收；核实删除、覆盖、递归、批量操作的目标与范围，留意空变量和过宽选择条件。每轮与续接重新读取，模板升级不覆盖用户编辑；已有安装按[运行时规则说明](../usage/configuration.md#运行时规则)人工合并。

工作推进一节仅适用于主模型：按运维或排障目标核实必要信息，只追问影响目标和操作范围的关键缺口、吸收后续补充并避免无进展循环。明确操作不要求先有故障，也不强行调查根因；验收总结按实际目标、操作和结果归档，无故障时不编造症状或原因。修改范围、错误说明、结果验证和群内表达继续服从生产约束。审核模型只评估单次调用并返回其入口要求的JSON；自然语言任务目标不代替具体方案的`/mcaiapply`批准。规则采用适合MC运维与排障的通用工作方法，不引入Codex身份、专属工具、沙箱权限、Git工作流、技能或子代理。

## 群内交流与执行进度汇报

任务消息、进度与命令回复统一使用`「任务名」：`前缀。

say 入口按 AstrBot 管理员或配置的 `admin_ids` 计算 `is_admin`，作为必填关键字参数传入 `Tasks.feedback`。反馈记录和pending均保存插件判定的身份；普通成员正文前加不完全可信提示，管理员前加身份提示，正文自称身份不能改变外层字段。主模型、独立审核、历史压缩和验收总结复用内置来源／任务边界规则，已有用户AGENTS.md仍保留不覆盖。普通成员的停服、删改MOD／数据及改变目标要求须管理员提出或确认；管理员指令也不能越出当前MC任务实施宿主机重启、格式化、无关文件删除等破坏性操作。模型规则与独立AI审核负责这些语义判断，通用脚本的系统权限保持原样。

管理员用 `/mcaisaymode 任务名 false` 暂停普通成员反馈，`true` 开启；管理员say始终可接收。接收检查先于pending、反馈、参与者、方案失效和模型唤醒等变更，被拒消息直接返回原因。切换只保存任务开关并记录操作者，不改变模型、任务和已提交操作状态；先前已接收内容保留。

输入按任务收集：`/mcainew 任务名 问题描述`可直接创建；有引用时读取第一条引用文本，将可选补充标注为创建者补充，一起保存至report和初始pending，首次模型调用即可读取。后续只接收`/mcaisay 任务名 内容`。不拉取群历史，普通群聊不进入任务；图片与语音没有独立解析路径。插件没有反馈条数或速率上限，待处理反馈会合并输入并持久化；模型历史由token预算控制，详见[上下文与群消息范围](../usage/configuration.md#上下文与群消息范围)。

普通消息用于必要提问、关键结论、批准与验收。mc_say仅用于必要提问，结论和验收请求使用final；同轮只对完全相同的mc_say文本与最终答复去重，不因调用过mc_say而丢弃其他最终答复。群消息完整分段，不再按280字符截断或只保留三个来源链接，方案说明与暂停原因也完整发送。普通消息发送前移除含`/mcai…`命令提示行前的空白行，提示与上一行仅隔一个换行，其他正文分段保留。普通消息与进度共用每段正文1800字符、优先换行的分段器，保留原文顺序和全部链接，第一段携带@，复用持久化发件箱逐段发送、失败重试与重载续发。工具分页、后台轮询和审核过程不单独播报。

`forward_progress`默认关闭，仅控制commentary是否发群。运行时AGENTS.md保留两个交流通道、中途进度说明和最终答复规则：工具调用前先说明，工作中分享假设、发现、决策和方向变化，重点说明已知、未知与下一步；不设固定时间、工具次数或句数。中途不提问、不发最终答复，final应独立完整。本插件不会在最终答复出现后折叠此前进度，模板保留无需回看进度的要求。程序只转发主模型 Responses 中`type: message`且`phase: commentary`的`output_text`，不转发`reasoning.summary`、通用`reasoning_content`或审核内容，也不主动请求推理摘要。

流式在`response.output_item.done`时收集完整进度消息，非流式从响应输出读取；同一响应与消息条目去重，清除Markdown和空行并按平台长度拆分，复用持久化发件箱，停止任务后丢弃未发送进度。进度通知不作为新群反馈，最终结果不重复包含commentary。保留原生runner；任务私有适配器在历史中保存原始助手消息及phase，后续请求与工具检查点恢复按原消息边界回放。纯commentary响应继续下一步，不把进度误判成任务结束；分页、轮询和工具流水不另行播报。结论仍需工具证据及管理员验收。

插件私有客户端在实际Chat/Responses SDK调用边界保存请求、返回和流式片段，按任务写入`traces/`；其他提供商记录其规范化调用边界。审核、压缩、验收和能力测试同样留痕，不修改共享客户端。插件命令在权限和参数判断前记录，处理结果与回复沿事件编号关联；任务发件箱记录实际发送成功或失败。设置页可按时间和任务导出本地记录及状态快照，不依赖B在线。记录失败会明确写入AstrBot错误日志，不因此重发已完成的API请求。
