# 运行维护

[使用索引](README.md) · [配置说明](configuration.md)

## 多窗口管理服务端

B先在独立窗口运行 `mcai host`（运行期间窗口标题会变为 `MCAI-HOST`）。每个服务端再打开一个独立托管窗口：

```powershell
mcai tm -C "D:/MC/CTI_0.4.6"
./start.bat
```

`terminal` 与 `tm` 等效；在服务端目录运行时可省略 `-C`。B首次启动记住本机配置绝对位置，之后不必向各窗口重复填写连接信息。未知目录先输入项目ID和说明，B在线登记；已有目录在B离线时照常运行并持续重连。

每个窗口独立持有PowerShell／ConPTY和BAT。关闭窗口会影响该实例，其他实例继续；B退出、升级或崩溃不关闭它们。没有托管窗口时，远程start要求人工打开，不自动创建窗口。

执行 `mcai tm -C '服务端目录'` 后，当前窗口标题设为 `MCAI - 配置ID`，清空原屏幕和滚动历史，前两行显示实例目录与启动说明，随后出现托管PowerShell提示符。托管PowerShell已保存的命令历史仍保留，可用上键调用。

`mcai attach cti` 可额外查看控制台并发送MC命令，`/detach` 仅结束这次查看。人工输入不走AI审核；生产操作请自行核对。

其他命令：

```powershell
.\.venv\Scripts\python.exe -m mcai status cti
.\.venv\Scripts\python.exe -m mcai stop cti
.\.venv\Scripts\python.exe -m mcai restart cti
.\.venv\Scripts\python.exe -m mcai reload
.\.venv\Scripts\python.exe -m mcai --config D:/mcai/host.json list
```

`--config` 等全局选项放在子命令前。可通过 Windows 任务计划程序启动控制程序，运行目录与配置路径应固定。

## 状态查询与只读问答

`/mcaiask`确定目标后会自动参考该服已验收经验；无直接关键词命中时可浏览最近案例或继续检索。问答只读取本次选定实例的经验，不能跨服查看索引或检索；历史内容同样经过隐私脱敏，引用前仍须核对当前版本与现场。

允许群中的成员都可用 `/mcaiserver` 列出实例 ID、说明和状态；用 `/mcaiserver cti` 查单服（将 `cti` 换成实际 ID）。窗口在线与 MC 运行是两回事。Probe 可用且 MC 运行时显示在线玩家、近 10 秒的 TPS 和平均 MSPT；未安装时仍可查运行状态。管理员还能看到 B 数据盘剩余空间和窗口会话。B 连不上时会回复原因，查询不会一直等待。

`/mcaiask cti服现在有哪些玩家在线，TPS 下降了吗？` 会使用排障模型作一次只读问答，不需要单独填写实例 ID。模型会根据问题和实例说明自动绑定服务端；若问题中没有足够信息判断要绑定哪个服务端，会回复不知道是哪个服务端，不回答该问题。问答默认仅管理员可用；[可开放给成员](configuration.md#aastrbot-插件)，默认同一人两次提问间隔 300 秒，且前一次问答结束前不能重复提问。为保护现实隐私，全部只读问答都会拦截敏感凭据/IP 封禁文件，并对返回与答复中的 IP 地址、密码、Token 及宿主机用户目录脱敏，游戏内坐标和实体等排障信息照常回答。

两条命令都能查询已有任务占用的实例。`/mcaiask` 受理提问后会先给原消息贴上 QQ 表情回应 `[不是吧]`（编号 `476`；其他支持回应的平台贴对应确认表情，不支持时静默跳过）提示已收到并正在查询，默认最多 10 个模型步骤、总限时 180 秒（均可在设置中调整），最终只发一条回复，长文沿用群消息合集或分段。它不接收 `/mcaisay` 续问；需要修改时，管理员可以引用答复后发送 `/mcainew 任务名`，把答复带入新任务。问答的调用记录可在设置页的「诊断导出」中按问答选取。

## 直接启停正式服

在允许群中，管理员先用 `/mcaiserver` 查询实例 ID，再发送 `/mcaiswitch 实例ID 动作`。`start` 启动，`stop` 正常停止，`restart` 正常重启；不需要建任务或调用模型。AstrBot 插件设置页的「运行概览」也提供这些操作。实例有活动群任务或正在维护时，两处都会拒绝提交。

正常停止无法结束服务端时，可以使用 `forcestop` 强制停止，或用 `forcerestart` 强制停止后再启动。强制结束可能丢失未保存的数据。群内先发送例如 `/mcaiswitch cti forcerestart`，核对返回的 Java 或 `start.bat` 启动链 PID，再由同一管理员于同一群在 120 秒内发送 `/mcaiswitch cti forcerestart confirm`。进程身份或窗口会话变化后要重新获取确认单。网页端使用「强制停止」或「强制重启」，点击弹窗确认。

网页或群命令提交的正常停止、重启卡住时，确认强制操作后会先取消原停服等待，再核对实时进程状态。如果此时已经停稳，强制停止直接结束，强制重启只执行启动。原操作在时限内未释放时，按原编号稍后重试；尚未确认 B 受理的操作和其他待核对的启停仍会阻止提交。「运行概览」打开时会自动核对启停进度，也可手动点击「核对操作状态」。

群命令受理后立即回复操作编号，B 完成后由发件箱把结果发回原群；插件重载后也会继续核对。若未能及时确认结果，到「运行概览」按原编号核对，或用 `/mcaiserver 实例ID` 查看当前状态。要确认一次启停是否成功，请以原操作编号为准。

## 任务、批准与停止

新任务可直接发送 `/mcainew 任务名 问题描述`，也可引用玩家问题并附可选补充。任务名后的文本与引用问题一起保存并进入首次排查；没有引用时问题描述不能为空，任务名不带空格。任务未识别目标时，AI可联网、看历史、提问；实例工具需先绑定目标。多个未识别任务可以并存，绑定时才占用实例。已绑定任务暂停后仍保留占用。

| 场景 | 行为 |
|---|---|
| 管理员 `/mcaisaymode 任务名 false`／`true` | 暂停／开启该任务普通成员补充；管理员始终可补充，重载后保留，不改变任务状态 |
| 模型生成中补充 `/mcaisay` | 保存反馈，取消尚未完成的生成，带新消息继续当前任务；未执行方案失效 |
| 历史压缩期间补充 `/mcaisay` | 保存反馈，等待压缩完成，与摘要和保留原文一起进入下一次主请求，发送前检查预算 |
| AI提问后等待反馈 | `/mcaisay`直接启动下一轮，不需要`/mcairesume` |
| 修复执行中补充 | 先保留反馈，执行结果返回后再处理 |
| 暂停时补充 | 只保存，并明确回复仍暂停；管理员 `/mcairesume` 后一起读取 |
| 管理员 `/mcaiapply 任务名 短码` | 只批准与短码匹配的当前待批准方案；新方案需再次批准 |
| `/mcailist [页码]`、`/mcaiplan 任务名` | 查看当前群活动任务；重发待批准方案及短码，或查看多轮方案的范围、完成条件、状态和批准人 QQ |
| 管理员 `/mcaipause` | 保存进度暂停；已提交修复完成后再暂停模型 |
| 管理员 `/mcaistop` | 停止接收反馈，取消所属诊断、下载与扫描；修复中当前文件步骤结束后停止后续步骤。先释放正式服占用，再清理隔离试服并确认中止 |
| 管理员 `/mcaidone` | 验收结束；所属后台工作结算后释放正式服占用，试服清理期间即可启停正式服。后台生成已验收经验 |

不立刻发出同步文字回复的异步任务指令（`/mcainew`、未暂停或带附件时的 `/mcaisay`、`/mcaiapply`、`/mcaipause`、`/mcairesume`、`/mcaistop`、`/mcaidone`）校验受理后，会先给原消息贴上 QQ 表情回应 `[不是吧]`（编号 `476`；其他支持回应的平台贴对应确认表情，不支持时静默跳过），表示已收到并开始处理；参数错误或被拒绝时只发文字说明，不贴表情。

已提交修复的任务保持目标固定，其他服务端另建任务。停止不自动撤销已发生修改，也不生成已解决案例。修复执行中要中止使用 `/mcaistop`，不能直接验收。

上表中的补充行为只适用于已接收的消息。普通成员 say 暂停时，新消息明确拒收，不保存待补发，不打断生成或使方案失效；此前已接收的反馈保留。用 `/mcaistatus 任务名` 查看接收模式，管理员用 `/mcaisaymode 任务名 true` 恢复。普通成员反馈带不完全可信提示，管理员反馈有身份标注；操作要求以管理员提出或确认为准，仍须遵守 MC 任务范围和原审批流程。

群指令统一使用 `/mcai…`，创建时填写任务名和可选补充，不需要填写实例 ID；AI根据线索选择目标。多位管理员权限相同。

批准时使用方案通知中显示的短码，字母大小写均可。缺少短码或使用已失效的短码时，回复会附上与 `/mcaiplan 任务名` 相同的当前方案正文，末尾给出正确的批准命令；核对后再批准。插件重载后，仍在等待批准的方案保留原短码。批准记录保存实际发出批准命令的管理员 QQ。

建任务通知附带群成员补充和进度查询命令；状态查询按排查、修复、等待反馈、待批准和暂停状态给出带实际任务名的下一步命令。待批准方案同时提示管理员批准和群成员补充／调整，暂停通知区分保存补充与管理员续接。任务列表附查询及补充用法，有后续页时给出翻页命令；空列表、缺少参数或找不到任务时给出创建／查询／帮助指引。

需要按现场结果分批维护时，AI可同时提交允许范围、完成条件、后续动态规划和首批操作。管理员批准一次后，AI执行一批、读取实际结果，再决定下一批；每批具体操作仍经过独立审核，原范围内调整命令或工具无需重复批准。状态会显示批次执行、观察决策或等待必要补充；普通线索不会撤销已批准方案。达到条件后结束方案执行，报告结果待管理员验收。改变目标、扩大范围或修复失败后提出新方案，需要再次批准；原方案结束后仍可直接只读复核。文件修改每批仍执行停服备份。待批卡片会说明在线命令的恢复边界；本批已有快照时，会提示没有单独撤回方式，必要时可停服恢复本批备份。

已确认的隔离试服可以直接执行整批白名单只读控制台命令，例如 `list`、`tps`、`tick query`、`datapack list` 和符合白名单格式的定向数据查询。整批只要有一条超出白名单就需独立审核；正式服控制台命令始终送审。修改、启停和保存继续走方案流程。

排查内存问题先看[内存趋势或 JFR](queries.md#常见查询)。需要抓在线堆转储时，AI 先核对目标 JVM 和磁盘空间，并在群里说明停顿和文件大小。任务管理员用 `/mcaisay 任务名 内容` 明确同意；AI 引用该条反馈编号提交独立审核，通过后后台采集。本流程无需停服或另发 `/mcaiapply`。

## 断线和修复失败

两端网络波动自动重连，使用原操作编号查询，不重复启动诊断或修复。MC 服务端、B 上的后台诊断、扫描和下载继续运行。进行中任务的排障、审核、两类上下文压缩，API 请求错误默认持续重试；独立搜索 `mc_search`（`alpha/search`）绑定提供商端点并沿用有限重试。未配置备用模型时，认证或权限失败，以及明确额度不足的 429，每 5 分钟重试；其他错误（含普通 429 限流）依次等待 2、5、10、20、30 秒，之后固定 30 秒。

配置备用排障或备用审核模型后，排障（含上下文压缩）与独立审核各自独立进行主备故障切换：当前通道连续失败 3 次（第 1、2 次失败分别等待 2、5 秒，第 3 次失败后不等待），或遇到认证／权限失败（401、非特性拦截的 403）、明确额度耗尽的 429、模型不存在／404 配置错误时立即切到另一通道；切到备用成功不发群打扰提醒（仅记本地日志，可在 `/mcaistatus` 和任务看板看到当前通道），并按 `backup_cooldown_minutes`（默认 10 分钟）进入冷却驻留。驻留期间后续请求直接走备用；到期后先试探一次主 API，成功即切回主并清除冷却，临时失败则立即回切备用并续期冷却。只有在主备 API 都失败时，才向创建管理员发送一次提醒（同阶段 15 分钟内不重复，附 `/mcaipause` 和 `/mcaistop`），随后按退避间隔（主备均为认证／额度／配置错误时等 5 分钟，否则按 10／20／30 秒或 429 退避）主备轮流重试，直到恢复或达到[连续失败自动暂停](configuration.md#模型用量与费用保护)。`/mcaiask`、验收归档总结与群图片识别共享主模型的备用配置和冷却状态，每通道有限重试，不触发任务暂停或群告警。

未配置备用时，认证或额度问题首次出现即通知创建管理员，其他错误在同一请求连续失败 3 次后通知；每轮只提醒一次，并附带 `/mcaipause` 和 `/mcaistop`。插件重载保留重试进度。若配置了[连续失败自动暂停](configuration.md#模型用量与费用保护)，到时显示错误类别和持续时间；管理员续接后优先从主 API 继续原请求。有新反馈时仍按原规则更新输入。手动暂停可打断模型请求或等待，停止会结束任务重试。

B 离线时仍可创建未绑定任务；读取实例列表和绑定目标需等 B 恢复。从 B 拉取实例 JAR 到 A 工作区时，连接和读空闲超时均为 35 秒；持续有数据传输时没有总时长限制。

后台群消息通过持久化发件箱发送。同一发送目标按入箱顺序发送，其他群独立发送。失败后等待 2、5、10、30、60 秒再试，之后每 60 秒继续尝试。队首连续失败 3 次后，若下一次重试仍失败，会试发同群下一条；试发成功说明队首是单条故障，后续消息可以继续送达，原消息仍会重试。试发也失败则继续按原顺序等待。确认发送的合集或分段会先记录进度，重试或重载从未确认部分继续。停止任务后会丢弃该任务剩余的进度消息。

在「MCAI 设置 → 诊断导出」可查看每条未送达消息的目标群、正文首行、尝试次数、最近错误、重试时间和单条故障标记。点「立即重试」可取消当前等待时间，也可重新启用旧版已停用的消息；同一目标仍按队列发送。点「丢弃」并确认后，发件箱不再发送该消息，审计保留操作者和时间。发送中的消息需等这次尝试结束再操作。

上下文超限先自动缩减或拆批，无法缩减仍明确返回容量问题。审核拒绝是正常结果；审核模型输出非法 JSON 属于模型格式协议错误而非 API 传输故障，仍在当前审核模型上最多重试 3 次（不触发主备切换），本地记录失败明确报错并暂停。验收后的经验归档保留有限重试策略（配置备用时单通道最多 3 次并可切备一次）。

修复确定失败后停止原方案后续步骤，保留备份、已发生修改及服务端状态。AI 检查记录、状态和控制台继续分析；新方案重新审核、批准，无可行方向则暂停。不会自动回滚或重启失败的修复。

插件重载恢复已保存操作和上下文，已暂停任务保持暂停。B 程序重启会中断未完成的后台工作并保留输出。尚在排队的操作记录为未执行（`execution_state=not_executed`）；已进入执行的操作记录为状态不确定（`execution_state=unknown`）。修复不自动重放；状态不确定时停止原多轮方案的后续批次，AI 先按原编号读取记录并核实现场。托管窗口继续运行并自动重连 B；原控制请求绑定会话，不会重放到新窗口。

试服正式发布若在发送时掉线，续接先查原操作编号。只有原 B 操作库明确还没受理且原批准和试玩反馈未变，才用相同编号和参数补交；无法核实原库时保持暂停。

正常退出B会结束辅助工作、等待当前修复操作并断开托管连接，不主动停服。强制结束B会终止辅助进程树，托管窗口继续运行；未完成修改保留现场。

## 文件、存档与故障取证

可在任务中要求AI按下列方式处理，无需人工拼接NBT下标或脚本：

| 需要处理的场景 | 当前能力与执行条件 |
|---|---|
| 大配置里只改几处 | 查询文件哈希和补丁预览，保留编码／BOM／换行；原文歧义或文件变化时停止写入 |
| 日志和后台输出很长 | 限定目录、文本／正则检索、计数、末尾读取；后台沿原游标等待、按字符位置读取产物 |
| 卡顿、线程阻塞、停服无响应 | 采集实例内进程增量与JDK线程／堆概要；正常停服超时后，另提带进程身份的强制恢复方案，一次审核批准后执行 |
| 检查修复结果 | 配置解析、文本／NBT断言、新启动就绪与错误观察、端口监听；实际进服与玩家复现仍需确认 |
| 查MOD、插件、数据包冲突线索 | 本地元数据、依赖声明、重复ID、服务端适用性、哈希和前后清单比较；未知版本语法明确未核实 |
| 改玩家、实体、容器数据 | 按UUID、位置、Slot或字段选择，批量预览并核对带类型旧值，再停服备份修改 |
| 救援坏区块 | 检查区域头与记录，从磁盘或备份导出原始记录，按同目录／维度／坐标恢复；可明确移除整个区块及同位置实体／POI，其他扇区保留 |
| 定位或修复具体方块 | 读取已保存坐标、按状态检索统计；支持的布局可按完整旧状态修改，换掉有方块实体的类型需明确删除其旧数据 |

正式实例可开启[故障留证和群通知](configuration.md#故障留证与通知)。在群里说「刚才崩了，查一下就好」，Agent 会根据实例和时间找记录，按需读故障控制台、旧 JVM 指标和已归档的日志或崩溃报告，再单独核对当前状态。事件详情按每次启动列出附件及缺失原因。日常排查仍可直接查当前日志。留证只观察，不触发停服或修复。

遇到「跑新图就卡」或「存盘时全服顿一下」，可以让 MCAI 按需采集 **60 秒区块 JFR**。默认静默开录；需要配合复现时，可要求发送开录提醒（`notify_user=true`），收到提醒后照原步骤复现。Agent 会继续等结果，无需批准或回复。支持区块生成的版本可统计阶段和耗时；支持区域读写的版本可查看发生时间、区域、次数和字节数。读写事件本身不等于 I/O 延迟；与慢 tick 重合也不单独证明卡顿原因。前提是托管 Java 有同目录的 `jcmd.exe`，且没有其他 JFR 录制。Probe 非必需；慢拍逐拍对齐需要同会话的 Probe 历史。原件随 B 的诊断作业保存，不占主动留证库额度。

文件写入继续使用原方案审核、管理员一次批准、停服和备份。强制停服先保留现场并核对PID、创建时间和托管会话，不自动触发。原生`force_stop`先结束该实例已识别的自动重启启动链，再结束目标Java及其子进程，保留托管PowerShell和start.bat；可能丢失未保存进度，退出不完整时停止后续文件步骤。JVM取证需要实际运行MC的Java同目录有`jcmd.exe`（JDK），不会改用存档工具的Java替代。磁盘读取只代表已保存数据，在线采集中变化会标记；不主动加载区块。MCR方块语义目前只读，未知布局或缺少section会明确停止；普通NBT编辑与原始区块恢复仍可使用。语义方块修改不推断模组专有缓存或POI，重启后应结合相应服务端检查。

## 控制台与内存额度

控制台每窗口保留9999行，且最多16 MiB UTF-8内容；单行超过64 KiB保留末尾并标注截断。不连续写入B数据库。游标包含会话，内容淘汰会返回缺口；更早数据查询服务端logs。窗口关闭后缓冲消失，B重启不会清除仍在窗口里的缓冲。任务实际读取的片段和操作审计仍持久化。

辅助扫描、下载、NBT、备份、修复及脚本由独立进程执行，所有实例共用 `operations_memory_limit_mib`，默认8192 MiB。上限按Windows提交内存计算，包含辅助Python进程及子进程的开销，不是Java的Xmx或文件大小。B和服务端不计入额度。额度不足使当前操作失败，保留输出与备份，AI可缩小范围继续；新修复重新批准。此额度不限制MC，也不防止MC占满整机内存。

## 群文件和图片

发送 `/mcainew 任务名 问题描述` 或 `/mcaisay 任务名 内容` 时，可以在同一条消息附上文件或图片，也可以引用带附件的消息。例如引用玩家的 `latest.log` 后发 `/mcaisay 主城卡顿 看这个`。只有附件时可以省略文字。普通上传和闲聊不会自动进入任务；管理员暂停成员补充时，成员的附件不会下载。管理员引用普通成员上传的附件，仍保留原作者和非管理员来源。

- 文件单个最多 20 MiB，接受 `.txt`、`.log`、`.gz`、`.zip`、`.json`、`.toml`、`.cfg`、`.properties`。`.gz` 解出一份文本；`.zip` 只取支持的文本文件。每包解出最多 100 MiB、200 个文件，不解嵌套压缩包；越界路径会拒绝整个包。某个附件下载或解压失败，会单独说明原因，同条消息里已保存的附件不受影响。
- 图片单张最多 10 MiB。原图存入任务工作区，排障模型单独识别一次；任务只读到提取文字和画面说明，并标为可能有误。设置页「保存并测试」可查看图片识别能力。当前模型明确不支持时仍保存原图，请另发关键报错文字。语音暂不解析。
- 文件和识别文字都是排障线索，不是操作指令。发崩溃报告时，最好补明发生在玩家客户端还是服务端，以及游戏名和时间，便于区分本地 MOD、驱动问题和服端故障。

## 定时备份与定时重启

AstrBot Dashboard 管理员可在「定时维护」直接创建、编辑、暂停、恢复和删除计划，从实例及类型筛选，并核对调度健康、下次 B 本地时间和上次结果。网页登记记为 `web:<username>`，复用 B 的时间和路径校验，无需群内审核和确认。编辑生成新编号；原计划有未结算时段或公告时须等待。QQ 入口仍沿用下面的审核和短码批准流程。

用普通任务提出计划，审核通过后查看 `/mcaiplan 任务名`，核对目标实例、时间、路径或公告时间、保留数和通知选项，再用 `/mcaiapply 任务名 短码` 批准一次。时间按 **B 本机时区**，支持每天和每周指定几天；批准后不需要模型、AstrBot 或 QQ 在线。修改参数时用新任务说明要替换的计划编号，重新审核、批准。例如：

```text
/mcainew 每日备份 每天 03:00 在线备份 cti 的 world 目录，保留 7 份
/mcainew 每周重启 每周一和周五 05:30 定时重启 cti，提前 10 分钟和 1 分钟公告，成功也通知群
```

- 在线备份先关闭自动保存并等待 `save-all flush` 的保存回执，再复制批准的路径；复制结束或失败后恢复自动保存。在线复制不包含 MC 世界的临时 `session.lock`。如果 B 中途退出，重启后会尝试在原窗口和原 Java 进程上恢复自动保存；会话变更时只记录。停服备份只会停启原来运行的实例，原本停止时直接复制。
- 备份默认写入 B 数据目录的 `backups/操作编号/`；可在 B 配置中指定另一块盘。备份使用与修复备份相同的清单。要恢复时，可以按备份编号提出 `restore` 方案并审核、批准。恢复会在目标盘准备并校验候选；替换失败时，按该操作记录的目标、候选和原目录保留路径核对现场，不默认重试。每次备份成功后，按保留数删除同一计划最旧的备份；如果备份仍被审核或活动操作引用，会暂时超出保留数。修复备份和其他计划的备份不受影响。
- 重启只处理正在运行的实例，默认提前 10 分钟和 1 分钟公告，按原 `start.bat` 的方式停启，并检查服务端是否就绪。实例正在修复时，备份和重启都最多推迟 30 分钟；有 A 端活动任务时只推迟重启。A 超过两分钟没上报时，B 照常判断并执行重启，在结果中注明活动任务状态未知。
- 已批准计划仍绑定审核的实例目录。若本次动作的审核快照包含 Java 路径或停服命令，只比较这两项是否变化；变更后需重新提案。停服超时、重启提示、BAT 编码和 PowerShell 路径不参与这项比较。
- B 停机错过时间时，只补跑最新一次备份，不补重启；结果都会通知。失败、推迟和跳过都会按[已配置的群路由](configuration.md#故障留证与通知)通知：有该实例的配置就发往指定群，否则使用 `*` 默认通配。正常成功默认不通知，可在提出计划时开启。
- 群成员可用 `/mcaischedule list` 查询计划编号、实例、时间、状态、下次执行时间和上次结果。管理员可用 `/mcaischedule pause 编号`、`/mcaischedule resume 编号`、`/mcaischedule delete 编号` 管理计划。这三项会记审计，无需重新审核；暂停或删除不会中断已经开始的一次维护，也不会删除已有备份。

## 数据与备份

「运行概览」显示托管窗口、Java PID、占用任务、配置待生效和隔离试服；实时玩家、近 10 秒 TPS／MSPT 由管理员按实例刷新。启动、停止、重启以及强制操作见[直接启停正式服](#直接启停正式服)。提交未收到确认时，在原实例核对原编号。配置重载仅重新读取 B 的实例文件。

隔离试服显示运行状态、窗口是否退出、Java PID 和目录是否存在。试服所属任务结束后，可以在这里停止、强制停止、关窗或删除；删除运行中或窗口未退出的试服时，确认后将强制停服、关窗并永久删除副本。活动任务的试服只允许在停稳后关闭窗口。手工移除副本后，仍未退出的窗口会继续显示，便于清理；目录和窗口均已消失且相关操作结算后，残留记录自动收敛。

「故障与告警」按实例、事件类型筛选并分页查看 B 的留证、告警历史与定时事件，活跃健康告警单列。可选「仅看现有实例」；删除实例、换目录或关闭相应告警会清理不再适用的活跃状态，不发恢复通知。历史仍在留证库中，按容量淘汰。A 的失联与恢复记录在 B 离线时仍可读取。打开事故可分段查看故障控制台、Probe 性能、各轮启动及附件；已留存的日志或崩溃报告可分页预览或下载 gzip。

| 位置 | 内容 |
|---|---|
| A：`AstrBot/data/plugin_data/astrbot_plugin_mcai/` | 任务、消息、审核与工具记录、规则、网页缓存、经验 |
| A：`knowledge/index.md`、`knowledge/servers/*.md` | 按 B 的规范目录关联的经验索引和文档 |
| B：配置的 `data_dir` | `state.sqlite3`、`audit.jsonl`、证书和任务数据 |
| B：`data_dir/incidents.sqlite3` | 故障事件、控制台快照、故障前指标和已归档的 gzip 附件，按留证容量上限管理 |
| B：`jobs/操作编号/` | 后台结果、诊断脚本、输出及存档采样副本 |
| B：`downloads/操作编号/` | 完成校验的暂存文件和未完成临时文件 |
| A、B：各自的 `workspaces/` 或配置路径 | A 的任务源码与构建目录，B 的隔离试服和失败的复制现场 |
| B：`backups/操作编号/` | 原文件、`manifest.json`、修复脚本与输出 |

完整命令、上下文和错误保存在本地。经试玩成功发布并验收的任务会自动清理其工作区制品与试服，正式服备份、普通下载及历史仍需按下文维护。

打开「MCAI 设置 → 数据占用」，点击「统计占用」。A 显示各类文件的大小和数量、审计行数、最大的 10 个任务留痕及其任务状态。数据库大小包含 WAL，按记录类别另列条数和正文大小；正文大小用于判断哪些记录增长，与数据库文件占用是两个数值。B 显示数据盘剩余空间、下载、后台结果、故障留证、执行日志及试服工作区占用，并按操作编号列出备份。备份行的任务状态来自 B 看到的操作或后台结果，不代表 A 的验收或归档状态。B 离线时仍可查看 A；超时或无法读完的类别会标为「部分」或显示错误。

「状态数据库可回收」是 SQLite 当前空闲页的总大小。确认两端没有正在运行的任务等工作后，可分别点击「压缩 A 数据库」或「压缩 B 数据库」，让 `state.sqlite3` 归还空闲空间。压缩需要额外磁盘空间，耗时随文件大小变化，适合在维护窗口执行。压缩前后大小写入审计，不处理 `incidents.sqlite3`。

A、B 的 `audit.jsonl`、A 无任务留痕 `traces/unassigned.jsonl`、B 的 `execution.log` 跨自然月压缩，例如 `audit-202610.jsonl.gz`。文件大小计入统计，审计行数只数当前未压缩文件。可在「按月清理日志归档」选择 A 或 B，刷新后选月份，确认永久删除该端该月的压缩日志；当前日志保留，删除写审计。

### 导出一次完整交互

「数据占用」的 B 明细区分修复备份和定时计划备份（含计划编号），可查看清单覆盖范围。可检查当前和近期作业、取消未结算作业，并核对暂存下载的来源、大小、SHA-256、所属任务和安装引用。

在「MCAI 设置 → 诊断导出」选择「排障任务」「只读问答」或「全部与全局日志」。可在前两个标签用独立搜索框查找记录并跨标签多选；点击搜索框旁的「日期筛选」可设置本地日期，或勾选「精确到时分」。要导出当前搜索结果，先点「全选当前」。

勾选后默认导出所选项的完整日志，也可开启「导出时也按此时间范围截取已选项的日志事件」。未勾选时，按当前标签和日期范围导出；只有「全部与全局日志」还会包含未关联任务的命令、权限拒绝和系统审计日志。ZIP 同时下载到浏览器并保存到 A 数据目录的 `exports/`，B 离线也可导出 A 已保存的信息。

导出读取所选月份的 A 端压缩日志和当前日志，逐行过滤并使用临时文件归并时间顺序，需要为临时副本留出磁盘空间。遇到文件内部的时间倒序（如系统时钟回调），程序会在磁盘上稳定排序对应临时副本，并在设置页列出相关日志。导出不会改写原日志。

包内`events.jsonl`保存用户插件命令、模型实际请求和响应、流式消息、工具及消息事件，`records.json`保存相关任务、任务对话、工具和审核状态，`timeline.md`提供时间索引，`manifest.json`说明版本、范围、三份运行时规则的模板基线状态及缺失限制。A 的占用统计会将独立保存的任务对话列为 `task_messages`；导出时仍把对话合并进对应任务。API 正文保存在 A 的`traces/`；AstrBot 日志仅显示请求编号及路径。旧版本未记录的请求、API 未公开的推理及尚未取得的 B 端结果无法补回。导出不包含完整数据库、完整配置、存档、备份或连续控制台日志。执行进度汇报默认关闭，开启后只转发主模型 commentary 消息；旧摘要转发选项已移除，推理摘要和审核内容不进群。

文件修复会先估算备份大小，再加上 1 GiB 或备份大小的 5%（取较大者）。`backups/` 所在卷的可用空间须扣除同卷其他尚未写完的修复备份估算量。空间不足时以 GiB 报告所需和可用空间；备份范围有循环链接或目录联接时也会明确拒绝。这两种情况均在停正式服或试服前结算为未执行。空间和文件在预检后仍可能变化。通过预检后才按计划停服备份；成功后原先运行的服务端默认启动，方案中显式启停步骤优先。在线控制台修复可能没有可恢复备份，批准消息会说明。人工恢复某次备份会先备份当前目标：

```powershell
.\.venv\Scripts\python.exe -m mcai restore cti 备份目录名
```

恢复使用备份清单：恢复原文件、移除该次修复新增的目标。恢复操作也可能失败，应保留原备份并检查执行记录。

### 手动清理与离线备份

「MCAI 设置 → 数据占用 → 清理已结束任务」只接受已验收或已停止、且取消、归档及清理都已结算的任务。活动任务、暂停任务，以及仍被未结算操作、待恢复审核或有效多轮方案引用的数据会保留。

1. 选择「单个任务」或「按天数批量清理」。单个任务点击「刷新任务」后选择；批量输入结算天数，例如 `30`。逐项勾选要清理的数据。A 可选任务留痕、网页记录、工作区、已发送或明确结算为失败的发件记录，以及未引用的 A 端下载目录与记录；待重试的消息继续保留。B 可选后台结果和未被安装引用的暂存下载（勾选「下载」会同时核对 A／B 暂存）。正式服备份默认不勾选，执行前还要单独确认。
2. 点击「预览清理」，核对路径、记录条数和大小；批量预览按任务列出结算时间、各类别大小及跳过原因。备份会列出操作编号、实例和大小。勾选 B 的类别（含同时涉及 B 端的「下载」）需要 B 在线；只勾选仅属 A 的类别可以离线执行。检测到目录链接、目录重定向或越界路径会拒绝清理。
3. 点击「确认清理…」后再点击「执行清理」。执行会重新核对任务状态、引用和清单；结果有变化时必须重新预览。A 会先将所选留痕、网页和发件记录存为 `exports/mcai-archive-<时间>.zip`，包含 `manifest.json`、`events.jsonl`、`records.json` 和 `timeline.md`。A 工作区和 A／B 下载与 B 文件不进这个包。两端先记录操作者、范围和字节数再删除。若两端仅一端成功或 B 响应中断，先核对两端审计和目录，再重新预览；程序不会自动重试删除。

B 清理后台输出或暂存下载时，同时移除对应数据库记录及后台输出事件。原操作记录仍可查询，读取已清理的后台任务会明确提示。勾选「B 端试服目录」可预览并删除已结算任务的试服副本、复制半成品和终端目录；试服窗口未退出时，先到「运行概览」停服并关窗。清理期间避免同时移动或替换所列文件；清理正式服备份前，先确认不再需要用它恢复，或另存一份完整备份及其清单。

如需自动维护，在同一区域设置「自动清理已结算任务数据的天数」。默认 `0` 不执行。开启后，A 启动后约一分钟开始检查，每个本地日期最多执行一次，重载也不重做当天的清理。自动执行使用批量保护规则，清理 A 留痕、网页、已结算发件记录、工作区及两端未被引用的暂存下载、B 后台结果；A 选定数据仍先归档，备份及日志归档仍只能人工删除。不向群发结果，可在 A 审计查看完成、跳过和失败的任务。旧任务缺少可靠的结算时间时，批量和自动清理都会跳过，可单独选择清理。

清理期间仍可创建任务和绑定实例；排障模型若刚返回新的工具调用，会等清理完成再登记引用。已结算的历史任务仍可在设置页选择清理或导出诊断，群命令只显示活动任务。

预留“全部待备份文件＋暂存下载＋现有历史”的空间，定期查看磁盘可用量。在完整源码包中可运行只读清单；可重复传入已安装 Probe 的实例目录：

```powershell
.\.venv\Scripts\python.exe scripts/data_inventory.py --a-dir "D:/AstrBot/data/plugin_data/astrbot_plugin_mcai" --b-dir "D:/MCAI/runtime/host" --instance "D:/MC/NCraft"
```

清单统计字节、文件数、数据库记录类型和quick_check，列出活动／暂停任务、待批准方案、未结算工具、运行操作、待取消、待归档和待核对控制的引用来源。两端应在同一维护窗口导出；未列出活动引用的历史仍可能用于人工恢复和经验追溯，清单不生成删除候选。

离线备份或维护其他数据时，先让 A 停止接收任务并退出插件，正常退出 B 等待修复完成；维护 Probe 数据还需停对应 MC 服。完整备份 A/B 数据、实例 Probe 目录和托管窗口数据，保存配置及证书。SQLite 使用 Python 的 `sqlite3.Connection.backup` 做一致副本，对副本执行 `PRAGMA integrity_check`；运行中不能只复制主数据库而遗漏 WAL。数据库 records/events、审核与上下文证据不手工逐行删除。完成后启动两端，核对原操作、历史查询、备份读取和暂停任务续接。

备份按源规范目录核对身份；同目录改配置名仍可恢复，同名换目录会拒绝。缺少来源目录的旧清单需人工核对。`mc_operation_read`用operation_id查询原操作和脚本日志，每页最多12000字符，沿next_call继续读取。可使用与产物、历史相同的`result_path`键／下标数组定向取原值，例如`["operation","status"]`、`["operation","current_step"]`或`["operation","error"]`；返回的value来自原记录，避免整份材料缩略后丢失本次审核所需字段。

## MOD 试服试玩与正式发布

1. 在「B 主机」统一配置玩家可达的 `test_address` 和专用 `test_port`，在各实例按需填写 `test_copy_paths`。不同任务可保留各自的磁盘副本，但全局同时只有一个试服可以打开托管窗口或运行。`mc_test_server`（`status`）在试服尚未创建时返回 `not_created` 与已配置的 `test_address`／`test_port`，创建后同时展示对外地址、端口与 `server.properties` 的实际 `listen_ip`／`listen_port`；停服后可在「运行概览」关闭试服窗口，或用 `mc_test_server` 的 `close` 释放名额，副本仍保留。
2. 管理员批准包含试服验证和正式发布范围的方案。源码修改、只读 `jar_entries`／`jar_diff`／`javap` 检查与构建在 A 工作区完成；B 在隔离副本安装、启动并记录目标 JAR SHA-256 与就绪结果；需要真人进服复验时，确认就绪后由 A 向群里发试玩邀请。后续仅调整普通配置或执行命令不会使未变动的已验证 JAR 失效。
3. 实际进试服复验后，由管理员发送 `/mcaisay 任务名 刚进试服验证，原故障没有再出现`，或说明具体失败。通过反馈须对应本次邀请和实际试玩；如果有失败或仍不明确，任务继续检查，不会因此发布。若为纯服务端改动且任务管理员书面授权免除真人进服（`client_login_waived=true`），须附原管理员反馈 ID 与试服安装操作编号，B 仍严格核对同一制品 SHA-256 及后续 `ready` 验收（允许试服已干净停止）。
4. 明确通过或按管理员免试玩授权满足发布条件后，MCAI 在原批准范围内正常关闭试服（若尚在运行），备份正式服、安装实际验证过的同一份制品，再启动验证。若管理员明确只需在试服验证，凭原反馈调用 `mc_plan_finish`（`release_waived_feedback_id`）结束方案后即可 `/mcaidone 任务名` 验收。任务中止或仅试服结案后，会自动停止试服，正常停服超时则强停，再关窗并删除副本与工作区制品。若清理失败，可到「运行概览」手动处理。正式发布后的验收清理保留正式服备份。

## 经验维护

「任务看板」可筛选活动和历史任务，查看模型用量、待批方案和多轮授权范围，执行成员 say 开关、暂停、续接、中止与验收。批准仍须填写当前短码并核对独立 AI 审核记录。已验收但归档失败的任务可在看板重试归档。

「经验知识库」按实例打开案例卡片，最新案例在前，每页20条，可按标题、编号、类型、关键词或正文筛选；筛选后从第一页显示。卡片展示类型及已过时的替代编号，可编辑、删除或新增人工经验。通过「目录关联管理」新建和修改关联、解除关联或删除孤立文档。需要编辑文件时可切换 Markdown 源码，或在折叠的高级区打开原始 `index.md`。文件已更新时须重新读取后再保存。

新经验顶部包含标题、类型、状态、关键词、环境与替代案例，正文先给结论与适用条件，再记录依据、操作验证、避坑、备份和来源。旧文本与人工Markdown仍可直接维护。明确被新结论覆盖的旧案例在检索中默认隐藏，网页显示“已过时”；替代关系由新案例的“替代案例”编号派生，旧正文保持原样，删除替代者后会重新计算。

管理员验收后才归档，不把 AI 自称修好直接记为成功。归档在后台进行，失败不会重新占用实例；待归档状态在插件重载或该实例下次绑定时重试。

经验文档允许人工补充。索引的 `mcai-server` 注释以 JSON 记录规范目录和相对文档路径，`mcai-case` 标记用于案例去重，编辑时保留这些标记。注释 JSON 无法解析时，实例仍可绑定；读取历史或归档会报告 `index.md` 的错误行，修正后再重试。实例配置改名或公网 IP 改变不影响目录关联；搬迁服务端目录默认视为新实例，需要继承经验时，在「目录关联管理」将文档关联到新目录。当前按一台 B 设计，换到另一台主机应分开维护经验。

## 升级与常见问题

组件清单遇到非标准依赖元数据时按文件返回错误并继续，`summary.partial=true`说明结果不完整；不能将失败组件解释为不存在。就绪验证独立识别Probe身份，不依赖完整组件清单。

标准Anvil的`Blocks/Data/Add`现支持12-bit扩展数字方块ID（0–4095，Data为0–15）的`block_set/block_batch`写入，并读取`level.dat`中的FML ID映射辅助显示与按注册名查询；写入仍使用明确的数字`Id/Data`状态。包含`Blocks16/Add2/Data16/BlocksB2/BlockIDs`等未知扩展数组的区块（如GTNH自定义扩展ID节格式）仍明确拒绝方块语义写入，MCR列式方块仍只读。区域NBT、实体筛选及区块导出恢复按各自能力使用，不能由读取成功推定任意方块布局可写；具体边界见[方块坐标与状态](../design/integrations.md#方块坐标与状态)。

启动后的只读补验可直接执行，无需重复批准。`ready`默认把`Done (`视为字面量，启用正则时会在方案产生效果前检查表达式；证据仍须来自本次启动或明确游标／会话。原BAT自动重启循环属于原服务端启动方式，修复失败后MCAI保留现场、停止该修复方案；两者分别判断。

### 升级步骤

0.21.x、0.20.x 与 0.19.x 同为 `mcai-9`。升级时配套更新 A、B 和所有托管窗口，包括仍使用 `mcai-8` 的旧安装。已有留证直接保留；若尚在旧主库中的历史事件未导入，会由 B 导入独立留证库并保留原编号与通知游标（没有保存文件附件的旧事件不能补回）。随 B 包提供的 Probe 0.5.0 若未随当次版本重建，已安装同构建的服无需替换；旧构建按[安装表](probe.md#安装)更新。

各版本的行为调整与配置变化见[发布说明](releases.md)。升级后先用 `/mcaiplan 任务名` 查看方案，再用 `/mcaiapply 任务名 短码` 批准；短码必填。网页读取和下载只访问公网地址，代理的检查方式见[下载代理与 HTTPS](configuration.md#下载代理与-https)。设置页提供「数据占用」及[手动清理](#手动清理与离线备份)，按需预览并确认后执行。

1. 用 `/mcailist` 核对活动任务。完成或中止任务，并等已提交的操作收尾。未结算的旧工具调用不迁移。
2. 停用插件或退出 AstrBot。在维护窗口正常停服、关闭旧托管窗口，再正常退出 B。备份 A 插件配置与数据目录，及 B 的 `host.json`、`instances.json` 和 `data_dir`；这些目录包含证书、任务历史、备份、规则及经验。自定义任务工作区另行保留。
3. 用同次发行的 A、B 包更新原安装，保留原配置和数据。在 B 安装目录运行 `./.venv/Scripts/python.exe -m pip install -e .`，再启动 B，重新为每台服打开托管窗口并运行原 `start.bat`。单独重启 B 不会替换仍在运行的旧窗口代码。
4. 在 AstrBot 更新并启用插件。打开「MCAI 设置 → 运行时规则」，逐份查看新版提示及差异；升级不会自动覆盖现有规则。按[规则说明](configuration.md#运行时规则)保存人工合并后标记已合并，或确认由插件先备份再采用新模板。测试 A→B 连接、模型能力和新建只读任务。AstrBot 最低 v4.29.4，当前集成验证以此版本为基线；更新 AstrBot 后也做同样检查。

### 安装依赖时拒绝访问

Windows 上，AstrBot 插件页安装依赖时，pip 可能需要升级 AstrBot 已加载的 Python 扩展。例如 `trafilatura 2.3.1` 要求 `charset-normalizer>=3.5.2`，若环境中仍是 3.4.7，替换其 `__mypyc*.pyd` 时可能出现 `WinError 5：拒绝访问`，使插件安装中止。

1. 完全退出 AstrBot，确认其 Python 进程已结束；仅禁用或重载插件无法保证释放扩展文件。若使用自动重启脚本，先停止该脚本。
2. 将同次发行的 `astrbot_plugin_mcai.zip` 解压到临时目录，找到其中的 `requirements.txt`。
3. 在 PowerShell 7 中，用 **AstrBot 实际使用的 Python** 安装这份依赖清单。以下示例中 AstrBot 位于 `D:\AstrBot`，插件解压到 `D:\MCAI-A`；按自己的目录替换：

```powershell
& 'D:\AstrBot\venv\Scripts\python.exe' -m pip install -r 'D:\MCAI-A\requirements.txt'
& 'D:\AstrBot\venv\Scripts\python.exe' -c 'import trafilatura, charset_normalizer; print(trafilatura.__version__, charset_normalizer.__version__)'
```

使用镜像时，在安装命令末尾加 `-i 'https://mirrors.aliyun.com/pypi/simple/'`。不要换用 B 的 `.venv` 或系统 Python。若进程全部退出后仍拒绝访问，检查运行账号对日志所示文件的读写权限与文件占用。

安装命令成功、导入检查打印版本号后，重新启动 AstrBot，在插件页重试安装 ZIP 或仓库。若上次 pip 卸载失败导致 `charset_normalizer` 导入损坏，在 AstrBot 仍退出时，用同一个 Python 执行 `-m pip install --force-reinstall 'charset-normalizer>=3.5.2,<4'`，然后重新安装插件依赖并检查导入。

### 其他常见问题

| 现象 | 处理 |
|---|---|
| 无法连接 B | 检查 B 是否运行、端口映射、防火墙和 A 的最终 `https://` 地址；详细错误看本地日志 |
| 指纹或令牌错误 | 核对 B 启动输出与 A 配置，修改后重载插件 |
| 证书文件缺失或损坏 | 检查 `server.crt` 和 `server.key`；不会覆盖现有半套证书 |
| 模型或审核配置错误 | 修正提供商、参数或凭据后，管理员 `/mcairesume` 继续 |
| 查不到目标服务端 | 检查 B 的目录与 `description`；在群里补充常用名称、版本或位置 |
| Java 版本不符 | 分别检查实例 `java_path`、BAT 写死路径和 `world_tools.java_path` |
| PowerShell 版本错误 | 安装 PowerShell 7.3+ 的 7.x，或在 B 的 `powershell_path` 指定正确 `pwsh.exe` |
| 主动停服超时 | 检查本次退出提示是否匹配、倒计时是否存在；原循环不需要删除。未确认退出时不会进行文件修复 |
| 不能搜索或网页提取失败 | 核对模型服务能力；动态或需登录页面不支持完整浏览器渲染 |
| MOD 下载受限 | 检查 CurseForge key、分发权限及实际官方文件地址 |

人工换证书时先停止 B，将旧 `server.crt`、`server.key` 一起移走，再启动生成新证书并更新 A 的指纹。公网 IP 变化而证书未变时，只改 `host_url`。更多持久化与失败语义见[状态与恢复设计](../design/storage-and-recovery.md)。
