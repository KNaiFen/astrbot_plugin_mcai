## A：AstrBot 插件

推荐打开插件详情的 **设置视图**：连接测试、模型选择、能力测试、多人权限、B 的服务端和 CurseForge 密钥集中在这里。普通插件配置页同样支持 `_conf_schema.json` 中的字段。

模型的 API 地址、密钥和模型名称先在 **AstrBot 模型提供商页**配置。插件下拉选择该提供商，显示名称、ID、模型和接口类型。提供商 ID 不是模型名或 API Key。

| 字段 | 默认值 | 用途 |
|---|---|---|
| `host_url` | `https://127.0.0.1:18765` | B 最终控制地址，公网 IP 加映射端口即可 |
| `host_token` | 必填 | B 的共享令牌，设置视图留空保留原值 |
| `host_fingerprint` | 空 | B 证书的 SHA-256 指纹，自签名 HTTPS 直连时填写 |
| `curseforge_api_key` | 空 | CurseForge官方API／CDN凭据，仅A使用，不进入模型上下文 |
| `workspace_dir` | 插件数据目录下的 `workspaces` | A端任务源码、MOD和构建文件目录 |
| `workspace_powershell_path` | 空 | A 端 PowerShell 7.3+ 完整路径；留空自动查找。插件启动和保存 A 设置时都会校验，即使尚未使用 MOD 源码构建 |
| `provider_id` | 空 | OpenAI 兼容 Chat／Responses 排障提供商；留空使用当前群同类配置，一键测试需明确选择 |
| `reasoning_effort` | 空 | 排障思考强度；留空继承，支持服务商接受的自定义值 |
| `review_provider_id` | 空，必须选择 | 独立审核模型，支持 OpenAI 兼容 Chat／Responses |
| `review_reasoning_effort` | 空 | 审核思考强度，留空继承审核提供商 |
| `model_prices` | `[]` | 模型提供商单价，每行 `提供商ID=货币:输入:输出:缓存`；费率单位为每百万 token |
| `task_token_limit` | `0` | 单任务输入＋输出 token 累计上限；`0` 不限 |
| `model_failure_pause_minutes` | `0` | 单次模型请求连续 API 失败达到此分钟数后暂停；`0` 关闭 |
| `max_steps` | `40` | 每轮 Agent 最多模型步骤 |
| `forward_progress` | `false` | 转发主模型 Responses `commentary` 执行进度汇报，要求简短中文；不转发推理摘要 |
| `enable_web_search` | `true` | Responses 托管搜索 |
| `web_search_tool_type` | `web_search` | 可选兼容格式 `web_search_preview` |
| `enable_alpha_search` | `false` | 独立 `alpha/search` 搜索，Chat／Responses 均可测试 |
| `admin_ids` | `[]` | 可管理任务的 QQ 号；AstrBot 自身管理员同样可操作 |
| `group_ids` | `[]` | 允许的群号；留空允许所有群 |
| `allow_member_ask` | `false` | 允许群成员使用 `/mcaiask`；关闭时仅管理员可用 |
| `member_ask_cooldown_seconds` | `300` | 普通群成员上次受理问答后须等待的秒数；`0` 关闭冷却，每人仍只可同时提出一个问题 |
| `ask_max_steps` | `10` | 只读问答 `/mcaiask` 最多模型步骤（1–200） |
| `ask_timeout_seconds` | `180` | 只读问答 `/mcaiask` 超时秒数（至少 1 秒） |
| `incident_routes` | `[]` | 按实例设置[故障通知群](#故障留证与通知)；留空仅在 B 保存证据 |
| `host_offline_alert_minutes` | `3` | A 连不上 B 持续多久后通知已配置路由的群；至少 1 分钟 |
| `auto_cleanup_days` | `0` | 自动清理已结算任务数据的天数；`0` 关闭。开启后每天根据结算时间清理，永远保留备份 |
| `group_forward_threshold` | `400` | QQ 长回复合集门槛，填正整数；单条回复字符数超过该值时合并转发 |

QQ 和群号建议填字符串。多位管理员权限相同，可以交叉创建、批准、暂停、续接和结束任务。玩家可补充线索、查看状态和列表；普通闲聊不进入任务。

在设置页「群与通知」可开放成员问答，并调整冷却秒数、问答步数上限和超时秒数。冷却按成员计算，从受理提问时开始；管理员无需等待冷却。

### 模型、搜索与能力测试

排障与审核均使用 AstrBot 的 `openai_chat_completion` 或 `openai_responses` 提供商，排障模型必须支持工具调用。原生 Gemini 等其他适配器暂不支持本插件的完整工具结构，设置保存、能力测试及任务运行会明确拒绝。主模型与审核模型可相同，审核使用独立无工具对话。思考强度可以填 `low/medium/high/xhigh` 等模型支持的值，只覆盖对应请求，不修改共享提供商配置。

两种搜索可分别开关、同时使用：

- 托管搜索：Responses 请求的 `tools` 加入 `web_search`，保留 MC 函数工具。服务商明确不支持时本轮关闭该功能，API请求错误按任务持续重试策略处理。
- 独立搜索：`mc_search` 通过提供商基础地址追加 `alpha/search`，例如 `https://example.com/v1/alpha/search`。按 Codex 协议提供搜索、打开来源、页内查找，复用提供商鉴权、代理和请求头。任务内引用持久化。只有加密数据、没有可读 `output` 时明确返回不可用。

`mc_web` 继续用于直接获取已知 URL 的正文，网页内容属于外部资料。

“保存并测试、自动配置”执行短对话、图片识别、流式响应、无副作用回显函数及续接、各一次搜索、来源打开／查找、commentary 执行进度汇报、审核 JSON。不会操作 MC 或发送群消息。结果区分验证通过、明确不支持、本次未观察到和请求失败。图片能力测试只使用内置色块；群截图使用同一个排障提供商，运行时只复用匹配当前提供商的明确不支持结果。搜索验证通过后开启对应搜索功能，进度转发保留用户选择；托管搜索明确不支持再尝试 preview；临时失败保留此前配置，未观察到汇报不直接判定不支持。修改提供商、模型或思考强度后需重测。测试会产生少量模型及搜索费用。

执行进度汇报默认不转发到群。主模型按运行时AGENTS.md中的通道约定交流：工作前先对齐边界，推进中分享假设、发现、决策和方向变化，说清已知、未知与下一步；不设固定时间或工具调用次数。手动开启 `forward_progress` 后，程序转发 Responses 明确标记 `phase: commentary` 的助手消息，去掉空行、Markdown 标记与内部检索引用标记（不向群里插入未解析引用标签）；关闭时commentary只保留本地，不影响必要提问和最终答复。消息完成后即可入群发件箱，不必等整轮模型响应结束，汇报后任务继续。

中途进度不提问，也不包含最终答复。只有确实缺少用户信息或需管理员拍板才能继续时才通过`mc_say`合并提问，入箱后即转入等待并结束本轮，同轮不再附带发送 `final`；结论和验收请求使用final通道，在Responses中对应`phase: final_answer`。最终答复应独立完整，无需回看进度，完整 URL 引用保留在答复与任务历史中。

群内普通答复、提问、方案说明与进度消息超过合集门槛（含任务名前缀）时，QQ OneBot v11 适配器会把完整正文和来源链接放进一张合集卡片，接入端须支持群合并转发。默认超过 400 字符触发，正好 400 字符时插件照常发送；在“群与通知”的“QQ 长回复合集门槛”可修改。合集内每段最多 1800 字符，优先按换行分段。需要 @ 的消息在卡片之后发出一次 @。其他适配器仍按原长度分段发送，首段携带原有 @。此门槛只控制 MCAI 的合集转换，AstrBot 对命令回复的原有全局设置仍然适用，模型的任务上下文不受影响。

此功能需要服务商／模型返回 commentary 阶段消息；普通文本、推理摘要和审核内容不作为进度转发。中文由主模型按提示生成，不另发翻译请求。能力测试不会自动开启转发，未观察到汇报保留用户选择，明确不支持时关闭。原有摘要详细程度、标题／正文转发选项已移除，旧摘要转发配置不用于开启新功能。插件不再主动请求推理摘要；服务商自行返回的推理信息仍保存在本地API原文中。API返回原文和流式片段保存在A数据目录的`traces/`，只能记录服务商实际返回的内容。

Chat／Responses主请求均优先采用流式接收，关闭群进度转发也继续流式。服务商明确报不支持stream时，本轮回退非流式。主模型、审核和验收沿用AstrBot提供商的请求超时；下述300秒设置仅用于上下文压缩。各任务使用官方SDK的私有客户端实例，多Key选择和独立超时作用于实际请求，SDK自动重试关闭。进行中任务按[断线和修复失败](operations.md#断线和修复失败)重试或暂停。任务验收后的经验归档保留最多3次、2／5秒退避的策略。模型最大尝试次数不再作为可配置项。

保存 A 连接／模型配置时需等待当前轮结束或先暂停任务，避免替换执行中的连接。

### 模型用量与费用保护

设置页「模型与能力 → 模型用量与费用保护」按 A 机器本地日期显示最近 30 天的合计与每日模型用量，并单列这段时间内记录的非任务请求，如能力测试和 `/mcaiask`。任务按输入与输出 token 总量排序，可切换「前 10／全部任务」、按关键词搜索并打开阶段明细；任务看板也显示输入、输出、缓存和费用。用量单位是 tokens，价格单位是每百万（1M）tokens。未返回 token 或缓存命中数的请求分别计数；旧日志不回填非任务分类。

可在「模型与能力」同步上游价格目录（经 A 的代理，优先 models.dev，失败时尝试 models.opencode.ai）。以模型 ID、名称或厂商搜索，选择后按 USD 基准单价乘以倍率；费率可手动填写，也可改货币后输入折算倍率。再次同步只更新目录，按行「应用最新价」才会更新绑定的单价。保存 A 设置后立即重新估价。

`model_prices` 示例（以下为任选示例费率）：

```json
["troubleshooting=CNY:2:8:0.2", "review=USD:1.5:6:0.1"]
```

左侧用 AstrBot 的提供商 ID，右侧依次填货币名称、非缓存输入、输出、缓存命中输入的单价。只对已配置单价且返回用量的请求估价，不混加不同货币。缓存计数缺失时按非缓存输入估算。价格是当前设定的估算，变更会重新估算历史显示；实际费用以服务商账单为准。

单任务上限只累计返回的输入与输出 token，缓存命中的输入也计入上限。达到 80% 提醒一次，达到上限时等当前模型请求结算后暂停；因此单次请求可能使累计值超过上限。已提交的工具操作仍按原编号结算。管理员 `/mcairesume 任务名` 续接时再加一份配置额度，并在群里显示累计用量和新的上限。已验收的任务仍按原规则后台归档，归档请求计入用量。

### 上下文与群消息范围

上下文容量取自所选 AstrBot 提供商的 `max_context_tokens`；未设置或为 0 时沿用 272000 tokens。完整输入达到 75% 时尝试瘦身旧历史，达到 85% 或已超过预留输出后的输入额度时生成交接摘要。例如 472000 的两条水位分别是 354000 和 401200。系统提示、运行时规则和实际工具定义均计入；容量应按服务商实际支持值填写。`max_steps` 默认 40，限制一轮模型步骤。

每次模型请求前检查上下文。同一历史前缀优先复用 API 输入与输出用量，并估算新增消息；本地字符估算含加密推理载荷，实际分词以服务商为准。MCAI 只在任务私有提供商上关闭 runner 的自动截断。主模型使用 Responses 时默认发送 `prompt_cache_key=mcai:<任务编号>`；提供商已经配置该字段则沿用配置，明确拒绝字段时自动移除并重试。Chat 不自动加入缓存键。

软瘦身不调用模型。仅当旧历史可释放足够空间时，去掉已结算旧组的推理块和过期程序提醒，将大工具结果换成可回读引用，原内容保存在 SQLite。硬压缩使用同一排障提供商的独立无工具流式请求，网络操作超时为 300 秒；流持续返回数据时总时长可超过 300 秒。工具调用与全部返回作为一组，按 token 预算保留近期交互，最新用户消息、最近完整助手组和未结算组优先保留。空摘要、不完整响应、明确拒绝和不能缩减上下文的结果不进入检查点。

压缩期间收到的`/mcaisay`先持久保存，等待当前压缩完成。随后将摘要、保留原文（含最近完整交互）和新增补充一起检查预算，再发起下一次主模型请求。此规则同样适用于接口报上下文超限后触发的补救压缩；新增补充不会取消正在进行的压缩。

硬压缩的大工具输出先生成简短证据视图；服务商仍报上下文超限时，按完整组缩小本批再请求。首次生成五节交接摘要，后续用上一份摘要正文合并新增旧历史。检查点另带程序累计的管理员原话片段和证据索引，供续接查看；普通成员线索和附件仍是待核实资料。每批成功后原文和索引可用 `mc_context_history` 按 `entry/offset` 回读，后续失败保留已完成检查点和尚未处理的历史。受保护内容或单组无法容纳时明确暂停。验收整理使用自己的历史副本。

插件不拉取最近N条群历史。`/mcainew 任务名 问题描述`可直接创建；引用问题时，任务名后的可选文本作为创建者补充，与引用文本一起保存为初始问题。后续只有`/mcaisay 任务名 内容`进入任务反馈。两个入口都接收本条或引用中的[群文件和图片](operations.md#群文件和图片)，语音不解析。普通群聊、状态查询、批准命令和发出的执行进度汇报不作为新反馈。没有反馈条数、每分钟次数或补充文本长度的插件级硬上限，仍受QQ／适配器和模型容量约束。多条待处理反馈可合并成一次模型输入；反馈原文持久保留，上下文压缩不限制数据库的长期增长。

### 运行时规则

首次启用时，A 在 `AstrBot/data/plugin_data/astrbot_plugin_mcai/` 生成三份规则：

| 数据目录文件 | 包内模板 | 作用 |
|---|---|---|
| `AGENTS.md` | `mcai/agent_rules.md` | 执行模型：识别目标、使用工具、推进任务、核对结果和回复用户 |
| `REVIEW_AGENTS.md` | `mcai/review_rules.md` | 独立审核模型：检查实际动作、范围、证据、备份和验证 |
| `SUMMARY_AGENTS.md` | `mcai/summary_rules.md` | 整理模型：压缩历史、验收归档和保留事实来源 |

可以分别编辑。已有任务先暂停再修改，下一轮或续接时读取。执行或审核规则变化后，待批准方案须重新提案和审核；整理规则变化从下一次压缩或验收起生效。已提交的操作仍用原编号核对。

升级不会自动覆盖规则，即使文件从未改过。A 为首次生成的规则记录模板的 SHA-256、版本和时间。「MCAI 设置 → 运行时规则」显示每份文件的状态：**已是最新**表示记录的基线与打包模板一致，文件仍可包含自定义内容；**有新模板（用户未修改）**和**有新模板（用户已修改）**表示打包模板更新，并按文件是否仍与基线一致区分；**基线未知**说明旧安装没有基线记录，需要手工确认。

- **查看差异**：以纯文本显示当前文件与打包模板的差异。
- **采用新模板**：确认后先在同一目录生成 `AGENTS.bak-<时间戳>.md` 等备份，再覆盖规则并更新基线。
- **已人工合并**：在文件中手工合并并保存后再点击，只更新基线，保留文件内容。

查询使用 `mc_query.argv`，低频工具和专项流程通过 `mc_tools` 按需加载，见[工具分工](../design/agent.md#工具分工)和[查询用法](queries.md)。

## B：基础设置

从 `host.example.json` 复制为 `host.json`：

| 字段 | 默认值 | 用途 |
|---|---|---|
| `listen` | 缺省 `127.0.0.1`，示例 `0.0.0.0` | 监听地址 |
| `port` | `18765` | 本机端口，公网映射可用不同端口 |
| `tls` | `true` | 固定使用内置 HTTPS，不能关闭 |
| `token` | 必填 | 共享令牌，不能保留示例占位值 |
| `data_dir` | `runtime/host` | 状态、证书、输出、备份和下载 |
| `scheduled_backup_dir` | 空 | 定时备份的根目录，省略或留空（含纯空白）使用 `data_dir/backups`。可以填其他磁盘上的绝对路径，例如 `D:/MCAI/scheduled-backups`；须和实例目录分开。改路径不会移动旧备份或变更已批准计划。设置页单列另卷的当前定时备份目录占用；无法完整统计时，提示该目录需单独监控。不包含改路径后留在旧目录的备份 |
| `instances_file` | `instances.json` | 独立服务端文件，可热重载 |
| `powershell_path` | 空 | PowerShell 7 的完整路径，空时系统查找 |
| `world_tools.java_path` | 空 | 存档辅助程序 Java 21+，空时 PATH 查找 |
| `workspace_dir` | `data_dir/workspaces` | B端测试服任务工作目录 |
| `test_address` | 空 | 所有任务共用的、玩家可达的试服地址 |
| `test_port` | `null` | 所有任务共用的试服专用 TCP 端口（1–65535），与 `test_address` 成对填写 |
| `operations_memory_limit_mib` | `8192` | 全部辅助操作共用提交内存额度（MiB），不含服务端及托管窗口；至少64，重启B生效 |
| `incident_restart_window_seconds` | `120` | 所有已开启故障留证的正式服共用的启动失败统计窗口，填正整数秒 |
| `incident_capacity_mib` | `256` | B 的独立故障留证数据库上限，64–4096 MiB；超过时淘汰最早的整起故障 |
| `download_max_bytes` | `2147483648` | 单个下载上限，默认 2 GiB |

基础相对路径以 `host.json` 所在目录解析。PowerShell 必须是 **7.3+ 的 7.x**；中间层、固定启动器、在线诊断和修复脚本共用，缺失或版本不符明确失败，不回退 Windows PowerShell 5.1。路径可包含中文与空格。

图形界面可更新 PowerShell 和存档 Java。PowerShell 路径和辅助操作内存额度需重启 B；存档 Java 保存后供后续操作使用。监听地址、端口、令牌和证书仍在 B 本地配置。数据目录不要放入将要整体备份的实例范围。

在「B 主机」可保存 `scheduled_backup_dir`、`workspace_dir` 与正整数字节的 `download_max_bytes`（页面同时换算 MiB／GiB）。保存后立即生效；已登记的定时备份计划仍使用原根目录，已有备份不会搬迁。切换工作区前先结束已有隔离试服。试服窗口在线或正在运行时先停服并关闭窗口，再修改全局端口。主机页显示已保存配置和 B 的当前有效值。

「B 主机」还显示实际监听地址、协议和版本、数据路径、证书指纹、PowerShell 7、存档 Java 及两个辅助 JAR 的状态；「A 主机与连接」显示 A 的实际 PowerShell、共享内存额度及代理概况，代理账号和密码不回传。「模型与能力」支持打开检测详情、重测某项和从 A 经当前代理只读检查 Modrinth API。「群与通知」由已加载的主动消息平台、实例和允许群辅助填写，保存格式不变。

## B：服务端文件

从 `instances.example.json` 复制为 `instances.json`，或在设置视图增删：

```json
{
  "cti": {
    "description": "CTI 0.4.6，群里叫匠魂服",
    "directory": "D:/MC/CTI_0.4.6"
  },
  "zombie": {
    "description": "已故的工艺，群里叫僵尸服",
    "directory": "D:/MC/DeceasedCraft_Server_CB_5.11.18",
    "java_path": "D:/Java/jdk-17/bin/java.exe"
  }
}
```

`directory` 填写存在的服务端目录，托管窗口固定在其中使用 `./start.bat`。不接受 `command` 等旧字段，也不自动迁移。JSON 使用 `/` 或转义后的 `\\`；图形界面直接粘贴 Windows 路径。实例名使用字母、数字、下划线和短横线。

| 实例高级字段 | 默认值 | 用途 |
|---|---|---|
| `java_path` | 空 | 给实例和诊断设置 `JAVA_HOME`、PATH、`MCAI_JAVA`；空时继承 |
| `encoding` | `auto` | BAT 初始代码页，可填 `utf-8`、`gbk` 或 Windows `cp` 编号 |
| `stop_command` | `stop` | MC 正常停服命令 |
| `stop_timeout` | `120` | 等待正常停服的秒数，最多 3600 |
| `restart_prompt` | `Start server in 10 seconds. Press ctrl+c to stop right now.` | 退出后、自动重启前的完整提示 |
| `test_copy_paths` | 无 | 可选试服复制清单，填实际存在、相对于正式服根目录的启动和运行依赖；`start.bat` 始终复制 |
| `incident_watch` | `false` | 为此正式服开启主动故障留证 |

BAT 的自动重启循环保留。主动停服监听本次新输出，收到约定提示后只发一次 Ctrl+C，并处理批处理终止确认。正常退出、不循环的 BAT 同样可用。超时不会强杀，也不会继续文件修复。

自动编码按 BOM、有效 UTF-8、系统 ANSI 选择初始代码页，ConPTY 的 Unicode 输出直接保留。BAT 后续 `chcp` 由终端处理；日志查询编码独立设置。CMD 不支持的 UTF-16/32 BAT 明确拒绝，不改写原文件。

ASCII BAT在`auto`下采用系统ANSI代码页，但BAT编码不能证明Java／日志框架的输出编码。若控制台中文乱码而UTF-8日志正常，给对应实例显式设置`"encoding": "utf-8"`，正常停服、关闭并重开该实例托管窗口后再启动；已有窗口保持原配置。旧Java／GBK输出使用`gbk`，不要统一强制UTF-8。`mc_status`中的`encoding/initial_codepage`显示窗口配置和启动时的代码页（BAT自行chcp后的值可能不同）。

`java_path` 不覆盖 BAT 写死的绝对 Java 路径。希望配置生效可改用 `java` 或 `"%MCAI_JAVA%"`。存档辅助程序使用独立 Java 21，不改变服务端版本。

### 热重载

实例文件约每秒检查，也可 `mcai reload`。说明、试服复制清单、故障留证开关与健康告警设置立即生效；停服命令、超时和重启提示同步到在线窗口，窗口掉线或操作尚未结束时等重连或结算。只有目录、实例 Java 或编码的改动需要在停服后重开托管窗口，待生效字段会逐项显示。删除保留现有控制并阻止新绑定。旧 `instances.json` 的试服地址和端口会被忽略，保存服务端列表时移除，请在「B 主机」重新填写。错误配置保留上一份有效值，图形保存会核对文件版本。

主机页显示已保存值和运行值。刷新设置页保留已保存值，同时提示当前运行值；配置API的effective返回运行快照，restart_required标记待重启。A/B产品协议不匹配时在远程工作提交前报错，需配套更新插件、主机和托管窗口。

规范化绝对目录用于实例身份与经验归档，统一 Windows 大小写和分隔符。目录变化后旧任务的新操作明确停止，已提交操作仍按原编号查询。启动 BAT 或已审核脚本变化后需重新提案。

## 下载、代理与 HTTPS

Modrinth 公开 API 无需令牌。CurseForge 在A插件设置的高级项填写，密钥只保存在A配置中，仅返回已配置状态；支持替换、清空和官方只读接口测试。B不访问MCAI外网，密钥不提供给模型。分发受限或无官方下载地址时明确失败。

A工作区按任务目录保存源码、现场MOD、反编译结果和构建输出。`mc_workspace` 可读取文件、从 B 拉取实例文件、只读检查 JAR 条目／哈希差异与字节码（`jar_entries`、`jar_diff`、`javap`，其中 `javap` 使用 A 端配置的 `JAVA_HOME` 或 `PATH` 中的同目录 `javap.exe`）、暂存构建 JAR，并在审核和已批准方案的范围内执行 PowerShell 7.3+ 命令。命令使用 AstrBot 的 Windows 账号权限。试服地址和端口在 B 的 `host.json` 全局配置，实例只配置复制清单，流程见 [MOD 试玩与发布](operations.md#mod-试服试玩与正式发布)。

A 的网页获取、MOD API 与下载支持 `HTTP_PROXY`、`HTTPS_PROXY` 等环境变量；模型请求和独立搜索沿用 AstrBot 提供商代理。托管搜索的出站网络由服务商控制。

A 的 `mc_web` 和文件下载仅访问公网 HTTP／HTTPS 地址，禁止 URL 携带用户信息。初始地址和最多五次重定向的每一跳都检查；目标解析到本机、私网或其他非公网地址时直接报错。本机 HTTP 代理（如 `127.0.0.1:7890`）仍可使用，`NO_PROXY` 照常决定哪些请求直连。直连使用已检查的解析结果；走代理时，A 先在本地解析并检查目标，代理仍可能自行解析到不同的地址。请使用可信代理，并在代理侧限制对内网的访问。

B 首次开启 TLS 在 `data_dir/tls` 生成证书并持续复用。指纹支持大小写、冒号和空格分隔。本机 CLI 自动读取配置和证书，连接本机 HTTPS。公网 IP 变化只更新 A 的地址，证书未变则指纹不变。更多见[运行维护](operations.md)。

## 故障留证与通知

B 实例设置 `incident_watch: true` 后，B 可在 Java 意外退出、短时间内多次启动失败，或本次 JVM 的兼容 Probe 连续探测超时时保存故障证据。默认关闭；开启后 A 离线也能留证。

在 MCAI 设置的「主动留证」可改全局启动失败窗口、容量上限并查看当前用量。默认窗口为 120 秒，窗口内观测到 3 次未就绪退出才留证。留证库默认上限为 256 MiB，可设为 64–4096 MiB 的整数；达到上限时按先后顺序删除最早的整起故障，调低上限时立即回收。两项可在设置页在线保存并应用，留空恢复默认。若留证库暂时无法应用新容量，设置页区分已保存值与当前上限；处理页面提示的错误后可重新保存。直接编辑 `host.json` 则在 B 下次启动时加载。

事件会冻结并保存当时仍在托管窗口缓冲区里的控制台内容（最多 9,999 行、16 MiB，包括未换行输出）。Java 退出后，B 尝试复制能确认属于本轮的整份 `logs/latest.log` 和最多两份崩溃报告。BAT 自动重启应留出至少 10 秒；复制使用其中最多 8 秒，不延迟重启。连续启动失败的前两次先暂存，达到阈值才归档和通知。单份文件没有固定体积上限；来不及完整复制、无法确认归属或留证库放不下时会写明原因。主线程卡死但 Java 未退出时，沿用控制台和指标留证。

原文件不改动；复制时直接写为 gzip，不额外写一份未压缩的临时文件，与控制台一起计入 B 的 `data_dir/incidents.sqlite3` 容量。清理旧事件会一起删除附件，不影响其他数据库或备份。旧事件保留原有内容，不补造文件附件。

安装兼容 Probe 时，B 每 30 秒采集一份 10 秒指标，在内存保留最近五分钟。故障记录只附同一个旧 JVM 和 Probe 会话的成功样本：TPS、MSPT、实测最慢维度、玩家数、加载区块数和最后采集时间。没有匹配样本时标明缺失，正常运行不持续写入性能历史。

需要群通知时，在 A 插件设置填写 `incident_routes`，每行 `实例=平台ID:GroupMessage:群号`，例如 `cti=qq:GroupMessage:123456789`。平台 ID 是 AstrBot 的消息适配器**配置 ID**，群号须在 A 的允许范围内。只开启留证、不填通知路由时，证据留在 B 的留证数据库。群通知为简短提示，不附原始控制台，不自动创建任务或操作服务端。

主动告警共用这些路由，与 `incident_watch` 独立。可在设置页「群与通知」修改 B 失联告警分钟数；一次中断只通知一次，B 恢复后再通知一次。两条实例路由指向同一个群时，该群只收到一条 B 失联或恢复通知。未配置路由时不发群消息。

在设置页「服务端配置 → 高级选项」可为每个实例修改以下项目，也可直接编辑 `instances.json`，例如 `"alert_disk_gib": 20`。保存后可在实例运行期间生效。B 检查服务端目录盘、B 数据盘，以及当前 `scheduled_backup_dir` 所在的卷（与 B 数据盘不同时）。某盘暂时查不到时，仍检查其他盘；必须能读取所有受监控的盘才可判断恢复。每次定时备份还会在实际复制前检查目标空间。

新建服务端卡片时界面预设：停服超时 `180` 秒、主动保留故障现场开启、托管窗口掉线告警关闭（连续掉线 `3` 分钟）、磁盘空间告警关闭、Probe 性能告警关闭（瓶颈 MSPT 阈值 `66` 毫秒）。未在 `instances.json` 中显式填写的已有实例，后端仍沿用下列兼容性默认值：

| 字段 | 默认值 | 用途 |
|---|---|---|
| `alert_window` / `alert_window_minutes` | `true` / `3` | 窗口曾连上 B，之后连续掉线达到指定分钟数时告警；重新连接后通知恢复 |
| `alert_disk` / `alert_disk_gib` | `true` / `10` | 任一盘低于阈值持续 15 秒时告警；所有受监控的盘均达到阈值再加 1 GiB 时恢复。服务端目录盘或 B 数据盘不足时，告警附上 B 用量最大的三个类别 |
| `alert_performance` / `alert_mspt` / `alert_performance_minutes` | `false` / `50` / `3` | Probe 平均 MSPT（处理一个游戏刻的耗时）持续高于阈值时告警；有效样本回到阈值以内时恢复。未装支持此心跳指标的 Probe 时不检测 |

同一实例的同类告警 1 小时内最多发一次；已发告警的恢复消息不受这一小时限制。告警收到后，如需继续排查，可以按提示执行 `/mcainew 任务名 处理事件 <事件编号>`，AI 可以按编号读取事件。B 失联详情由 A 保存在本地，只能从收到该告警的群查询。磁盘告警中的统计若未扫完会标为「部分」；可到设置页「数据占用」查看详情。
