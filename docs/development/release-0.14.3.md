用户要求将已生成群消息的发送也限制为3次，并发版推main。本次A／B版本0.14.3，Probe0.4.1，通信仍为mcai-5，Probe协议仍为1。dev保留完整源码和验证历史，公开main仅从插件ZIP生成。

## 发送策略与最小修改

每条发件箱消息最多尝试3次，包含首次；两次重试分别等2／4秒。发送前持久化次数，失败保存错误和耗尽状态；耗尽后不再自动发送，不阻塞其他消息。重载保留剩余预算，长消息按分段分别计数。发件箱记录原位更新，保留rowid以维持失败分段的发送顺序。

进行中任务的模型API仍按已确认策略持续重试，第三次失败通知一次；群消息API和模型API的次数分别计算。经验归档保留原有限重试策略。

消融审查复用发件箱、数据库记录和交付协程，没有新队列、发送工具或配置。源码提交7f15fb8。运维和设计说明同步，版本发布修改另行提交。

## 验证

首轮任务交互与持续API重试组合28项通过、1项失败，定位到失败分段被替换写入移到队尾。改为发件箱原位更新后，任务交互及诊断导出6项全部通过、零跳过（32.28秒）：长答复分段顺序、第三次成功、第三次耗尽、重载保留次数及耗尽后不自动续发均通过。证据`runtime/message-delivery-three-attempts.*`、`runtime/message-delivery-final.*`。

独立解压插件、从B包离线构建wheel并安装到单独site，使用AstrBot v4.29.4原生runner和HTTPS测试。33项通过、零跳过（126.60秒），覆盖任务交互、持续重试、下载／审核安装／归档、CLI及Chat／Responses多轮方案。64个模块来源核对通过，A来自解压插件，B及worker来自独立安装目录；证据`runtime/release-0.14.3/installed.xml`及`import-proof.json`。

发行构建执行固定辅助工具校验和七目标Probe构建。原0.4.0候选与已发布0.14.2比对，发现尚未发布的模拟玩家清理和spark已有采样保护等修复，因此统一标为Probe0.4.1后重建；此次版本整理不改诊断逻辑，不将历史实服验证冒充0.4.1重新实测。现有双服实测与限制见上方链接。
