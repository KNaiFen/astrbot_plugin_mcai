# B端运维能力补齐与验证

[开发索引](README.md) · [工具设计](../design/agent.md)

以下记录0.9.0八类维护能力的实现与验证：精确文本修改、卡死恢复、JVM与系统取证、修复验证、本地组件清单、按对象批量NBT、区块救援与方块语义、文件检索与后台等待。沿用operation编号、原生runner、独立审核、一次管理员批准、停服备份和Jobs，不增加外部服务或自动重放。文中旧工具名称属于该版记录，0.11.0当前入口及对照见[工具设计](../design/agent.md)与[升级说明](../usage/configuration.md#运行时规则)。

## 精确文本与查询

- `patch_text`在副本内容中先完成全部唯一匹配，校验源哈希，保留BOM、编码和换行，再通过原原子替换路径提交。`mc_files preview_patch`返回差异但不写入。实际替换前复核哈希。
- `stat/tail/search`与原文件查询共用后台执行、分页和错误上报；`mc_job find`给出字符位置，`wait`沿原游标有界等待。SQLite访问留在B的原线程，文件产物检索才移到I/O线程。
- 2026-11-14，真实Windows HTTPS／worker／ConPTY链路：新增维护测试与原诊断、查询、修复边界共60项首次运行59通过，产物搜索1项因跨线程读取SQLite失败（185.84秒）；修复后新增文件5项全部复测通过（25.29秒）。覆盖UTF-8 BOM、UTF-16、GB18030和CRLF保留、预览不写入、停服备份／原窗口重启、过期与歧义补丁拒绝、同编号不重放、检索计数、末尾读取、有界等待及Unicode产物定位。不是整套回归结果。

## JVM证据与卡死恢复

- 增加固定只读`mc_diagnostics`，进程采样和jcmd子进程走原Jobs／辅助额度；强制停服是方案首步，按原会话和进程创建时间执行，先保存证据、结束重启链，再结束JVM，支持接同一方案的停服备份修复。独立托管PowerShell与无关进程保留，原控制编号持久去重。
- 在实际Oracle javapath环境发现java.exe包装进程，改为按父子关系选择叶子JVM，JVM工具取实际可执行文件同目录；独立的多个JVM仍要求明确目标。隔离Java程序不响应stop，验证连续线程采集、过期身份拒绝、正常停服超时、强制恢复后修复与重新启动，以及重放旧编号不会杀死新JVM。
- 工具参数扩展触及默认32768上下文预算；模型只接收去重后的联合参数说明，调用时继续使用原完整oneOf校验，预算按实际模型定义计算。未扩大默认容量或放松执行校验。
- 2026-11-14：首次恢复与原终端／重连／后台测试40项39通过，JVM查询因包装进程不能唯一识别而失败；修复后恢复2项通过（19.05秒）。扩大到原生AstrBot v4.29.4等43项40通过、3失败（119.64秒），暴露默认上下文预算和终端测试读空文件的时序。修复后关键5项通过、零跳过（50.85秒），含2项恢复、2项原生Agent完整流程和真实CLI交互。整组复跑的后台记录在42个完成标记后中断，无最终退出码，不计入通过。保留上游audioop弃用警告，未联调真实QQ或外部模型。

## 修复验证

- 增加共用只读验证实现和`mc_verify`，方案内`verify`与在线查询使用同一检查；支持JSON/TOML/YAML/NBT解析、文本与NBT断言、启动游标绑定的就绪／错误观察及本机TCP检查。补丁可先解析候选再替换，已通过结果保存在原operation，失败留现场。
- PyYAML列为B基础依赖；固定验证环境已锁定6.0.3。启动前记录最新行号，验证不重用旧READY；观察期间会话、Java身份和缓冲缺口明确失败。TCP检查不宣称玩家登录成功。
- 2026-11-14，Windows真实HTTPS／worker／ConPTY与AstrBot v4.29.4：维护、验证、原生完整流程及修复边界29项全部通过、零跳过（127.62秒）。覆盖三种配置解析、无效候选不替换、已修改NBT断言失败后保留现场、旧就绪消息拒绝、延迟FATAL、TCP及取消，保留上游audioop警告。未联调真实QQ、外部模型或生产MC。

## 本地组件清单

- `mc_inventory`从实际归档／目录解析组件，处理常见四类MOD声明、两类插件声明、数据包和嵌套JAR，输出依赖、来源、哈希与问题线索；原Jobs产物保存快照并比较先前同实例基线。确认不了的运行条件和版本语法明确标为未核实，不做自动依赖求解或生产安装。
- 实际JVM参数、JDK release和主JAR版本信息作为运行版本证据；没有进程时仍可检查磁盘声明。扫描和文件哈希可通过原后台取消结束所属worker，不结束MC。
- 2026-11-14，Windows真实HTTPS／worker／ConPTY、实际JDK与AstrBot v4.29.4共7项通过、零跳过（52.17秒）。覆盖嵌套Fabric、Forge Manifest版本替换与Maven区间、重复ID、必需依赖、仅客户端、实际Java版本不匹配、Paper/Bukkit元数据、目录数据包内容变化、清单新增／移除、损坏和未知归档，以及恢复与原生Agent回归。保留上游audioop警告；未在生产整合包执行全量清单，特殊版本约束保留未核实状态。

## 身份选择与批量NBT

- 复用原NBT／区域工具增加选择和批量预览，按三种UUID表示、方块实体位置、Slot或字段匹配对象。先解析全部目标和带类型旧值，拒绝重复／祖先重叠与歧义，再统一修改；列表删除不依赖变化后的下标。NBT数组从文件读取后可能只读，保留数组类型重建后替换，同时修复原单项数组写入路径。
- Java辅助程序增加同区域多区块读取与统一保存，复用原编解码和完整邻居检查，写后比较候选NBT，保持MCR、四种压缩及外部MCC的原处理。构建产物仍忽略，不提交生成JAR。
- 2026-11-14：新增批量、原诊断／修复、外部MCC恢复及原生全工具34项首轮33通过，数组只读1项失败（164.19秒）；修复后同组34项全部通过、零跳过（163.10秒）。覆盖在线查询后对象重排、多实体删除、旧UUID表示、Slot、字段新增、数组多删／单写、类型错误、过期旧值、重叠、歧义、跨区块同区域、负坐标、未知Long字段、备份恢复、四种压缩与MCR，以及实际审核→一次批准→批量修改→验证。保留上游audioop警告；未宣称跨文件原子性或生产大存档性能。

## 区块点恢复

- 原始记录按扇区检查并导出，保留压缩与外部MCC；来源归档哈希、规范目录和维度／坐标绑定后才可恢复。支持从已有备份提取，默认处理同位置region/entities/poi；损坏导出仅留现场。点恢复追加目标记录，保留其他原始扇区，绕过正常编辑器必须解码全部邻居的限制；候选先读回再替换。
- 区块移除作为独立批准动作，沿用停服、备份和一次批准。统一计算每步实际文件目标用于受审脚本检查和备份；逐文件持久化writing/written_files，部分失败保留现场，不增加重放机制。
- 2026-11-14，真实Windows HTTPS／worker／ConPTY、Java后端和AstrBot v4.29.4：区块恢复、批量NBT、原修复边界、外部MCC与原生全工具28项全部通过、零跳过（160.68秒）。覆盖坏邻居字节保留、三数据集关联、从备份导出、移除／恢复、旧指纹拒绝、归档变化拒绝、路径／坐标错配、坏归档保留不可恢复、重叠和短头报告、第二文件替换失败的进度与备份恢复、负坐标MCR／MCC，以及实际审核批准链。保留上游audioop警告，不承诺多关联文件事务或重建不足的区域头。

## 方块坐标与状态

- 现代光照／高度缓存失效后交服务端重建，标准旧Anvil使用固定MCA Selector高度图算法，扩展数字ID和非标准旧高度拒绝推测。模组缓存、计划刻与POI不能由注册名推断，继续按版本取证和验证；没有把通用脚本或存档库包装成游戏运行时。
- 首轮方块、区块救援、批量与原生全工具20项19通过，完整旧区块SNBT被接口提升为分页产物，测试误按短返回读取而失败（205.74秒）。修正读取后另一组17项16通过（162.44秒），暴露测试把透明旧方块ID200当作高度图阻光块；核对固定JAR映射后改为不透明ID159，并增加改回空气后的高度图验证。两次失败未掩盖或算作全绿。
- 2026-11-14，真实隔离原版MC 1.21.1经HTTPS／ConPTY启动、生成与保存区块，停服备份后修改指定方块，再启动通过MC命令确认新方块与相邻方块保持，随后保存并复核磁盘。第一次验证脚本误用分页控制台短返回，改查MC实际日志后完整重跑成功；现场和结果保留在忽略的`runtime/maintenance-real/`。不宣称其他MC版本或模组语义已真实服联调。

## 收尾回归与消融

- 区块恢复追加位置避开其他头项声明的扇区，即便邻居声明位于原EOF之外也不占用其范围；混合恢复与普通编辑保留原备份清单。组件清单基线按规范目录再次核对，只有未知归档时也标记partial，不能当作完整兼容结论。
- 首次整套回归发现循环BAT自动重启时，JVM身份枚举遇到已退出子进程使整个窗口被标为未知。保留原失败审计后终止该轮，不计为完整结果。新增ppid、name、create_time三个退出阶段的确定性回归，修复前3项失败、修复后3项通过；跳过本次快照中已退出的子进程，权限或连接错误仍明确失败，不增加修复自动重试。
- 修复后JVM恢复、循环BAT完整生命周期与方块场景23项通过、零跳过（130.83秒）；此前解压包回归94项中93通过，另1项因测试断言依赖pytest截短摘要而失败（370.06秒），已改用后台最终状态及error原文。整套及新包重新验证的最终结果另列，不沿用中途通过数。
- 后续单进程全量执行到托管搜索时，6种模式均被旧的“23个函数工具”固定数量断言拦住；单项重现确认后，改为按当前工具定义逐名和数量校验，不改产品行为。该轮终止并改为三个互斥文件批次完整重跑，未把中途输出算作全量通过。
- 更新B包构建wheel并安装到独立目标目录，从精简A包运行原生Agent、所有新增维护模块及循环BAT等107项全部通过、零跳过（384.57秒）。主进程和辅助worker使用已安装B模块，运行目录避开源码和精简A模块；再次通过已安装B验证真实MC 1.21.1的停服备份、方块编辑、重启命令确认及相邻方块保持。
