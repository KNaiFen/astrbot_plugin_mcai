# API持续重试与第三次失败通知

[开发索引](README.md) · [任务恢复设计](../design/storage-and-recovery.md#模型失败暂停与停止)

2026-11-17，从dev `fe94582`实施。此前双服实测中，排障API连续三次连接失败后任务暂停，需要管理员手动续接。本次将进行中任务的API错误改为持续重试，并保留管理员主动暂停／停止入口。

## 实际行为

- 覆盖排障、独立审核、上下文压缩、审核历史压缩和独立搜索。连接、超时、流中断、429／5xx，以及认证、额度、参数等API错误均持续重试。
- 每次失败后依次等待2、5、10、20、30秒，之后固定30秒；API请求本身的耗时另计。SDK自动重试继续关闭，单次实际请求仍由任务层统一控制。
- 同一次请求连续失败3次（包含首次）后，向原任务群提醒创建管理员一次，说明当前阶段、错误类别和“正在继续重试”，提供实际任务名的`/mcaipause`、`/mcaistop`。通知不依赖模型和进度转发开关，不发送原始异常正文。
- 请求成功结束该轮计数；反馈改变主请求或上下文材料缩减时开始新轮次。任务已有`model_retry`时，重载不插入改变输入的重启提示；保留轮次编号、失败次数、错误、下次重试时间和通知状态。
- 发件箱使用轮次编号及分段偏移作为稳定键，即使通知已经入箱、通知标记尚未保存，也不会因重载再次生成同一条通知。发送失败继续沿用原发件箱交付机制。
- 暂停／停止取消当前模型请求和退避，暂停保存进度、续接后重新尝试。MC已提交修复的安全步骤规则沿用原行为，不因API重试重新执行工具或服务端操作。

上下文容量错误仍优先缩减、压缩或拆批；无法缩减时明确返回原容量问题。审核deny是正常工具结果；无效审核协议最多3次。API成功后的校验及本地记录错误明确暂停，不无限重发成功请求。经验归档保留原有限重试与永久错误分类，不纳入本次持续重试。

删除`model_max_attempts`配置、设置表单和校验，不保留无效开关；有限协议校验及归档继续使用原默认3次。README、配置、运行维护及设计说明同步。

## 集成验证

Windows／Python3.12／AstrBot v4.29.4原生runner、真实群命令调度、HTTPS B和托管终端。模型HTTP或提供商响应受控；本次未联调外部计费API、真实QQ或重新启动GTNH／亡者世界。

| 场景 | 结果 |
|---|---|
| Chat／Responses连接、超时、401、400、429额度、503各连续失败7次后恢复 | 单次请求输入一致、实际请求8次、通知1条、成功后清除重试记录 |
| 审核请求卡住、30秒退避期间暂停／停止 | 四种组合均在2秒内退出，受审脚本没有执行 |
| 审核失败3次后重载 | 失败数及重试时间保留，通知1条，恢复后原脚本仅执行一次 |
| 主请求失败3次、通知已入箱但标记未保存后重载 | 轮次和输入保持，通知未重复，原工具仅调用一次 |
| 一次成功后再次连续失败 | 两个独立轮次各通知一次 |
| 两类压缩和独立搜索连续失败5次后成功 | 原输入不变，均自行继续，分别仅通知一次 |
| 本地用量记录、最终审核记录写入失败 | 明确暂停，成功审核API只请求一次，不执行受审操作 |
| 不完整响应、审核协议、容量恢复、say、归档隔离 | 保留原文、取消／合入正确，拒绝和容量结果不触发服务端操作 |

首次7项定向验证通过（26.06秒），随后19项新增集成通过（52.73秒）。扩大回归127项为121通过、6失败（410.29秒），零跳过。两项失败来自更新测试时缺少asyncio导入，已补齐。另四项在修改前`fe94582`独立源码副本重跑均同样失败（16.56秒）：

- checkpoint用例在恢复时调用阅读预算，触发system尚未绑定；原失败仍保留。
- 完整答复用例的两个参数分别缺少期待的final正文及response_messages；原失败仍保留。
- 容量用例仍断言paused，而已有实现会返回可恢复context_capacity并继续。修正该旧断言，同时继续验证操作未执行和请求材料不变。

最终专项33项中32项通过（92.45秒），另1项发现本地用量记录错误被交回为普通工具失败；已改为在API成功后的本地校验边界明确暂停。受影响本地错误、主请求重载、两类压缩／搜索及协议8项复核全部通过（27.03秒），零跳过；33个不同专项场景最终均验证通过。较大选择集中的3个基线失败用例未在本任务修复，不能宣称全仓测试全部通过。

证据位于忽略目录`runtime/continuous-retry-*.log`／`.xml`，包括initial、new、regression-final、baseline、final-verification及local-final。早期全量选择曾因零延迟夹具配合持续失败而无法让出事件循环，已中止；重试循环补充异步让出点，旧“三次自动暂停”断言改为持续失败后发送管理员暂停，并验证历史原文保留，随后重跑。实际生产间隔保持上述递增策略。

## 消融与交付

复用现有任务记录、发件箱、取消、工具编号、审核和容量恢复机制；只为可取消模型请求维护任务内协程引用。审核请求与本地校验分开，移除多余的内部转发函数和重复响应检查。没有新增数据库表、后台重试服务或配置开关。

静态检查、格式、Git空白及文档本地链接在提交前核对。保留全部运行证据；不推送、不发布、不修改生产环境。
