本轮开发态完成查询CLI、工具按需加载、帮助与示例整理，并通过OneBot测试群消息、AstrBot v4.29.4原生消息管道、真实模型API、A→B HTTPS、独立PowerShell／ConPTY与亡者世界、GTNH隔离实服验证。未连接实际QQ或生产服；未推送、部署或发布。

## 实现与验收结果

- 九类查询复用原契约与实现，经`mc_query.argv`调用：文件、日志、NBT、区域NBT、方块、区域检查／导出／扫描和进程／JVM诊断。安装CLI与AI入口共用解析器；参数数组不经过shell解释，继续使用venv。
- 模型工具由41个调整为34个，首次暴露15个基础工具，19个按需加载。`mc_tools`返回相关说明与示例，完整schema在下一次请求提供；加载集合和顺序随任务保存，新工具追加到已有定义之后。
- 查询原argv、解析后的语义、原操作编号与参数持久化，审核证据使用程序保存的查询名称与参数。帮助不产生远程操作；后台、产物、原操作及历史续读继续复用现有机制。
- 新模板将详细示例移到按需帮助，补齐NBT选择器、SNBT类型、坐标单位、日志事件、验证语义和多轮提案。更新保留用户运行时规则；程序提供当前接口目录与用法。

16个新版实服任务均已验收归档：两服×两类提供商×巡检／存档／维护共12个任务，再从独立安装的A/B完成4个相同只读巡检。另有4个改动前基线任务。16个新版任务逐一核对首轮工具集合、查询解析及远程参数、操作编号、控制台公告、审批次数和归档状态；两个NBT样本SHA-256保持一致，`9223372036854775806L`精确读取，维护文件最终值与保留行正确。

## 流程、恢复与错误验证

- 两服均完成真实文件、日志、进程／JVM、NBT选择与预览、区域NBT、单点方块、区域检查／导出及有界扫描。存档只读与预览没有改变样本；实际维护限定在专用测试文件，修改前停服和备份，启动后核实，再依实际结果发送第二批公告并结束方案。
- 两个Chat维护任务在加载提案／验证工具后暂停并重启A，续接后保留加载集合。GTNH的后期任务验证工具定义前缀不因加载改变；检查点及压缩后工具使用另由原生runner集成测试覆盖。
- GTNH Responses巡检期间重启B。原查询返回中断错误，模型按原操作编号核查后继续；保存原编号和请求参数摘要，没有把中断操作记为成功。两服托管窗口独立于B运行。
- 首次亡者世界Responses维护把`^phase=after$`用于整份多行文本，第一批文件修改和启动成功、文本检查失败。模型保留现场，补取准确原文后重新提案并取得一次新的批准，未重做原修改。帮助补充了字面量匹配和显式`(?m)`多行锚点；后续三组维护各一次批准完成两批。详细失败与审批次数见JSON。
- 回归暴露检查点恢复在system准备前计算结果预算，已将恢复放到提示准备之后；小schema下固定API开销导致读取预算过度缩小，改为复用现有基准比例与固定偏置校准，保留必要小字段完整读取。

本轮真实请求共190次：排障157、审核9、验收总结24，包含重试与重启后的归档请求。新版16个任务均完成归档。没有新增实服压缩压力轮或四服矩阵，未重新验证长期并发和跨主机网络。
