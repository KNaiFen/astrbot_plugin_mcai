## 验证与测量

验证环境从[固定依赖清单](dependencies.md)重建，Windows x64／Python3.12.14／PowerShell7，真实runner使用官方AstrBot v4.29.4；模型回复受测试控制。未调用生产QQ、外部模型或操作生产实例。

- 完整347项回归：346通过，1项旧serve测试仍拦截已替换的web.run_app而失败，耗时893.70秒，零跳过。修订到新入口后，CLI、serve和模型恢复相关22项复测全部通过（107.53秒）；本轮没有把整套运行表述成一次全绿。
- 此后新增1000个无关区域文件与备份世界共存场景，1项通过（4.08秒）；300轮上下文、原历史分页续读与300条验收反馈归档1项通过（9.30秒）。当前348项已定义场景均有本轮通过记录。
- 关键路径78项集成通过（105.56秒），包括真实HostRunner.cleanup的四个关闭时点及全部工具路径；后续serve测试修订和历史续读由上述复测覆盖。
- 解压B包构建wheel并安装，精简插件配合已安装B运行真实runner，51项通过（74.01秒），零跳过。确认B从独立site-packages导入，插件来自解压目录。固定依赖在空环境按哈希安装成功。
- 四目标Probe构建及本次JAR安装版真实服全部通过；Fabric1.20.1的真实HTTPS→独立ConPTY→Probe链路通过，包含重连去重、取消、停服备份修复、原窗口重启和B正常退出隔离。
- Ruff检查、格式、JS语法、Git空白检查、21份README／文档链接及两包的模块／许可／锁定清单／文档层级检查通过。上游audioop和jieba/pkg_resources警告保留；完整运行另外两条资源警告来自该旧测试在异步循环中调用同步入口，修订后的22项复测不再出现。

新增真实路径包括：备份目录身份、正常退出四个时点、同session原控制核对、窗口离线和B重启的配置快照、缓存Probe取消、三种阻塞I/O取消、大修复日志、受审启动器多步写入、保存配置刷新、协议不匹配前置拒绝、长任务压缩及续接、取消失败收尾和拒绝切换目标。

SQLite合成数据：各100000条已发送outbox和已完成operation，3次热查询中位数。全量outbox读取100000条为612.911ms；条件查询未发送项0条为0.011ms，活动operation 0条为0.008ms。同步执行期间事件循环同样被占用；条件查询的读取量取决于活动数。进程查询前后RSS约24.01→26.79MiB，仅为读取后的驻留量，没有测量峰值，也不代表生产CPU结论。

真实worker日志结果：1000条0.640秒、21次RPC／26次提交；10000条0.915秒、205次RPC／206次提交，结果条数和分页顺序完整。两次复用同一broker，每次创建独立worker；第一条包含broker冷启动，两次均含HTTPS轮询。原审查1000条2964ms为不同轮次的历史测量，不据此给出严格加速倍数。

四目标Probe重新构建并使用本次JAR安装测试通过，覆盖Forge／Fabric的1.20.1和1.21.1。实体空间查询优化在真实服漏结果后已撤回，保留原有实体遍历；没有把这个尝试纳入交付。十万级已加载对象、慢磁盘和大生产存档的tick分位数尚未测量，不给出新的性能保证。

## 消融审查与保留边界

复用现有SQLite、operation、终端session、Jobs、artifact和原生runner；没有增加服务、审批层级、自动重放或自动清理。执行上下文只提取两种环境共同需要的逻辑，HTTP和配置生命周期留在B。未引入实体空间索引或通用工作流框架。

上下文token是AstrBot估算值；模型未填写max_context_tokens时使用32768预算，实际部署应填写提供商容量。摘要仍需模型返回事实，原证据可用mc_job history查看。B进程被强制结束后的文件修复不续跑；新session无法证明旧控制结果时明确保留不确定。旧备份没有目录身份时不猜测关联。
