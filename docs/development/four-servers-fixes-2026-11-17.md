# 四服务端测试整改与验证

[开发索引](README.md) · [原始问题与实测范围](four-servers-e2e-2026-11-17.md) · [工具接口](../design/agent.md)

本轮根据四服报告修复F01—F04、处理O01—O07及spark采样副作用。基线为`fc8ee02`之后的本地dev源码；没有推送、发布或更新用户生产安装。原报告中的调用数、压缩数和失败保持历史含义，不作为修复后的统计。

## 完成标准

异常组件不终止整批清单，部分结果标记与实际一致；就绪检查不依赖完整MOD解析；原始GTNH实体字符串无损读取；中文日期能参与时间过滤。新工具参数在模型schema、执行入口、审核／提案与续读建议中一致，保留原操作编号和一次批准机制。错误正则在方案产生效果前拒绝；追问结算后等待用户，重启不额外追问。spark不得替换已有采样。验证后停止本轮隔离服务与测试进程。

## 逐项处理

| O05 | 审核混淆BAT自动重启与MCAI重放失败修复 | 执行及独立审核模板明确区分两者，保留原循环；新的修改、范围扩大和失败新方案仍走原审核与批准。未新增审批层级 |

O02、O05、O06、O07包含模型策略与规则改进，不能把规则改动等同于所有提供商、任意提示下的行为保证。已有用户规则不会被升级覆盖，合并方法见[配置说明](../usage/configuration.md#运行时规则)。

## 工具接口取舍

保留41个按对象分工的工具，没有增加通用工具或旧模型参数别名。查询分支用`mode`，修复步骤用`action`，检查类型用`kind`，保留三者各自语义。

| 含义 | 统一参数 |
|---|---|
| 文本／文件匹配 | `query`＋可选`regex`／`glob` |
| 上下文行数／事件游标 | `before_lines/after_lines`／`cursor` |
| 超时／采样时长／采样间隔 | `timeout_seconds`／`duration_seconds`／`interval_seconds` |
| 世界路径／基线清单 | `world_path`／`baseline_job_id` |
| Probe对象／磁盘实体类型 | `object_type`／`entity_type` |
| ready命中／禁止文本 | `query`／`forbid_query`，默认字面量 |

`offset`仍表示字符或列表偏移，`limit`事件分页上限100；现有`wait_seconds/window_seconds/stable_seconds`继续使用。错误给出具体字段路径和当前分支字段。B传输和操作记录保留原字段，转换不修改NBT键或正文；旧模型参数的未结算步骤不迁移，升级前完成或中止旧任务。

最小启动方案：

```json
{"summary":"启动并验证本次就绪","steps":[{"action":"start"},{"action":"verify","checks":[{"kind":"ready","query":"Done (","timeout_seconds":300}]}]}
```

## spark副作用修复

DeceasedCraft的spark1.10.53会在开始限时采样时停止原后台采样，超时导出不会恢复它。Probe现先调用`profiler info`；确认空闲才启动，已有前台或后台采样则明确返回占用。无法识别空闲时15秒失败，预检查取消及时释放引用；不尝试全局stop／cancel或事后恢复，以免影响管理员后续采样。

DeceasedCraft Forge1.20.1和Fabric1.21.1均完成两条真实路径：原后台采样存在时`preflight_complete=false/sampling_started=false`并返回保留说明，后续控制台确认仍在运行；测试控制器明确取消原采样后，空闲分支成功生成本地`.sparkprofile`。取消原采样是测试夹具动作，产品没有发送该命令。两服均沿原BAT、指定Java目录并加`nogui`启动，结束正常停服。

## 验证与证据

Python集成基线为AstrBot v4.29.4，使用真实原生runner、消息管线、HTTPS、独立托管终端与Java区域辅助程序；确定性模型／API夹具用于错误分支、恢复与参数契约。按各测试模块本轮最后一次结果去重汇总，19个模块共155个当前用例通过、0失败；不是把多轮重跑数量相加。

真实模型复测任务`84dc02c8d9d44a6aa99ebf47fea22cc6`从OneBot消息进入AstrBot，经模型、独立审核、一次批准、B与原BAT启动DeceasedCraft。13次工具调用、0次参数错误；首次审核要求补读Forge的`win_args.txt`，模型自行补齐后通过，没有再因原BAT循环拒绝。新参数`glob/before_lines/after_lines`完成最近一分钟ERROR检索，JVM堆概要查询成功，字面量`Done (`和当前主线程响应验证通过。模型给出独立完整的结果与验收请求，控制器补充检查确认服务端在线后停服。该有限实测没有重新覆盖四服全部能力或真实压缩阈值。

七目标Probe及Java辅助程序构建通过。两端ZIP完整性、新模块和整改文档收录、解压后的导入通过；从解压B包构建wheel、安装到独立目标目录后导入通过。首次禁止构建隔离的wheel尝试因本地缺少setuptools失败，改用标准构建隔离下载构建依赖后通过，没有修改产品依赖。检查后的文档本地链接无缺失，未留下本轮实服或控制进程。

全仓`ruff check`、本轮21个Python文件的`ruff format --check`与`git diff --check`通过。全仓format检查另发现基线中未改动的`scripts/test_probe_host.py:182`已有格式差异，核对HEAD同样失败，本轮按最小改动约束保留。

## 消融审查与保留边界

删除了最初Python侧的SNBT转义补丁，统一修正Java输出源头，避免维护两套解码逻辑；参数只保留一份名称映射，不增加动作适配框架、别名、审批或自动重试。复用既有后台任务、发件箱、工具检查点和操作编号，未改上游AstrBot源码。

GTNH扩展数字方块ID仍不支持block_set；本轮只补充工具预览与规则中的边界，不盲目放行。真实提供商的502、断流及TLS故障仍由原有限重试和原编号恢复机制处理，本轮没有重写网络恢复。长上下文验证不等于任意长度、任意服务商永久稳定，也不代表重新跑完上一轮四服全部能力矩阵。
