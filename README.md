# MC 群内排障助手

管理员在 QQ 群里提出 Minecraft Java 服务端的日常运维需求，或直接描述、引用玩家的问题创建排障任务。管理员在外面无法进入后台时，也可让 AI 查询状态、发送服内公告、管理白名单、调整配置或 MOD、启停服务端等；任务不要求先有故障。AI 核对目标和范围，涉及修改时提出具体方案，管理员批准后执行；文件修改前停服、备份，管理员验收后归档经验。

本文按第一次部署的顺序说明。已有环境可直接跳到[群内排障示例](#三在群里完成一次排障)。

[准备环境](#安装前准备) → [部署 B 与托管窗口](#一在-b-机器安装并连接服务端) → [配置 A 插件](#二在-a-机器安装并配置插件) → [群内排障](#三在群里完成一次排障) · [命令速查](#群命令速查) · [常见问题](#常见问题)

## 先分清 A、B 和服务端窗口

| 名称 | 放在哪里 | 你要做什么 |
|---|---|---|
| **A：AstrBot 插件** | 运行 QQ Bot 的 Windows 机器 | 安装插件、选择模型、填写 B 连接信息，在 QQ 群中使用指令 |
| **B：MC 控制程序** | 运行 MC 服务端的 Windows 机器 | 安装主机程序、登记服务端目录，保持控制程序运行 |
| **服务端托管窗口** | B 所在机器，每个 MC 服务端一个 | 运行 `mcai tm` 打开窗口，在里面执行原来的 `start.bat` |

连接方向是 **QQ群 ↔ A → HTTPS → B → 各服务端托管窗口**。A 主动连接 B，A 不需要公网入口。A、B 可以在同一台机器上；分开部署时，A 必须能访问 B 的地址和端口。

全文使用以下**示例路径**，请换成自己的实际目录：

| 示例 | 含义 |
|---|---|
| `D:\MCAI` | B 安装包解压目录，里面有 `pyproject.toml` 和 `host.example.json` |
| `D:\MC\CTI` | 已经可以正常启动的 MC 服务端目录，里面有 `start.bat`、配置和存档 |
| `cti` | 给这个服务端起的配置 ID，用于本机命令；群内创建任务时由 AI 选择服务端 |
| `主城卡顿` | 群内排障任务名，与配置 ID 分开 |

下面的 PowerShell 命令都在 **B 机器**执行；QQ群指令发在 **Bot 所在的允许群**。命令框里的路径、IP、令牌示例需要替换，输入时不带 PowerShell 提示符。

## 安装前准备

当前版本为 **0.20.5**，A、B 和托管窗口使用 `mcai-9`。见 [0.20.5 下载与校验和](https://github.com/KNaiFen/astrbot_plugin_mcai/releases/tag/v0.20.5)及[发布说明](docs/usage/releases.md)。已有部署请先看[升级步骤](#更新时保留什么)。

B 使用 `mcai_windows_host.zip`，其中附带可选的 Probe 0.5.0；A 使用 `astrbot_plugin_mcai.zip`。需要从源码安装时，见[构建说明](docs/development/README.md#构建与发行)。

### 软件与版本

| 位置 | 需要准备的环境 | 如何确认 |
|---|---|---|
| A | Windows 本机运行的 AstrBot，**最低 v4.29.4**；Python **3.12+** | 在 AstrBot 管理界面或启动日志查看版本；插件依赖安装到 AstrBot 自己使用的 Python 环境 |
| A | 已连接 QQ 的消息适配器，支持引用消息和主动发消息 | 先确认 Bot 能收到群消息，并能在该群回复；创建任务要能取得被引用消息的文字 |
| A | 支持 OpenAI 兼容 Chat／Responses 的排障模型与审核模型 API，排障模型须支持工具调用 | 在 AstrBot 模型页配置，之后用插件设置页测试；两者可使用同一提供商，但审核独立请求 |
| A | PowerShell **7.3+ 的 7.x** | 插件启动时检查 A 本机的 PowerShell；需能自动找到，或在 A 配置填写完整路径 |
| A（仅 MOD 源码修复） | 构建该 MOD 所需的 JDK | [试玩与发布](docs/usage/operations.md#mod-试服试玩与正式发布)使用 A 构建制品 |
| B | Windows **10 1809 或更新版本／Windows 11**，建议 x64；Python **3.12+** | 在 Windows“设置 → 系统 → 关于”查看版本和系统类型，再执行下方 Python 检查 |
| B | PowerShell **7.3+ 的 7.x** | 执行 `$PSVersionTable.PSVersion`；程序是 `pwsh.exe`，Windows 自带的 PowerShell 5.1 不符合要求 |
| B | 存档辅助工具使用的 Java **21+** 运行环境 | 执行所选 `java.exe -version`；安装发行包只需运行 JAR，无需自行编译 |
| 各 MC 服务端 | 原来能够正常启动的 **Minecraft Java 版服务端**、对应 Java 和 `start.bat` | Java 版本按该 MC／整合包要求，先人工启动并确认玩家可以进入 |

AstrBot 的安装版本声明为 `>=4.29.4`，不设最高版本。本项目目前的集成验证基线为 v4.29.4；使用更新版时，安装后先完成下文的连接与模型能力测试，再创建一次任务确认。后续版本的验证结果会另行记录。

A、B 可以共用一台 Windows 电脑，也可以分开。本文按 Windows 本机部署说明；B 的托管窗口依赖 Windows ConPTY，Linux、WSL 或 Linux Docker 容器不能运行该托管流程。A 的基础排障不需要 B 的 PowerShell、存档 Java 或服务端环境；B 不需要安装 AstrBot。若 A、B 同机，则在同一台机器准备两边的环境。

**两套 Java 要分开理解：**`host.json` 的 `world_tools.java_path` 指向 Java 21+，供存档辅助工具使用；MC 仍使用原 `start.bat` 或实例配置指定的 Java。例如原整合包要求 Java 17，就保留它，同时另装 Java 21 给存档工具。配置时分别写完整路径，多套 Java 可以共存。

### 内存、磁盘与运行账号

- **内存：**按“MC 最大堆内存 + Windows／AstrBot 等程序 + 辅助操作余量”安排。B 默认让全部辅助操作共享最多 **8 GiB**，这是按需使用的上限，不是预先占用，也不是整台机器的最低内存。MC 的内存独立计算；整机余量不足时，先下调 `operations_memory_limit_mib`，大范围扫描也要相应缩小。
- **磁盘：**除现有服务端和安装文件外，B 的数据目录需要容纳下载暂存、操作记录，以及每次修复中待修改文件／目录的完整备份。若方案涉及整个存档目录，就预留至少该目录一份副本的空间；多次操作的备份会累积，维护方法见[数据与备份](docs/usage/operations.md#数据与备份)。
- **账号与权限：**运行 B 的 Windows 账号需要读写服务端目录、B 配置和数据目录，并能够启动所需 Java、PowerShell 与辅助进程。B 与各托管窗口使用同一 Windows 用户。A 的运行账号需要能写 AstrBot 插件数据目录。
- **模型算力：**使用远程模型 API 时，A、B 无需为了本插件额外准备显卡。若自己在本机部署模型，其显存和内存另按模型服务要求准备；模型 API 通常按服务商规则计费。

### 网络条件

| 从哪里访问 | 必须能访问什么 | 什么时候使用 |
|---|---|---|
| A → QQ 适配器／平台、模型服务 | 正常的消息连接和已配置的模型 API | 收发群消息、排障和独立审核 |
| A → B | B 的 HTTPS 地址和 TCP 端口，默认 `18765` | 控制程序和查询结果；跨网络时要配置可达地址与端口映射 |
| A、B → Python 包源 | 安装所需依赖的包源或可用镜像 | 首次安装和更新依赖 |
| A → 网页／独立搜索 API | 所查询的网页或已配置的搜索服务 | 启用相应查询功能时 |
| A → Modrinth／CurseForge 及文件下载站 | 对应 API 和下载地址 | 搜索或下载 MOD 时；CurseForge API Key 填在 A 插件设置 |

同机部署时 A 使用本机地址即可，不需要为了 A→B 连接配置公网入口；异机地址的具体填法见后面的[连接地址表](#5-启动-b保存连接信息)。模型托管搜索由模型服务商访问网络。需要代理时，A 的模型代理、A 的网页与下载代理分别按[代理说明](docs/usage/configuration.md#下载代理与-https)配置。

### 安装并检查基础软件

可从 [Python Windows 下载页](https://www.python.org/downloads/windows/)、[PowerShell Windows 安装说明](https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-windows)、[Temurin Java 下载页](https://adoptium.net/temurin/releases/?version=21)准备环境。

在开始菜单打开 **PowerShell 7**，执行：

```powershell
$PSVersionTable.PSVersion
py -3.12 --version
& 'C:\Program Files\Java\jdk-21\bin\java.exe' -version
```

应分别看到 PowerShell 7.3 或更高的 7.x、Python 3.12 和 Java 21 或更高版本。Java 路径按实际安装位置修改。本文用 Python 3.12 演示安装；如果已经使用更高版本，将后文的 `py -3.12` 统一换成对应版本，例如 `py -3.13`。若提示找不到 `py` 或指定版本，安装 Python 时确认包含 Python 启动器，或用已安装的 `python.exe` 完整路径代替 `py -3.12`。

A 的 Python 与 B 的 `.venv` 是各自的运行环境；在 B 安装依赖不会替 A 安装插件依赖。先完成上述检查，再继续解压和配置。

## 一、在 B 机器安装并连接服务端

### 1. 解压并安装主机程序

将 `mcai_windows_host.zip` 解压到例如 `D:\MCAI`。确认 `D:\MCAI\pyproject.toml` 存在；如果 ZIP 被额外套了一层文件夹，进入实际包含该文件的目录。

打开 PowerShell 7，依次执行：

```powershell
Set-Location -LiteralPath 'D:\MCAI'
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
Copy-Item -LiteralPath '.\host.example.json' -Destination '.\host.json'
Copy-Item -LiteralPath '.\instances.example.json' -Destination '.\instances.json'
```

前两条安装命令分别创建 Python 环境和安装 B。安装成功后，`D:\MCAI\.venv\Scripts\` 中应有 `python.exe` 和 `mcai.exe`。后两条只在**首次安装**时复制配置模板；升级时保留已经填写的配置。

后文直接使用完整路径或 `.venv` 内的程序，不需要激活环境，也不要求把 `mcai` 加入 PATH。

文件、日志、存档和JVM查询可使用[查询命令与按需帮助](docs/usage/queries.md)；群内仍直接描述目标，由AI选择查询和必要工具。

### 2. 填写 B 的基础配置

用记事本打开 `D:\MCAI\host.json`。可在刚才的窗口执行：

```powershell
notepad .\host.json
```

按实际情况修改，例如：

```json
{
  "listen": "0.0.0.0",
  "port": 18765,
  "tls": true,
  "token": "这里换成你自己生成的一串令牌",
  "data_dir": "runtime/host",
  "instances_file": "instances.json",
  "powershell_path": "C:/Program Files/PowerShell/7/pwsh.exe",
  "world_tools": {
    "java_path": "C:/Program Files/Java/jdk-21/bin/java.exe"
  },
  "operations_memory_limit_mib": 8192
}
```

| 字段 | 第一次应该怎样填 |
|---|---|
| `listen` | 使用示例的 `0.0.0.0`，让 B 接受本机及其他机器的连接 |
| `port` | 默认 `18765`，是 A 连接 B 的端口，与 MC 游戏端口分开 |
| `token` | 自己生成一串令牌，稍后原样填到 A 的“共享令牌”；它与模型 API Key 分开 |
| `powershell_path` | PowerShell 7 的 `pwsh.exe` 完整路径；留空时自动查找 |
| `world_tools.java_path` | Java 21+ 的 `java.exe` 完整路径；供存档工具使用 |
| `data_dir` | 可保留示例；备份、证书、操作记录保存在这里，不要放进 MC 存档目录 |
| `operations_memory_limit_mib` | 默认 `8192` MiB，即全部辅助操作共享 8 GiB，MC 服务端不计入该额度 |

需要生成令牌时，在 B 安装目录执行下面这条命令，把输出保存到 `token`：

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
```

JSON 路径推荐写 `/`；如果写反斜杠，需要写成 `D:\\MC\\CTI`。字段之间要有逗号，最后一项后面没有逗号，文件内不要添加注释。保存为 `host.json`，注意记事本不要另存成 `host.json.txt`。

### 3. 登记 MC 服务端

用记事本打开 `D:\MCAI\instances.json`，将示例目录换成自己的真实服务端目录：

```json
{
  "cti": {
    "directory": "D:/MC/CTI",
    "description": "CTI整合包服，群里也叫CTI服、匠魂服，主城在主世界"
  }
}
```

- `cti` 是配置 ID，只用字母、数字、下划线或短横线；本机 `status`、`stop` 等命令会使用它。
- `directory` 指向包含 **`start.bat`** 的服务端根目录，不是 `world`、`mods` 或 B 安装目录。
- `description` 给 AI 识别目标使用，填写整合包名、群内简称等真实信息。不同服务端要能区分。

有多个服务端时，在同一个 JSON 对象中增加配置项，每个配置指向不同目录；具体示例见[服务端配置](docs/usage/configuration.md#b服务端文件)。后续也能在 A 设置页添加，不需要提前填完所有服务端。

### 4. 核对原来的 start.bat

先确认这台 MC 服务端原本能正常运行。继续使用原有启动参数和对应 Java，保留整合包所需脚本与自动重启循环。

若 BAT 有自动重启循环，在 **Java 退出之后、下一次启动之前**输出下面这行提示，并保留倒计时。下方是插入现有 BAT 的片段：

```bat
echo Start server in 10 seconds. Press ctrl+c to stop right now.
timeout /t 10 /nobreak
```

提示让托管窗口知道“本次 Java 已退出，可以中断自动重启”。Java 应在 BAT 中前台运行；不要用 `start` 把 Java 另开到脱离当前窗口的进程。原本没有循环、Java 结束后就退出的 BAT 可以继续使用。

主动停服由托管窗口处理：先发 MC 的 `stop`，等待这次退出提示，再发一次 Ctrl+C，必要时确认终止批处理，最后保留 PowerShell。超时没有确认停服时，文件修复不会继续。详细配置见[停服与启动参数](docs/usage/configuration.md#b服务端文件)。

### 5. 启动 B，保存连接信息

回到 B 的 PowerShell 7 窗口：

```powershell
Set-Location -LiteralPath 'D:\MCAI'
.\.venv\Scripts\python.exe -m mcai host
```

启动后当前窗口标题会变为 `MCAI-HOST`（退出时恢复原标题）；首次启动会生成证书，并显示类似：

```text
HTTPS 监听：0.0.0.0:18765
证书 SHA-256 指纹：一串64位十六进制字符
```

看到这两行且没有后续启动报错，窗口持续运行，说明可以继续连接检查。**这个窗口保持打开，专门运行 B。** 将证书指纹复制保存，稍后填写到 A；B 的连接地址、`token` 和指纹是三项不同信息。B 的配置界面位于 A 插件内，不需要在浏览器打开这个 HTTPS 地址找管理网页。

根据 A 和 B 的位置选择地址：

| 部署方式 | A 的“B 地址”示例 | 网络上需要做什么 |
|---|---|---|
| 同一台 Windows 机器 | `https://127.0.0.1:18765` | 使用本机地址，仍填写指纹 |
| 同一个局域网 | `https://192.168.1.20:18765` | 换成 B 的局域网 IP，让 B 防火墙允许该 TCP 端口 |
| 不同网络，通过公网连接 | `https://你的公网IP:28765` | 例如将外部 TCP `28765` 映射到 B 的 TCP `18765`，A 填外部端口 |

`0.0.0.0` 是 B 的监听设置，A 地址填写实际可访问的 IP 或域名。公网映射填写 B 的端口；只开放 MC 游戏端口 `25565` 不能让 A 连上 B。使用云主机时，还要在云平台的入站规则中允许所选 B 端口。详细网络选项见[HTTPS 配置](docs/usage/configuration.md#下载代理与-https)。

### 6. 为每个服务端打开独立托管窗口

在 B 机器**再开一个 PowerShell 7 窗口**，与 B 使用同一 Windows 用户，执行：

```powershell
& 'D:\MCAI\.venv\Scripts\mcai.exe' tm -C 'D:\MC\CTI'
```

这里使用完整路径，即使系统提示“找不到 mcai 命令”也能运行。`-C` 后面是刚登记的服务端目录。

当前窗口标题会变为 `MCAI - cti`，清空原屏幕与滚动历史，并从第一行显示：

```text
MCAI 托管窗口：cti · D:\MC\CTI
请执行 .\start.bat；关闭窗口只影响本实例。
PS D:\MC\CTI>
```

等待托管 PowerShell 的输入提示符出现，再在**这个窗口里面**执行：

```powershell
.\start.bat
```

等待 MC 原本的启动完成提示，确认玩家可以正常进入。这时该窗口就是这台 MC 的交互控制台；第二个服务端另开一个窗口，换成它的目录。

如果 MC 已经在原来的普通窗口里运行，先正常停服，再按上述方式从托管窗口启动。创建 `tm` 窗口不会接管已经在其他窗口运行的进程。

还没有登记的目录会提示输入项目 ID 和介绍，并由 B 保存；首次登记需要 B 在线。已经登记的目录在 B 暂时离线时也能打开，窗口会持续重连。只运行 `tm` 会打开托管环境，MC 是否启动取决于里面是否执行了 `start.bat`。

**窗口关系：**B 退出或重启时，托管窗口和 MC 继续运行；关闭某个托管窗口会影响该服务端。需要日常查看时保留这些窗口，不要通过关闭窗口来代替正常停服。

### 7. 在本机检查一次

再开一个用于检查的 PowerShell 7，执行：

```powershell
Set-Location -LiteralPath 'D:\MCAI'
.\.venv\Scripts\mcai.exe list
.\.venv\Scripts\mcai.exe status cti
```

`list` 应包含 `cti`，`status` 中主要看：

| 字段 | 正常情况下的含义 |
|---|---|
| `window_online: true` | 托管窗口已连到 B |
| `running: true` | 已识别正在运行的 BAT 启动链；最终就绪仍以 MC 日志和玩家进入为准 |
| `state_unknown: false` | 当前状态能明确判断 |

若托管窗口已打开但 MC 还没启动，`running: false` 可以是正常状态。若 `window_online: false`，先核对 B、托管窗口和它们使用的配置，再配置 A。

## 二、在 A 机器安装并配置插件

### 1. 安装插件并找到设置页

在 AstrBot **插件管理页**使用 ZIP 安装入口，选择配套的 `astrbot_plugin_mcai.zip`，等待安装依赖并启用插件。找到显示名称为 **“MC 排障助手”**、插件标识为 `astrbot_plugin_mcai` 的插件，打开其**设置视图**，页面标题为“MCAI 设置”。

也可以通过仓库地址安装：[插件仓库](https://github.com/KNaiFen/astrbot_plugin_mcai)。安装时为 A、B 与托管窗口选用同一版本：0.20.x 与 0.19.x 使用 `mcai-9`，0.18.0 使用 `mcai-8`。部署步骤见[安装前准备](#安装前准备)。

若安装依赖时出现 `WinError 5`，并指向 `charset_normalizer` 或 `__mypyc*.pyd`，完全退出 AstrBot 后，按[安装依赖时拒绝访问](docs/usage/operations.md#安装依赖时拒绝访问)预装依赖，再启动 AstrBot 重试安装。

### 2. 填写并测试 B 连接

在“**主机连接**”区填写：

| 界面字段 | 对应内容 |
|---|---|
| B 地址 | 前面选定的完整 `https://IP或域名:端口`，例如同机 `https://127.0.0.1:18765` |
| 共享令牌 | B 的 `host.json` 中 `token` 的值，不包括 JSON 引号 |
| 证书 SHA-256 指纹 | B 启动时显示的指纹；可包含冒号或空格，不填写整段提示文字 |

点击“**测试连接**”。出现“连接成功，B 配置了 N 个服务端”后，点击“**保存 A 设置**”。连接测试证明 A 能访问 B；服务端是否已启动，要看“服务端”区和 B 的窗口。

连接失败时先按文末[常见问题](#常见问题)处理。B 地址使用 `https://`，填写最终地址，避免使用需要跳转的网页地址。

### 3. 选择排障模型与审核模型

先在 **AstrBot 的模型提供商页**填好 API 地址、API Key 和模型名称。回到“MCAI 设置”的“**模型与能力**”区：

1. 在“排障模型”中选择已配置的 OpenAI 兼容 Chat／Responses 提供商；首次建议明确选择，方便一键测试。AstrBot 原生 Gemini 等其他适配器暂不支持完整工具结构，会明确拒绝。
2. 在“审核模型”中选择一个 OpenAI 兼容 Chat／Responses 提供商。审核模型必须设置，可以与排障模型使用同一个提供商，但审核会独立请求。
3. 思考强度不确定时先留空，继承提供商设置；只填写该模型支持的值。
4. 在 AstrBot 提供商设置中按模型实际容量配置 `max_context_tokens`。插件按这个值控制历史输入，未配置或为 0 时按 272000 tokens 估算，长任务会压缩已结算历史。详细行为见[上下文与群消息范围](docs/usage/configuration.md#上下文与群消息范围)。
5. 点击“**保存并测试、自动配置**”，等待结果区结束，查看“普通对话”“工具调用与续接”“图片识别”“审核模型与 JSON”等结果。

能力测试只发测试模型／搜索请求，会产生少量 API 费用；不会操作 MC，也不会发送群消息。普通对话、工具调用或审核失败时，先核对对应提供商的错误。搜索和执行进度汇报是可选能力：服务商不支持时可关闭对应开关，未观察到汇报也不等于排障功能不可用。执行进度汇报默认关闭，开启后转发中文的工具前说明与工作进展，不按固定时间通知。API 托管搜索和 `alpha/search` 独立搜索的区别见[模型与搜索说明](docs/usage/configuration.md#模型搜索与能力测试)。

### 4. 配置管理员和允许群

在“**群与通知**”区：

- “管理员 QQ”每行填一个可以创建、批准、暂停和结束任务的 QQ 号。AstrBot 自身识别的管理员也可管理任务。
- “允许群号”每行填一个使用本插件的 QQ 群号；留空允许所有群。
- 点击“**保存 A 设置**”。多个管理员权限相同，可以接续处理同一个任务。

再到“**服务端配置**”页点击“**刷新 B 配置**”，应能看到 `cti` 和填写的说明。需要新增实例时，点击“添加服务端”，填写配置名、说明和 **B 机器上的目录**，再点击“保存服务端列表”；新实例仍需在 B 手工打开独立托管窗口。

界面显示“无托管连接”时，回 B 检查 `tm`。目录、实例 Java 或编码变更需停服并重开托管窗口；停服参数会在窗口重连或当前操作结束后继续同步。B 主机的 PowerShell 路径和辅助内存额度需重启 B，存档 Java 保存后供后续操作使用。

最后到允许群发送 `/mcaihelp`，应收到命令帮助。本文指令按 AstrBot 默认唤醒前缀 `/` 书写；若改过前缀，使用对应前缀，例如 `!mcaihelp`，也可 @Bot 后输入 `mcaihelp`。若没有回复，先确认 Bot 收得到该群消息、唤醒前缀和群号填写正确，且插件已启用。

## 三、在群里完成一次排障

日常查询可以先发 `/mcaiserver` 列出实例，再发 `/mcaiserver cti` 查看指定实例。状态查询不调用模型；装有 Probe 时可查看在线玩家和近期 TPS／MSPT。想进一步了解原因，可用 `/mcaiask cti服为什么 TPS 降低了？`。问题中没有足够信息判断要查询哪个服务端时，会回复不知道是哪个服务端、不回答该问题。问答默认仅管理员可用，并对所有问答屏蔽或脱敏玩家 IP、密钥和宿主机用户路径等现实隐私（游戏内坐标与实体信息照常回答）。两条命令都不建任务、不占用实例；需要修改时，可引用问答回复，再发 `/mcainew 主城卡顿` 开始排障。

以下以任务名“主城卡顿”、目标为 CTI 服为例。任务名由你取，**不带空格，最多 40 字**；同一群内不要重复使用正在进行中的任务名。

### 1. 描述问题，或回复玩家的问题创建任务

直接发送任务名和问题描述即可；也可以在 QQ 中回复玩家的问题消息，再填写可选补充：

```text
/mcainew 主城卡顿 是CTI服，昨天更新模组后开始卡，玩家Steve在主城附近复现
```

创建需要管理员权限。`主城卡顿` 是任务名，后面的文本在没有引用时就是问题描述；有引用时作为创建者补充，与引用原文一起进入首次排查。只输入 `/mcainew 主城卡顿` 时，需要引用一条有文字的问题消息。

`/mcainew` 和 `/mcaisay` 都将任务名后的整段文字作为内容，支持空格、换行和空行，无需加引号；任务名仍不带空格。任务名与内容可用空格或换行分隔。

日常运维也用同一入口，例如 `/mcainew 维护公告 给CTI服发送公告：今晚22点维护，请提前下线`。明确的操作只核对必要的目标、状态和范围，再按原有审核／批准流程执行，无需先提供故障或复现信息。

Bot 应回复“开始排查”，并附上群成员补充命令 `/mcaisay 主城卡顿 内容` 和进度查询命令 `/mcaistatus 主城卡顿`。AI根据实例说明、引用和补充选择服务端；不明确时会追问。一个任务只处理一个服务端，同一服务端只允许一个活动任务，已暂停的任务继续占用它。其他服的问题请另建任务。

### 2. 回答追问、补充线索

普通玩家也可以补充，消息里带上任务名：

```text
/mcaisay 主城卡顿 我的游戏名是 Steve，主世界坐标 120 65 -300
大约 20:10 开始卡
更新模组后第一次出现
```

有价值的信息包括：哪台服、游戏名、时间、维度、坐标、怎样复现、最近改过什么，以及已经人工做过的处理。也可以引用玩家发的日志、崩溃报告或截图，再发 `/mcaisay 主城卡顿 看这个`；创建时也可直接附上或引用附件。文件单个最多 20 MiB，支持 `.txt .log .gz .zip .json .toml .cfg .properties`；压缩包最多解出 100 MiB、200 个文件，不解嵌套压缩包。图片单张最多 10 MiB，排障模型识别后把文字交给任务；模型不支持时请把关键内容写成文字。语音暂不解析。详见[群文件和图片](docs/usage/operations.md#群文件和图片)。

普通成员的补充会注明“内容不完全可信，仅作排障线索”，管理员补充则按插件识别的身份标注。停服、删改 MOD、删改数据或改变任务目标等要求须由管理员提出或确认，具体修改仍需审核和批准。Agent 只处理当前 MC 服务端任务，禁止格式化磁盘、重启或关闭宿主机、删除无关文件等破坏性操作，管理员也不能扩大这一范围。

有人捣乱时，管理员可暂停该任务的普通成员补充，再按需开启：

```text
/mcaisaymode 主城卡顿 false
/mcaisaymode 主城卡顿 true
```

`false` 暂停接收、`true` 开启接收，管理员始终可用 `/mcaisay` 补充。开关只影响指定任务，重启插件后保留，新任务默认开启；`/mcaistatus` 会显示当前模式和切换命令。被拒收的消息会明确提示，既不保存也不打断模型或使方案失效；先前已接收的补充保留。切换接收模式不会暂停或续接任务。

模型仍在生成时收到被接收的补充，会取消尚未完成的生成，带上已保存上下文和新消息重新请求；已提交的工具操作先沿原编号结算。AI提问后等待反馈时，`/mcaisay`直接开启下一轮。若状态明确显示“已暂停”，被接收的补充会保存并提示管理员用`/mcairesume`续接。

**普通群聊不会自动进入任务。**后续补充使用 `/mcaisay`；插件也不会自动翻最近 N 条群历史。查看当前进度：

```text
/mcaistatus 主城卡顿
/mcailist
```

`/mcaistatus` 也显示任务的模型请求数、审核请求数和输入／输出 token。最近 30 天总量、非任务用量和任务明细见「MCAI 设置 → 模型与能力 → 模型用量与费用保护」；这里也可[同步价格、设置单价与单任务上限](docs/usage/configuration.md#模型用量与费用保护)。

AI可查看日志、文件、存档和在线指标；诊断脚本与发送到控制台的诊断命令会经过独立 AI 审核。排障在后台继续，需要补充信息、批准方案或报告关键结论时，Bot 会主动发到原群，不必再次发送命令才能收到消息；回答追问仍用 `/mcaisay 任务名 内容`。完整结果保存在本地，没有逐条播报工具进度是正常的。

开启[主动留证](docs/usage/configuration.md#故障留证与通知)后，服务器重启了也能让 MCAI 查刚才崩溃时的控制台和可取得的性能记录。遇到「跑新图就卡」，可以请 MCAI [做一次区块录制](docs/usage/operations.md#文件存档与故障取证)，需要配合复现时可要求开录提醒。

设置[故障通知群](docs/usage/configuration.md#故障留证与通知)后，也会收到 B 失联、托管窗口掉线、磁盘空间不足及其恢复通知。装有支持心跳指标的 Probe 时，还可按实例开启性能告警。需要排查时，按通知里的事件编号建任务。

使用 QQ OneBot v11 且接入端支持群合并转发时，插件默认把超过 400 字符的单条回复发成一张合集卡片，点开可读完整正文。原消息需要 @ 成员时，卡片之后单独 @ 一次。门槛可在“MCAI 设置 → 群与通知 → QQ 长回复合集门槛”修改，点击“保存 A 设置”生效。

### 3. 查看方案，再决定是否批准

AI有修复方向时，会发简短方案并提示批准。如果需要重新查看：

```text
/mcaiplan 主城卡顿
```

确认操作对象、修改内容和预期影响后，由管理员复制方案通知中的批准命令。以下以短码 `9F2A7C` 为例，实际使用当前方案显示的短码：

```text
/mcaiapply 主城卡顿 9F2A7C
```

这条命令只批准**短码对应的当前待批准方案**。缺少短码或短码已失效时不会执行，回复会附上完整的当前方案，末尾给出批准命令。请先核对方案再批准，也可用 `/mcaiplan 主城卡顿` 主动查看。文件修复会先结束该任务所属诊断、停服、备份，然后修改；成功后原先运行的服务端通常会重新启动，方案中明确的启停步骤优先。在线命令可能没有可恢复备份，确认消息会说明，由这一次批准一并确认。

支持根据结果分批维护：方案会说明允许范围和完成条件。批准一次后，AI执行一批、读取效果，再决定下一批；范围内的具体操作每批仍经过独立审核，无需重复批准。用 `/mcaiplan 任务名` 查看已批准方案和状态。普通线索补充保留原批准；改变目标、扩大范围或失败后提出新的修复方案，需要重新批准。达到完成条件后AI停止后续操作并请求验收。

如果暂时不同意，先不要批准，用 `/mcaisay` 说明需要调整的地方。新反馈会使尚未执行的方案失效，由 AI 重新判断；新方案仍需再次批准。MOD 由 A 下载，提交安装方案时传给 B 暂存并校验，批准后才安装；CurseForge 凭据在 A 插件设置的“下载与主机”区填写，Modrinth 公开下载无需令牌。

### 4. 验证效果，再验收

修复后先让玩家按原步骤复现，补充实际结果：

```text
/mcaisay 主城卡顿 已重新进入主城，观察10分钟未再出现掉TPS，其他玩家也恢复正常
```

AI可以继续核对日志与现场。对涉及源码修复的 MOD，先按[试服试玩和发布流程](docs/usage/operations.md#mod-试服试玩与正式发布)确认实际效果。

确认问题已解决后，管理员再发：

```text
/mcaidone 主城卡顿
```

这会结束任务、释放服务端占用，并在后台归档已验收经验。先发验证反馈，再发验收命令，效果信息才能进入该任务。任务结束后不再接收 `/mcaisay`；再次出现问题可引用新反馈另建任务。

### 5. 需要暂停、继续或中止时

| 你遇到的情况 | 应该怎么做 |
|---|---|
| 暂时没空、需要等玩家复现 | 管理员 `/mcaipause 主城卡顿` 保存进度 |
| 任务已暂停，想先补信息 | `/mcaisay 主城卡顿 内容`，只保存，不自动继续 |
| 已补完信息或修正模型配置，准备继续 | 管理员 `/mcairesume 主城卡顿` |
| 放弃本次排查 | 管理员 `/mcaistop 主城卡顿`，停止接收反馈并取消所属后台工作 |
| 问题已解决，准备归档 | 管理员 `/mcaidone 主城卡顿` |

暂停继续保留实例占用；中止收尾后释放任务占用，但不自动撤销已经发生的修改。文件修复进行中请求暂停，会等待原操作结束后暂停；请求中止，则在当前文件步骤结束后停止后续步骤。执行中的修复不能直接验收。

进行中任务遇到模型 API 错误默认持续重试。认证或权限失败（401／403）和明确额度不足的 429 在首次失败时通知管理员，之后每 5 分钟重试；普通限流及其他错误按 2、5、10、20、30 秒等待，随后固定 30 秒，连续失败 3 次时通知一次。可用 `/mcaipause 任务名` 暂停，或 `/mcaistop 任务名` 停止。设置页可选配连续失败自动暂停或单任务 token 上限，两项默认关闭。上下文超限先缩减或拆批，无法缩减、审核协议持续不合规及本地记录失败仍会明确报告。修复失败时保留备份和现场，AI可继续检查，新方案重新审核和批准。网络中断使用原编号核对，通常不需要重复发送批准命令。

## 群命令速查

下表中的方括号表示可选内容，实际发送时不用带方括号。群内提示用中文双引号标出完整命令及参数（引号两边留空格），实际发送时不用带引号；如果不小心拼错指令、在 `mcai` 后多加空格或指令与参数间漏写空格，Bot 会给出最接近的指令建议。

| 命令 | 谁可以用 | 用途 |
|---|---|---|
| `/mcaiserver [实例ID]` | 群成员 | 不调用模型，查看所有实例或指定实例的实时状态；管理员可查看 B 数据盘剩余空间和窗口会话 |
| `/mcaiswitch 实例ID start\|stop\|restart\|forcestop\|forcerestart [confirm]` | 管理员 | [直接启停正式服](docs/usage/operations.md#直接启停正式服)，强制操作须在群内确认，提交后按原编号回报结果 |
| `/mcaiask 问题` | 管理员；开启后群成员可用 | 一次只读 AI 问答，可查询已有任务正在使用的实例；须在问题中体现目标服务端 |
| `/mcainew 任务名 [问题或补充说明]` | 管理员 | 直接描述问题创建任务；有引用时追加补充 |
| `/mcaisay 任务名 内容` | 群成员 | 向指定任务补充文字 |
| `/mcaisaymode 任务名 true\|false` | 管理员 | `false` 暂停普通成员补充，`true` 恢复；管理员始终可补充 |
| `/mcaistatus 任务名` | 群成员 | 查看状态、模型用量和已配置单价的估算费用 |
| `/mcailist [页码]` | 群成员 | 查看本群活动任务；页码为正整数，省略时查看第 1 页 |
| `/mcaiplan 任务名` | 群成员 | 重发待批准方案，或查看已批准的多轮方案 |
| `/mcaiapply 任务名 短码` | 管理员 | 用方案中显示的短码批准该方案 |
| `/mcaischedule list` | 群成员 | 查看定时备份、定时重启的时间、状态和上次结果 |
| `/mcaischedule pause\|resume\|delete 编号` | 管理员 | 暂停、恢复或删除定时计划 |
| `/mcaipause 任务名` | 管理员 | 保存并暂停；已暂停时提示续接命令 |
| `/mcairesume 任务名` | 管理员 | 从已保存状态续接 |
| `/mcaistop 任务名` | 管理员 | 中止，不作为已解决案例归档 |
| `/mcaidone 任务名` | 管理员 | 验收结束，后台归档经验 |
| `/mcaihelp` | 群成员 | 查看帮助 |

## 可选：安装服内诊断 Probe

Probe 提供玩家位置、维度耗时、已加载对象普查和短时实体热点。客户端无需安装，不新增端口。先正常停服，再从 B 包的 `probe/` 目录选择与 Minecraft 版本和加载器匹配的 **一个 JAR** 放入 `mods/`；重启后确认日志出现 `MCAI Probe 0.5.0 ready`。文件名、Java 要求及用法见[Probe 安装表](docs/usage/probe.md#安装)。

## 日常启停、规则与备份

### 下次开机怎么启动

先[启动 B](#5-启动-b保存连接信息)，再为每个服务端[打开托管窗口并运行 `start.bat`](#6-为每个服务端打开独立托管窗口)。A 端照常启动 AstrBot 和 QQ 适配器。单独重启 B 时，已有托管窗口和 MC 继续运行并自动重连。日常启停、`attach` 和观察状态见[多窗口管理](docs/usage/operations.md#多窗口管理服务端)。

### 调整 Agent 预设

自定义约定写入 A 插件数据目录的运行时规则。升级保留现有文件；在「MCAI 设置 → 运行时规则」查看三份规则的模板状态和差异。可人工合并后标记「已人工合并」，或确认「采用新模板」，由插件先备份再覆盖。三份模板的用途和位置见[运行时规则](docs/usage/configuration.md#运行时规则)。

### 备份在哪里，如何恢复

B 的文件备份默认在 `data_dir/backups/操作编号/`。恢复前先核对原实例目录和备份编号，按[备份恢复步骤](docs/usage/operations.md#数据与备份)执行。A 的任务、规则和经验保存在插件数据目录。

可建任务安排[定时备份和定时重启](docs/usage/operations.md#定时备份与定时重启)。例如发 `/mcainew 每日备份 每天凌晨 03:00 在线备份 cti 的 world 目录，保留 7 份`，核对方案并批准一次。之后由 B 按本机时间执行，AstrBot 或 QQ 离线时也照常运行。

### 更新时保留什么

升级时建议配套更新 A、B 和托管窗口（当前协议 `mcai-9`）。若随 B 包提供的 Probe 构建与当前已安装版本相同，服务端无需替换 JAR。先完成或中止活动任务，再安排停服及备份。A 更新后在设置页核对三份规则的新版提示；升级不会自动覆盖现有规则，旧安装没有模板基线时会显示「基线未知」，请先查看差异。详见[升级步骤和保留清单](docs/usage/operations.md#升级步骤)。

升级后须用 `/mcaiapply 任务名 短码` 批准方案。网页读取和下载只访问公网地址。「MCAI 设置 → 数据占用」新增两端占用统计和已结束任务的手动清理，清理前可先预览范围。

## 常见问题

| 现象 | 按什么顺序检查 |
|---|---|
| 找不到 `mcai` 命令 | 使用本文的 `.venv\Scripts\mcai.exe` 完整路径，确认之前的 `pip install -e .` 已成功 |
| 提示 PowerShell 版本不对 | 打开 PowerShell 7，核对 `$PSVersionTable.PSVersion` 及 `host.json` 中的 `powershell_path` |
| 启动时目录／配置文件不存在 | 核对解压层级、当前目录、文件扩展名及 JSON 路径；B从安装目录启动 |
| 提示找不到 B 配置位置 | 先在同一 Windows 用户下成功启动一次 B，再打开托管窗口 |
| A 测试连接失败 | 确认 B 仍在运行；核对实际地址、端口、令牌和证书指纹 |
| 有服务端配置但显示无托管连接 | 确认 `tm -C` 的目录正确；普通窗口中的 MC 不会被自动接管 |
| AI 没看到刚发的解释 | 用 `/mcaisay 任务名 内容` 补充；暂停状态下需管理员续接 |

模型、下载、停服和安装依赖等问题见[运行维护常见问题](docs/usage/operations.md#其他常见问题)。
